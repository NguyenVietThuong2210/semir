1. ML định nghĩa 1 câu

Machine Learning = xây dựng thuật toán học "quy luật" từ dữ liệu, thay vì lập trình quy luật thủ công. Tom Mitchell (1997) chính thức hóa:

📖 Tom Mitchell definition

"A program learns from experience E with respect to some class of tasks T and performance measure P, if its performance at tasks in T, as measured by P, improves with experience E."

Áp vào V18:

  • Task T: dự đoán ticker FPT ngày mai UP / DOWN / FLAT
  • Experience E: 1250 phiên OHLCV lịch sử + label ngày kế
  • Performance P: cross-validated accuracy (V18 đạt ~60.5% vs random baseline 42%)
💡 Ví dụ đời thực — Học chạy xe máy

Cách cũ (rule-based, KHÔNG phải ML): Bố dạy "nếu đèn đỏ → thắng; nếu ngã tư → giảm tốc; nếu mưa → chậm 50%". Máy chỉ làm đúng những gì được lập trình.

Cách ML: Bạn tự chạy 1000 lần (experience E), té ngã và bị bấm còi (performance P) rồi tự điều chỉnh cách bẻ lái, phanh (task T). Không ai viết luật "khi rẽ trái với tốc độ 30km/h thì nghiêng người 5 độ" — nhưng não bạn học được.

Áp dụng V18: Không ai bảo "khi RSI > 70 và volume tăng 2× thì DOWN". Model tự học pattern này từ 1250 phiên lịch sử.

2. Ba loại Machine Learning

LoạiCó label không?Ví dụ VNÁp dụng trong project bạn

Unsupervised Không (chỉ input) Segment khách hàng, phát hiện anomaly, topic modeling KHÔNG dùng trong PredictStock (nhưng có thể dùng cluster sector rotation)
Reinforcement Reward signal (không label sẵn) Bot đánh cờ, giao dịch algo tự học, robot điều hướng RLHF (Level 4.4) dùng RL để align LLM

2.1 Supervised: 2 nhánh con

Classification (phân loại) — output là category rời rạc:

  • Ví dụ: FPT ngày mai UP / DOWN / FLAT (3 class)
  • Loss function: cross-entropy
  • Metric: accuracy, F1, precision/recall, AUC

Regression (hồi quy) — output là số liên tục:

  • Ví dụ: dự đoán return chính xác của FPT (+2.5%, -0.8%, ...)
  • Loss function: MSE, MAE, Huber
  • Metric: RMSE, MAE, R²
Câu hỏi phổ biến phỏng vấn

"Tại sao V18 là classification 3-class thay vì regression giá?" → Vì regression giá cổ phiếu quá nhiễu: giá phụ thuộc quá nhiều biến (news, sentiment, macro) mà ta không quan sát được. Classification 3-class chỉ hỏi hướng — ít nhiễu hơn + dễ actionable (trader chỉ cần biết long/short/flat).

Analogy tổng hợp — 3 cách học của người

  1. Supervised: Học đại học có giáo viên chấm bài. Nhanh nhưng phụ thuộc chất lượng giáo viên.
  2. Unsupervised: Đọc 1000 cuốn sách một mình. Tự nhóm, tự thấy pattern. Chậm nhưng độc lập.
  3. Reinforcement: Học kinh doanh — thử, lỗ tiền, học, thử lại. Không có "đáp án đúng" — thị trường phản hồi qua doanh thu.

Cây quyết định — chọn loại nào?

Có label không?
├── Có → Supervised (default 90% ML task)
│   ├── Output số → Regression → RMSE/MAE
│   └── Output category → Classification → F1/PR-AUC
└── Không →
    ├── Muốn explore/cluster? → Unsupervised → Silhouette
    └── Muốn learn từ trial-error? → Reinforcement → Cumulative reward

➡️ Muốn hiểu sâu Algorithms + Metrics từng loại? Đọc L1.3 — module dành riêng cho Algorithm landscape (Supervised/Unsupervised/RL) và bộ Metric đầy đủ.

Câu hỏi phỏng vấn: "V18 dùng loại nào? Vì sao?" → "Supervised classification 3-class. Có label rõ (UP/DOWN/FLAT tính từ future return) + task discrete + data quantity đủ. Metric CV accuracy vì class gần balanced. RL không phù hợp vì delayed feedback + không có simulator ổn."

🚨 Bài học đắt giá từ V19.5

ML system có thể fail lặng lẽ theo cách traditional software không có: 14 blue-chip tickers rơi vào v1 legacy fallback vì T3/T5 artifacts thiếu features. Traditional code sẽ throw exception; ML pipeline chỉ log warning và tiếp tục serve. → Bạn phải build fail-loud guard rails (V20 Slice 5 consistency cron).

4b. 📖 Glossary — thuật ngữ nền bạn sẽ gặp xuyên suốt Level 1

ⓘ Định nghĩa nhanh (đọc lướt, sẽ đào sâu ở modules sau)
  • Feature (đặc trưng) — 1 con số mô tả sample. VD: rsi_14 = 65.2. Model chỉ "thấy" thế giới qua features.
  • Label (nhãn) — đáp án đúng cho 1 sample. VD: FPT ngày mai UP.
  • Model — hàm f(features) → prediction. VD: XGBoost tree ensemble.
  • Loss function — số đo "sai bao nhiêu" giữa prediction và label. Model học bằng cách giảm loss.
  • Gradient — đạo hàm của loss theo tham số. "Hướng dốc" giúp model biết chỉnh weight theo hướng nào để loss giảm. (Analogy: nhắm mắt xuống núi — feeling độ dốc dưới chân = gradient.)
  • Logit — output "thô" của model trước khi bị nén vào [0,1]. Range (-∞, +∞). Sigmoid(logit) = probability.
  • Cross-entropy — loss chuẩn cho classification. Phạt rất nặng khi model tự tin sai. Công thức: -Σ y·log(ŷ), trong đó y = label thật (0 hoặc 1), ŷ = xác suất model dự đoán. Sẽ derive ở L1.3.
  • Curse of dimensionality (lời nguyền chiều cao) — càng nhiều features (chiều), data càng "thưa" trong không gian đó, khiến khái niệm "gần/xa" mất ý nghĩa và cần exponentially nhiều data hơn để model học tốt. VD cụ thể: chia mỗi chiều thành 10 khoảng ("bin"). Với 1 chiều, 10 bin là đủ phủ. Với 10 chiều, số "ô" cần phủ là 10^10 (10 tỷ ô) so với 10 ô ở 1 chiều — tăng gấp 1 tỷ lần (10^9) — trong khi vẫn chỉ có 100 sample, gần như trống rỗng. Đây là why "cứ thêm feature vô tội vạ" làm model TỆ hơn, không tốt hơn (xem Q4 bên dưới, và KNN ở L1.3 mục 7.1 bị ảnh hưởng nặng nhất).
  • Accuracy — tỷ lệ đoán đúng. #đúng / #tổng. Đơn giản nhưng lừa khi class imbalanced (model đoán FLAT hết vẫn 50%).
  • Precision — trong số lần model đoán "UP", bao nhiêu % thực sự đúng UP. TP / (TP+FP). Cao = model ít "báo động giả".
  • Recall — trong số lần thực sự UP, model bắt được bao nhiêu %. TP / (TP+FN). Cao = model ít "bỏ sót". Precision và recall thường đánh đổi nhau (tăng cái này thường giảm cái kia).
  • F1 score — trung bình điều hoà giữa precision + recall (2 số ở trên). Range [0,1]. Dùng khi class imbalanced.
  • AUC (Area Under ROC Curve) — xác suất model rank random positive cao hơn random negative. AUC=0.5 = random, AUC=1.0 = perfect.
  • Overfitting — "học vẹt": model nhớ noise của train set thay vì học pattern. Train acc cao, test acc thấp.
  • Calibration — model bảo "70% chắc" thì đúng 70% lần thật. Sẽ đào sâu ở L1.6.
  • Leak (data leakage) — feature vô tình chứa info tương lai. Model "gian lận" trên train, sập trên production. Cạm bẫy #1 của time-series ML.
  • TimeSeriesSplit — cách chia CV giữ nguyên thứ tự thời gian (train quá khứ, test tương lai). Sẽ đào sâu ở L1.5.
🧮 Cross-entropy — ví dụ số cụ thể (1 sample)

FPT ngày mai thực tế là UP (label one-hot y = [0, 0, 1] cho [DOWN, FLAT, UP]). Model dự đoán ŷ = [0.1, 0.2, 0.7].

Loss = -Σ y_i · log(ŷ_i)
     = -(0·log(0.1) + 0·log(0.2) + 1·log(0.7))
     = -log(0.7) = 0.357

Nếu model tự tin SAI (predict UP chỉ 0.05 khi thật là UP): Loss = -log(0.05) = 3.00 — phạt gấp 8.4× so với case đúng. Đây là "phạt rất nặng khi tự tin sai": log(x) tiến về -∞ khi x → 0, nên loss nổ mạnh khi model chắc chắn nhưng sai.

5. Khi nào KHÔNG dùng ML?

  • Business rule đơn giản (khách VIP nếu spent > 10M) → viết SQL/if-else, đừng train model
  • Không có data hoặc data < 1000 samples
  • Yêu cầu 100% correctness (kiểm toán, y khoa quyết định)
  • Không có way to measure success (nếu bạn không biết đúng/sai, làm sao model học?)

✅ QA Gate — Tự test trước khi qua module kế

1. Định nghĩa ML bằng 1 câu (không nhìn note).

ML = xây thuật toán học quy luật từ data, thay vì lập trình rule thủ công. Perf phải cải thiện khi có nhiều data hơn.

2. Cho 5 ví dụ VN tương ứng: 2 supervised classification, 1 supervised regression, 1 unsupervised, 1 RL.

Classification: dự đoán churn user Momo, phân loại email spam Gmail. Regression: dự đoán giá nhà TP.HCM. Unsupervised: cluster khách hàng Shopee. RL: bot đấu cờ vua, LLM alignment (RLHF).

3. Vẽ ML pipeline 7 bước từ trí nhớ + đặt vào chỗ nào của V18 pipeline.

Problem → Data → Features → Model → Train → Eval → Deploy. V18 files: providers/vci.py → features_v18.py → train_v18_unified.py → validate_v20_artifacts.py → docker-compose.yml.

4. Tại sao V18 chọn classification 3-class thay vì regression?

Giá cổ phiếu quá nhiễu (phụ thuộc nhiều biến không quan sát được: news, macro, retail sentiment). Classification chỉ hỏi hướng — ít nhiễu, dễ actionable (long/short/flat).

5. Khác biệt lớn nhất giữa ML và code truyền thống khi debug production issue?

Traditional throw exception → stack trace. ML fail lặng lẽ (accuracy giảm 5% chẳng ai biết). Phải build monitoring: drift detector, canary, consistency cron. V19.5 chết vì thiếu cái này.

❌ Sai lầm thường gặp vs ✅ Thực tế
  • ❌ "ML sẽ tự tìm ra mọi pattern nếu có đủ data" → ✅ Không. Model chỉ học được pattern đã có trong features. Feed close price mỗi ngày, model không tự phát hiện "RSI > 70 = quá mua" — bạn phải compute RSI trước.
  • ❌ "Accuracy càng cao càng tốt" → ✅ Sai khi class imbalanced. Model đoán "FLAT" cho mọi ngày sẽ đạt 50% accuracy nhưng vô dụng. Dùng F1, PR-AUC.
  • ❌ "Deep learning luôn tốt hơn XGBoost" → ✅ Với tabular data cỡ nhỏ-trung (< 1M rows), XGBoost thường thắng DL. DL chỉ vượt trội trên image/text/audio ở scale lớn.
  • ❌ "Test accuracy 90% = deploy thành công" → ✅ Nếu test set bị leak, deploy sẽ chết. V19.5 chính là bài học đắt.

6. 🎓 Interview-style Q&A (phỏng vấn thực tế)

Q1: "Tôi có 1000 rows data khách hàng chợ Bến Thành. Bạn recommend supervised, unsupervised, hay RL?"

Model answer: "Depends on business goal. Nếu có label (churn/retain, high/low value) → supervised. Nếu chỉ muốn hiểu segment customer → unsupervised clustering (K-Means/HDBSCAN). RL chỉ hợp lý nếu có sequential decisions với reward (VD tối ưu discount schedule qua thời gian). Với 1000 rows nhỏ, tôi warn: supervised cần ≥ vài trăm mỗi class, unsupervised ổn hơn."

Q2: "Vì sao V18 dùng cross-validated accuracy 60.5% mà không phải test accuracy 65%?"

Model answer: "CV accuracy đo qua nhiều fold → variance estimate + bớt overfit đến 1 test set duy nhất. Test accuracy 65% single fold có thể là may mắn của split. V18 dùng TimeSeriesSplit 5-fold + gap → CV mean 60.5% là ước lượng honest của live performance."

Q3: "Random baseline 42% — con số này từ đâu?"

Model answer: "Baseline naive nhất = predict class majority. Nếu FLAT chiếm 42% samples train → predict FLAT mọi lúc → accuracy 42%. V18 đạt 60.5% = beat baseline 18.5 điểm → thực sự có edge. Nếu chỉ đạt 44%, model gần vô dụng dù nghe có vẻ > 50%."

Q4: "Sếp bảo 'thêm 100 features nữa xem model có tốt hơn'. Bạn nghĩ sao?"

Model answer: "Push back polite. More features ≠ better. Rủi ro: (1) curse of dimensionality — data càng thưa theo cấp số mũ với số chiều (xem glossary phía trên), (2) overfit tăng, (3) slow train + inference. Đúng cách: propose SHAP audit hiện tại, drop features contribution < 0.5%, chỉ add features có business rationale + hypothesis rõ."

Q5: "ML pipeline của bạn deploy production. Sau 3 tháng accuracy tụt 5%. Debug thế nào?"

Model answer: "Systematic checklist: (1) Data drift — feature distribution 3 tháng qua vs train? (2) Label drift — target distribution shift? (3) Concept drift — mapping feature→label changed (VD market regime)? (4) Pipeline bug — feature compute có silent fail? (5) External factor — Fed, war, corona. Fix theo priority: nếu drift → retrain với recent window; nếu bug → hotfix + re-baseline. Không patch bằng cách 'tune threshold' — đó là band-aid."
