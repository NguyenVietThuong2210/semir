Cách debug ML model như debug code. SHAP values, permutation importance, partial dependence — case study V20 Slice 3 prune 43→17 features.

Level 2 · Advanced ML · ~30 phút

🎯 Learning objectives

  • Explain 3 methods: Gain (XGBoost internal), Permutation, SHAP
  • Compute SHAP cho 1 prediction bằng TreeExplainer
  • Đọc SHAP summary plot + dependence plot
  • Áp dụng V20 Slice 3: dropped 26 features với adoption < 30%
💡 SHAP / Interpretability bằng ngôn ngữ đời thường

Trả lời "vì sao xe rẻ hơn thị trường?"

  • Global explanation: "Nhìn chung với 1000 xe, feature ảnh hưởng giá nhất là năm sản xuất, số km, hãng." → tương tự feature importance / PDP.
  • Local explanation (SHAP): "Chiếc xe CỤ THỂ này rẻ 30 triệu vì: km cao (-15tr), tai nạn cũ (-10tr), nhưng màu đẹp (+5tr)." → giải thích 1 case cụ thể.

V20 Slice 3 dùng SHAP để loại bỏ features "đóng góp gần 0" cho model — như đầu bếp bỏ những gia vị chẳng ai để ý → nồi phở nhẹ mà vẫn ngon.

1. Global vs local explanation

  • Global: overall feature importance across dataset. Which features matter overall?
  • Local: why this specific prediction? Which features push toward UP/DOWN?

2. Method 1: Gain importance (XGBoost internal)

importance = clf.feature_importances_   # sklearn API
# Hoặc: clf.get_booster().get_score(importance_type='gain')

# Metric: average gain in impurity when feature used at splits
# Fast, no extra compute
# Nhược: biased toward high-cardinality features, không quantify direction

3. Method 2: Permutation importance

from sklearn.inspection import permutation_importance
result = permutation_importance(clf, X_val, y_val, n_repeats=10)

# For each feature j:
#   baseline_score = score(X_val, y_val)
#   shuffle column j
#   drop_score = score(X_val_shuffled, y_val)
#   importance_j = baseline_score - drop_score

Ưu: model-agnostic, direct measure "if feature random, how much worse?". Nhược: slow (n_features × n_repeats × eval).

4. Method 3: SHAP (SHapley Additive exPlanations)

Lundberg & Lee (2017). Dựa Shapley value từ game theory: đóng góp fair mỗi feature.

Prediction = base_value + Σ SHAP_value[i]

# SHAP_value[i] = "how much feature i pushed prediction from base"
# base_value = average prediction across dataset
# Sum SHAP = prediction - base (additive!)
📐 Shapley value từ Game Theory — công thức đầy đủ + ví dụ 3 feature với số cụ thể

Bối cảnh — bài toán "chia lương công bằng" (Shapley 1953)

3 nhân viên A, B, C hợp tác kiếm được 1 tỷ. Chia thế nào cho công bằng? Shapley: mỗi người nhận trung bình giá trị họ thêm vào qua tất cả các thứ tự có thể tham gia team.

Công thức chính thức

φ_i(v) = Σ  [ |S|! · (n-|S|-1)! / n! ] · [ v(S ∪ {i}) - v(S) ]
      S ⊆ N\{i}
       ↑            ↑                          ↑
   tổng qua       trọng số                   "marginal contribution" —
   mọi coalition  hoán vị                    thêm feature i vào coalition S
   không chứa i                              làm tăng payoff bao nhiêu

Trong ML:
  N = tập tất cả features {1, 2, ..., n}
  v(S) = prediction của model khi CHỈ dùng features trong S
         (features ngoài S được "marginalize" — thay bằng expectation)
  φ_i = SHAP value của feature i cho 1 sample cụ thể

Gloss tiếng Việt:

  • S = "coalition" = tập con features (nhóm nhân viên đã có mặt)
  • v(S) = "payoff" khi chỉ nhóm S làm việc
  • v(S ∪ {i}) - v(S) = giá trị nhân viên i thêm vào khi gia nhập nhóm S
  • Weight |S|!(n-|S|-1)!/n! = xác suất S là "coalition đúng lúc" khi i gia nhập (uniform random ordering)

Hình dung cấu trúc coalition — với n=3 feature {RSI, Vol, News} có đúng 2³=8 coalition (subset), xếp thành lưới theo kích thước:

                      {RSI,Vol,News}            ← full coalition, v = 0.82
                     ╱      │       ╲
          {RSI,Vol}    {RSI,News}    {Vol,News}   ← coalition 2 feature
                     ╲      │       ╱
             {RSI}      {Vol}      {News}          ← coalition 1 feature
                     ╲      │       ╱
                          ∅                        ← coalition rỗng, v = 0.50 (base rate)

Để tính φ_RSI, chỉ cần nhìn 4 CẠNH đi LÊN có "thêm RSI vào" (mũi tên nào cũng
đi từ 1 coalition KHÔNG chứa RSI lên coalition CÓ chứa RSI, chỉ khác đúng 1 phần tử):

  ∅         → {RSI}              (RSI gia nhập coalition rỗng)
  {Vol}     → {RSI,Vol}          (RSI gia nhập coalition {Vol})
  {News}    → {RSI,News}         (RSI gia nhập coalition {News})
  {Vol,News}→ {RSI,Vol,News}     (RSI gia nhập coalition {Vol,News})

→ 4 cạnh này CHÍNH XÁC là 4 dòng "S=..." trong phép tính φ_RSI ngay dưới đây —
  mỗi cạnh đóng góp 1 "marginal contribution" v(S∪{i}) - v(S), nhân với trọng số
  = xác suất cạnh đó được đi qua nếu xáo trộn ngẫu nhiên thứ tự 3 feature gia nhập.

Ví dụ CỤ THỂ — 3 features (RSI, Volume, News), 1 sample VNM

Model là function v(S) — dự đoán probability UP. Ta biết 8 giá trị (mọi subset):

v(∅)          = 0.50   ← base rate, không feature nào
v({RSI})      = 0.65
v({Vol})      = 0.55
v({News})     = 0.60
v({RSI,Vol})  = 0.70
v({RSI,News}) = 0.78
v({Vol,News}) = 0.68
v({RSI,Vol,News}) = 0.82   ← full prediction

Tính SHAP cho RSI (φ_RSI): cần tính marginal contribution của RSI qua 4 coalition không chứa RSI:

S=∅:            v({RSI}) - v(∅)          = 0.65 - 0.50 = 0.15
                weight = 0!·2!/3! = 2/6 = 1/3

S={Vol}:        v({RSI,Vol}) - v({Vol})  = 0.70 - 0.55 = 0.15
                weight = 1!·1!/3! = 1/6

S={News}:       v({RSI,News}) - v({News}) = 0.78 - 0.60 = 0.18
                weight = 1!·1!/3! = 1/6

S={Vol,News}:   v({RSI,Vol,News}) - v({Vol,News}) = 0.82 - 0.68 = 0.14
                weight = 2!·0!/3! = 2/6 = 1/3

φ_RSI = 1/3·0.15 + 1/6·0.15 + 1/6·0.18 + 1/3·0.14
     = 0.050 + 0.025 + 0.030 + 0.0467
     = 0.152

Tính SHAP cho Vol (φ_Vol): 4 coalition không chứa Vol:

S=∅:            v({Vol}) - v(∅)              = 0.55 - 0.50 = 0.05,  weight = 1/3
S={RSI}:        v({RSI,Vol}) - v({RSI})      = 0.70 - 0.65 = 0.05,  weight = 1/6
S={News}:       v({Vol,News}) - v({News})    = 0.68 - 0.60 = 0.08,  weight = 1/6
S={RSI,News}:   v({RSI,Vol,News}) - v({RSI,News}) = 0.82 - 0.78 = 0.04,  weight = 1/3

φ_Vol = 1/3·0.05 + 1/6·0.05 + 1/6·0.08 + 1/3·0.04
      = 0.0167 + 0.0083 + 0.0133 + 0.0133
      = 0.0517

Tính SHAP cho News (φ_News): 4 coalition không chứa News:

S=∅:            v({News}) - v(∅)             = 0.60 - 0.50 = 0.10,  weight = 1/3
S={RSI}:        v({RSI,News}) - v({RSI})     = 0.78 - 0.65 = 0.13,  weight = 1/6
S={Vol}:        v({Vol,News}) - v({Vol})     = 0.68 - 0.55 = 0.13,  weight = 1/6
S={RSI,Vol}:    v({RSI,Vol,News}) - v({RSI,Vol}) = 0.82 - 0.70 = 0.12,  weight = 1/3

φ_News = 1/3·0.10 + 1/6·0.13 + 1/6·0.13 + 1/3·0.12
       = 0.0333 + 0.0217 + 0.0217 + 0.04
       = 0.1167
Tổng hợp:
φ_RSI  = 0.152
φ_Vol  = 0.0517
φ_News = 0.1167

Kiểm tra Local Accuracy:
  base + Σ φ = 0.50 + 0.152 + 0.0517 + 0.1167 = 0.8204 ≈ 0.82 = v({RSI,Vol,News}) ✓

Diễn giải business: "Model dự đoán VNM UP 82% (base 50%). RSI đóng góp +15.2pp (lớn nhất — đang oversold), News +10.8pp, Volume +6.0pp. Tất cả cùng chiều dương → BUY confident."

Vì sao tính này QUAN TRỌNG?

Shapley là lời giải DUY NHẤT thỏa 4 tiên đề công bằng (Efficiency, Symmetry, Dummy, Additivity — Shapley 1953). Không phương pháp interpretability nào khác có bảo đảm toán học này. Đó là lý do SHAP = gold standard.

Cost thực tế

Exact Shapley: O(2^n) — với n=88 features thì 2^88 subsets → không khả thi.

TreeSHAP (Lundberg 2018): khai thác cấu trúc tree → O(TLD²) với T=trees, L=leaves, D=depth. Với XGBoost 500 trees, depth 6 → giây, không phải năm. Đây là lý do TreeSHAP practical.

KernelSHAP (model-agnostic): sample subsets + fit weighted linear regression → approximation. Chậm nhưng dùng được cho NN/black-box.

Rule of thumb: tree model → TreeSHAP (always). NN → Integrated Gradients hoặc DeepSHAP. Prototype/demo → LIME. Regulatory/audit → SHAP có defensible math.

📐 Integrated Gradients — cơ chế thật đứng sau tên gọi (2 lần nhắc ở trên chưa giải thích)

Ý tưởng: thay vì chỉ nhìn gradient (đạo hàm) TẠI input hiện tại (dễ bị "gradient bão hoà" — gradient gần bằng 0 dù feature thực sự quan trọng, VD 1 neuron đã "saturate"), Integrated Gradients (Sundararajan, Taly, Yan — 2017) đi 1 ĐƯỜNG THẲNG từ 1 "baseline" (input tham chiếu, VD ảnh toàn đen/toàn 0 — đại diện cho "không có thông tin gì") tới input thật, RỒI CỘNG DỒN (tích phân — integral, phép tính tổng liên tục) gradient dọc suốt đường đi đó, không chỉ nhìn 1 điểm cuối:

IG_i(x) = (x_i - x'_i) · ∫₀¹ ∂F(x' + α(x-x'))/∂x_i dα

# x = input thật, x' = baseline, α chạy từ 0 (baseline) tới 1 (input thật)
# ∂F/∂x_i = gradient của model F theo feature i, đo TẠI điểm x' + α(x-x')
#           (1 điểm nằm trên đường thẳng nối x' và x, tại vị trí α)

Xấp xỉ thực tế (Riemann sum — chia đường thẳng thành m bước nhỏ thay vì tích phân liên tục):
IG_i(x) ≈ (x_i - x'_i) · (1/m) · Σ_{k=1}^{m} ∂F(x' + (k/m)(x-x'))/∂x_i

Ví dụ số tối giản (1 chiều): hàm toy f(x)=x², baseline x'=0, input x=2, chia m=4 bước. Đạo hàm f'(x)=2x. 4 điểm trên đường đi: x'+(k/4)·2 = 0.5, 1.0, 1.5, 2.0 → đạo hàm tương ứng = 1, 2, 3, 4.

IG ≈ (2-0) · (1/4) · (1+2+3+4) = 2 · (1/4) · 10 = 5

So với giá trị ĐÚNG (Completeness — tổng attribution phải bằng đúng chênh lệch
prediction): f(2) - f(0) = 4 - 0 = 4.

→ Với m=4 (ít bước), xấp xỉ 5 LỆCH so với giá trị đúng 4 (do đây là Riemann sum
  kiểu "lấy điểm cuối mỗi khoảng", đạo hàm hàm x² là hàm TĂNG nên hơi phóng đại).
  Tăng m lên 50 (giá trị mặc định phổ biến trong code thật, VD thư viện Captum)
  → xấp xỉ hội tụ về rất gần 4. Đây là lý do IG luôn cần chọn m đủ lớn.

2 tính chất (axiom) IG được thiết kế để đảm bảo (khác Gradient thô không đảm bảo được): Sensitivity — nếu 2 input chỉ khác nhau ĐÚNG 1 feature và cho ra prediction khác nhau, feature đó BẮT BUỘC phải nhận attribution khác 0 (gradient thô có thể cho 0 nếu rơi đúng vùng bão hoà); Implementation Invariance — 2 mạng neural network khác kiến trúc nhưng cho ra CÙNG kết quả với MỌI input phải nhận attribution giống hệt nhau (không phụ thuộc cách implement bên trong).

DeepSHAP khác gì Integrated Gradients — đây là 2 THUẬT TOÁN KHÁC NHAU, hay bị nhầm là cùng 1 thứ: DeepSHAP KHÔNG dùng tích phân theo đường thẳng — nó kết hợp quy tắc lan truyền ngược (backpropagation) của DeepLIFT với cách đóng khung theo Shapley value (mục "Shapley value" ở trên), lấy giá trị tham chiếu từ TRUNG BÌNH 1 phân phối nền (background distribution) thay vì 1 baseline/1 đường đi duy nhất.

TreeExplainer — fast SHAP cho tree models

import shap
explainer = shap.TreeExplainer(clf)
shap_values = explainer.shap_values(X_test)   # (n_samples, n_features)

# 1 prediction:
shap.force_plot(explainer.expected_value, shap_values[0], X_test.iloc[0])

# Global summary:
shap.summary_plot(shap_values, X_test)   # bee-swarm plot

# Feature dependence:
shap.dependence_plot("RSI_14", shap_values, X_test)
SHAP magic properties
  1. Local accuracy: Σ SHAP + base = prediction (exactly)
  2. Missingness: missing feature → 0 SHAP
  3. Consistency: model change increase feature contribution → SHAP không decrease

Chỉ SHAP thỏa 3 properties này (Lundberg proof). Vì thế = gold standard.

6. Partial dependence plot (PDP)

# Effect of RSI on prediction, holding others average:
from sklearn.inspection import PartialDependenceDisplay
PartialDependenceDisplay.from_estimator(clf, X, features=['RSI_14'])

Show trend: as RSI increases 30 → 70, prediction UP prob rise then plateau. Sanity check model logic.

7. Pitfalls

  1. Correlated features: SHAP splits credit — 2 features correlated 0.9 mỗi cái nhận half credit → underestimate. Fix: cluster + aggregate SHAP.
  2. Interaction effects: SHAP additive nhưng interactions phổ biến (RSI × MA20 status). Use SHAP interaction values (n²).
  3. Cost: TreeExplainer fast (O(depth × n_trees)) nhưng KernelExplainer (any model) O(2^features) — infeasible > 20 features.

Công ty 3 người kiếm 1 tỷ. Chia thế nào công bằng? Không phải chia đều 333 triệu. Không phải theo giờ làm. Shapley bảo: với mỗi nhân viên, tính xem "nếu không có bạn thì nhóm còn lại kiếm bao nhiêu?" — chênh lệch chính là đóng góp riêng của bạn. Trung bình qua mọi thứ tự bạn tham gia → lương công bằng.

Tương tự: mỗi feature là 1 "nhân viên", prediction cuối là "1 tỷ", SHAP value chính là lương công bằng mỗi feature đáng nhận. Đó là lý do Σ SHAP + base = prediction: tổng lương công bằng = tổng thu nhập.

⚠️ 3 hiểu lầm phổ biến về interpretability
  1. "Feature importance cao = feature causal" — SAI. SHAP/importance chỉ nói feature correlated với output theo cách model đã học, KHÔNG phải nhân quả. VD: "kem lạnh sales" cao SHAP cho "chết đuối" — nhưng nguyên nhân thật là "mùa hè". Feature importance ≠ causal inference. Muốn causal → cần intervention (A/B test) hoặc causal ML (DoWhy, EconML).
  2. "SHAP = ground truth explanation" — SAI. SHAP giải thích model của bạn, KHÔNG phải thế giới thực. Nếu model đã học wrong pattern (VD do bias data), SHAP sẽ giải thích wrong pattern đó rất "confident" → user tưởng đúng. SHAP là mirror của model, không phải oracle.
  3. "Correlated features chia đều SHAP không sao" — SAI khi ra quyết định feature engineering. 2 features corr 0.95 mỗi cái nhận half credit → nhìn ranking tưởng "cả 2 đều trung bình" → drop 1 tưởng an toàn nhưng thực tế model dùng combined signal → CV sụp sau drop. Fix: hierarchical clustering rồi aggregate SHAP tại cluster level, hoặc dùng SHAP conditional expectation (interventional).

✅ QA Gate

1. Gain importance vs Permutation vs SHAP — trade-off?

Gain: fast, biased toward high-cardinality. Permutation: model-agnostic, slow. SHAP: mathematically sound (3 properties), TreeExplainer fast cho tree, direction + magnitude.

2. Sum(SHAP) = prediction - base. Why matters?

Local accuracy = exact decomposition. Có thể verify feature contribution add up đúng. Feature importance methods khác không guaranteed.

3. V20 dropped days_to_next_fomc feature với adoption 33%. Right choice?

Borderline. 33% below 60% threshold. Nếu drop: cleaner model. Nhưng feature có thể mạnh cho subset tickers (US-exposed banks, tech). Decision context-dependent — V20 chose drop cho consistency.

4. SHAP value negative + prediction high — làm sao?

Nghĩa là feature push prediction DOWN, nhưng features khác push UP mạnh hơn → prediction net UP. SHAP local, not absolute.

5. Correlated features hurt SHAP thế nào? Fix?

2 features corr 0.9 mỗi cái nhận half credit → underestimate real importance. Fix: cluster correlated features (VD hierarchical clustering), aggregate SHAP tại cluster level.
