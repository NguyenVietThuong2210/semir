💡 Class imbalance bằng ngôn ngữ đời thường

Bệnh viện tầm soát ung thư: 1000 người khám, 10 người thật sự bị ung thư. Bác sĩ lười chẩn đoán "ai cũng khỏe" — accuracy 99%! Nhưng miss 10/10 bệnh nhân → chết người. Đây là accuracy paradox.

Metric đúng: Recall (bắt được bao nhiêu % ung thư thật) + Precision (bao nhiêu % nghi ngờ là ung thư thật). Trade-off: cảnh báo nhiều = precision thấp; cảnh báo ít = recall thấp.

Fix imbalance: (1) SMOTE = "tạo bệnh nhân giả gần giống bệnh nhân thật" để cân class; (2) Class weight = "phạt gấp 100× nếu bỏ sót ung thư"; (3) Threshold tuning = "hạ ngưỡng chẩn đoán" (từ p=0.5 xuống p=0.2).

1. Vì sao accuracy misleading?

Ví dụ classic — fraud detection

Dataset: 1000 transactions, 990 legit, 10 fraud. Model dumb luôn predict "legit" → accuracy 99%. Nhưng recall fraud = 0 → miss all fraud → business fail.

ROC-AUC dùng FPR = FP/N. Với N huge (negative class dominant), FPR tăng chậm → curve trông đẹp dù precision thấp. PR-AUC = better metric cho imbalanced.

📐 Matthews Correlation Coefficient (MCC) — công thức + vì sao nó "khó lừa" hơn F1

Vấn đề F1 không giải quyết được: nhìn lại công thức F1 ở bảng trên — nó được tính từ Precision và Recall, mà cả 2 chỉ dùng TP (True Positive — model đoán đúng lớp dương), FP (False Positive — model đoán nhầm thành dương), FN (False Negative — model bỏ sót). TN (True Negative — model đoán đúng lớp âm) KHÔNG BAO GIỜ xuất hiện trong công thức F1 — nghĩa là F1 hoàn toàn "mù" trước việc model dự đoán lớp âm (majority) tốt hay tệ.

MCC = (TP·TN - FP·FN) / √[(TP+FP)·(TP+FN)·(TN+FP)·(TN+FN)]

# Giải thích ký hiệu: TP/TN/FP/FN như đã học ở bảng Precision/Recall phía trên.
# MCC nằm trong khoảng [-1, +1]:
#   MCC = +1  → dự đoán HOÀN HẢO (khớp 100% nhãn thật)
#   MCC =  0  → không tốt hơn ĐOÁN NGẪU NHIÊN (random guessing)
#   MCC = -1  → dự đoán NGƯỢC HOÀN TOÀN (sai mọi trường hợp có hệ thống)
# Về bản chất, MCC chính là hệ số tương quan Pearson (Pearson correlation —
# đo mức độ 2 biến "đi cùng nhau") giữa nhãn dự đoán và nhãn thật.

Ví dụ số cụ thể — MCC "vạch trần" model mà F1 khen tốt: model chấm điểm 100 mẫu (92 dương thật, 8 âm thật): TP=90, FN=2, TN=5, FP=3 (tức là trong 8 mẫu âm thật, model đoán sai 3 mẫu thành dương).

Precision = 90/(90+3) = 0.968
Recall    = 90/(90+2) = 0.978
F1 = 2·0.968·0.978/(0.968+0.978) = 1.894/1.946 = 0.973   ← NHÌN RẤT TỐT

MCC = (90·5 - 3·2) / √[(90+3)(90+2)(5+3)(5+2)]
    = (450 - 6) / √(93 · 92 · 8 · 7)
    = 444 / √479,136
    = 444 / 692.2
    = 0.641   ← chỉ Ở MỨC TRUNG BÌNH, không "rất tốt" như F1 gợi ý

Kiểm tra riêng specificity (TN/(TN+FP), "recall của lớp âm") = 5/8 = 0.625
→ model chỉ đoán đúng 62.5% lớp âm — khá TỆ, nhưng F1 hoàn toàn không phản ánh
  điều này vì F1 không có TN trong công thức, còn MCC thì có.

Insight: dùng MCC khi bạn cần 1 con số DUY NHẤT phản ánh trung thực CẢ 4 ô của confusion matrix, không chỉ 3 ô như F1 — đặc biệt quan trọng khi bạn CŨNG quan tâm tới việc model có đoán đúng lớp âm (majority) hay không, không chỉ riêng lớp dương (minority).

3. Technique 1: Class weight

# sklearn:
from sklearn.utils.class_weight import compute_class_weight
weights = compute_class_weight('balanced', classes=[0, 1], y=y_train)
# weights = [0.505, 50.0]   (nếu 990:10 ratio)

clf.fit(X, y, sample_weight=[weights[yi] for yi in y_train])

Loss contribution của mỗi class cân bằng. Simple + không thay đổi data.

4. Technique 2: SMOTE (oversampling)

# SMOTE: Synthetic Minority Oversampling Technique (Chawla 2002)
# Cho mỗi minority sample x:
#   1. Chọn K nearest neighbors (cùng class minority)
#   2. Pick 1 neighbor random
#   3. Tạo synthetic sample: x_new = x + rand · (neighbor - x)
#   4. Repeat cho đến khi cân bằng
from imblearn.over_sampling import SMOTE
X_bal, y_bal = SMOTE(k_neighbors=5).fit_resample(X, y)

Ưu: model thấy nhiều minority pattern. Nhược: synthetic samples có thể không realistic → overfit.

5. Technique 3: Undersample majority

from imblearn.under_sampling import RandomUnderSampler
X_bal, y_bal = RandomUnderSampler().fit_resample(X, y)   # keep only 10 legit + 10 fraud

Ưu: nhanh train. Nhược: throw away data → info loss. OK khi data cực lớn.

6. Technique 4: Focal loss

Lin et al (2017, RetinaNet). Modify cross-entropy để focus hard examples:

FL(p_t) = -(1 - p_t)^γ · log(p_t)

# γ = focusing param (thường 2)
# p_t = model confidence ở correct class
# Nếu p_t high (easy example) → (1-p_t)^γ nhỏ → loss nhỏ → không waste attention
# Nếu p_t low (hard) → loss lớn → model focus fix

7. Technique 5: Threshold tuning

Default classification threshold 0.5 — không tối ưu cho imbalanced.

# Compute PR curve on val set:
from sklearn.metrics import precision_recall_curve
p, r, thresholds = precision_recall_curve(y_val, p_val)

# Chọn threshold maximize F1:
f1_scores = 2 * p * r / (p + r + 1e-9)
best_idx = np.argmax(f1_scores)
best_threshold = thresholds[best_idx]

# Deploy:
y_pred = (p_test > best_threshold).astype(int)

Không thay đổi model, chỉ shift decision boundary. Simple + effective.

📐 Deep-dive — Toán học đứng sau 3 kỹ thuật chính (class_weight, SMOTE, focal loss) — đọc SAU khi đã hiểu 5 techniques cơ bản ở mục 3-7 ở trên

Ký hiệu chung: N₀ = số sample class 0 (majority), N₁ = số sample class 1 (minority), N = N₀ + N₁, K = số class, p_t = xác suất model gán cho class ĐÚNG.

1. Class weight — công thức "balanced" của sklearn

weight_class_c = N / (K · N_c)

Ví dụ K=2, N₀=990, N₁=10, N=1000:
  weight_0 = 1000 / (2 · 990)  = 0.505
  weight_1 = 1000 / (2 · 10)   = 50.0
                                  ↑ minority nhận weight LỚN gấp ~100 lần

Loss weighted:
  L = -1/N · Σᵢ  weight[yᵢ] · [yᵢ·log(p̂ᵢ) + (1-yᵢ)·log(1-p̂ᵢ)]
                  ↑ sai 1 fraud bị phạt gấp 100× sai 1 legit

Ý nghĩa: Cân bằng "tổng đóng góp loss" của mỗi class. Class 1 chỉ có 10 sample nhưng mỗi sample nặng 50, tổng = 500. Class 0 có 990 sample × 0.505 = 500. Cân.

Cẩn thận: Ép weight quá cao (VD manual weight_1 = 1000) → model over-predict positive → precision sụp. "balanced" là điểm khởi đầu tốt, KHÔNG phải luôn tối ưu.

2. SMOTE — thuật toán từng bước (Chawla 2002)

INPUT: X_minor (m samples of minority class), k (số neighbors, default 5), N_target
OUTPUT: X_synthetic (N_target - m samples mới)

FOR mỗi sample x_i trong X_minor:
    1. Tìm k nearest neighbors CÙNG CLASS của x_i (dùng Euclidean distance
       trong feature space đã được scale). Gọi là {n_1, ..., n_k}.
    2. Quyết định cần tạo bao nhiêu synthetic từ x_i (ví dụ ⌈(N_target-m)/m⌉).
    3. FOR mỗi synthetic cần tạo:
         a. Chọn random 1 neighbor n_j từ {n_1,...,n_k}.
         b. Sinh λ ~ Uniform(0, 1)  ← số ngẫu nhiên trong [0,1]
         c. x_new = x_i + λ · (n_j - x_i)
                    ↑ điểm nằm trên đoạn thẳng nối x_i và n_j
         d. Gán label = minority class.
         e. Thêm x_new vào X_synthetic.

RETURN X_minor ∪ X_synthetic

Hình dung cơ chế interpolation (bước 3a-3c ở trên) — mỗi synthetic point luôn nằm TRÊN đoạn thẳng nối sample gốc và 1 neighbor cùng class, không bao giờ ra ngoài:

x_i ●───────────────────────────● n_j        (2 điểm minority CÓ THẬT)
    │                           │
    │◄────── λ·(n_j - x_i) ─────┤
    │                           │
    x_new = x_i + λ·(n_j - x_i)  ← điểm SYNTHETIC, luôn nằm trên đoạn x_i—n_j

  λ = 0    → x_new trùng x_i (điểm gốc)
  λ = 1    → x_new trùng n_j (điểm neighbor)
  λ = 0.5  → x_new nằm CHÍNH GIỮA x_i và n_j
  λ ~ Uniform(0,1)  → mỗi lần sinh, x_new rơi ngẫu nhiên ở 1 vị trí khác nhau trên đoạn thẳng

  → Đây là lý do SMOTE không bao giờ "bịa" 1 điểm cách xa 2 sample gốc —
    khác hẳn nhiễu ngẫu nhiên (random noise), synthetic point bị RÀNG BUỘC
    nằm trong "vùng lồi" (convex hull) của các sample minority đã có.

Ví dụ 2D cụ thể: minority chỉ có 3 sample: x₁=(1,2), x₂=(2,3), x₃=(1.5,2.5). Cần tạo 3 synthetic.

Cho x₁=(1,2), k=2 neighbors: x₂ và x₃.
Pick x₂. λ=0.4. → x_new = (1,2) + 0.4·((2,3)-(1,2)) = (1.4, 2.4). ✓
Pick x₃. λ=0.7. → x_new = (1,2) + 0.7·((1.5,2.5)-(1,2)) = (1.35, 2.35). ✓
...

Tại sao KHÔNG chỉ copy-paste minority? Duplicate = model chỉ học 3 điểm cứng → overfit. SMOTE interpolate → tạo "vùng" trong feature space → decision boundary mượt hơn.

Cạm bẫy quan trọng: SMOTE giả định "giữa 2 sample minority là một sample minority hợp lệ". SAI khi feature space có "vùng cấm" (VD: categorical encoded, hoặc minority tách rời thành cluster). Variant SMOTE-NC (Nominal + Continuous) xử lý categorical; BorderlineSMOTE chỉ synthesize gần biên.

3. Focal Loss — vì sao lũy thừa γ? (Lin 2017)

Cross-entropy chuẩn (CE):    L_CE  = -log(p_t)
Focal loss:                   L_FL  = -(1 - p_t)^γ · log(p_t)
                                       └──── modulator ────┘

Với γ ≥ 0 là "focusing parameter" (thường γ=2).

Trực giác từng phần:

  • Với sample DỄ (model đã confident, p_t = 0.9): (1-0.9)^2 = 0.01 → loss bị nhân 0.01 → gần như bỏ qua.
  • Với sample KHÓ (model uncertain, p_t = 0.3): (1-0.3)^2 = 0.49 → loss gần như giữ nguyên → model focus vào đây.

Bảng minh họa hiệu ứng γ:

p_t     | CE loss  | FL loss γ=1 | FL loss γ=2 | FL loss γ=5
─────────────────────────────────────────────────────────────
0.9     | 0.105    | 0.011       | 0.001       | 0.0000010     ← easy: bị dập
0.5     | 0.693    | 0.347       | 0.173       | 0.0217        ← medium: giảm nhẹ
0.1     | 2.303    | 2.072       | 1.865       | 1.360         ← hard: giữ gần đủ

Vì sao chọn γ = 2 (mặc định RetinaNet)? Empirical: γ=0 = CE thuần (không focus), γ=1 hơi mềm, γ≥3 quá dập easy samples → model bỏ qua data có thể học được. γ=2 là "sweet spot" trong nhiều task classification imbalanced. Phải tune như hyperparameter.

Extended focal loss (α-balanced):

L_FL = -α_t · (1 - p_t)^γ · log(p_t)
        ↑ weight per class (như class_weight)

Kết hợp cả 2 kỹ thuật: α cân class-level (như class_weight), γ cân sample-level (khó vs dễ).

💡 2 kỹ thuật hiện đại hơn SMOTE/class-weight cổ điển (đọc SAU deep-dive toán học ở trên)

ADASYN (He et al. 2008) — cải tiến trực tiếp của SMOTE (mục "Technique 2" ở trên): SMOTE tạo SỐ LƯỢNG synthetic BẰNG NHAU cho mọi sample minority, bất kể sample đó "dễ" hay "khó". ADASYN thông minh hơn: nó đếm, với mỗi sample minority x_i, có BAO NHIÊU trong K-nearest-neighbor của nó thuộc lớp MAJORITY (gọi tỷ lệ này là r_i) — sample nào có r_i cao (nghĩa là nó "lạc" giữa vùng toàn sample majority, gần ranh giới quyết định, khó phân loại) sẽ được ưu tiên tạo NHIỀU synthetic hơn hẳn; sample nào đã nằm an toàn giữa các sample minority khác (r_i thấp) thì gần như không cần thêm synthetic. Nói ngắn gọn: SMOTE rải đều, ADASYN rải tập trung vào vùng khó.

Class-Balanced Loss qua "effective number of samples" (Cui et al. 2019, CVPR) — vấn đề nó giải quyết: class_weight cổ điển (mục "Technique 1" ở trên) tính trọng số TỶ LỆ NGHỊCH với số lượng mẫu thô — nhưng thực tế, 1000 mẫu của cùng 1 class thường KHÔNG mang lượng thông tin gấp 1000 lần so với 1 mẫu, vì nhiều mẫu bị TRÙNG LẶP THÔNG TIN (overlap) với nhau. Cui et al. đề xuất "effective number" (số lượng hiệu dụng) để đo lượng thông tin THẬT SỰ mới, không phải đếm thô:

E_n = (1 - β^n) / (1 - β)      # n = số mẫu thô của class, β ∈ [0,1) gần 1 (VD β=0.99)

Ví dụ so sánh n=10 (minority) vs n=1000 (majority), β=0.99:
  E_10   = (1 - 0.99^10)  / (1-0.99) = (1-0.904)/0.01  ≈ 9.56
  E_1000 = (1 - 0.99^1000)/ (1-0.99) = (1-0.0000432)/0.01 ≈ 100.0

Trọng số ∝ 1/E_n → tỷ lệ trọng số minority:majority = (1/9.56)/(1/100.0) ≈ 10.5:1
So với class_weight thô (tỷ lệ nghịch trực tiếp số mẫu) = 1000/10 = 100:1

→ Effective-number weighting chỉ "đẩy" minority lên MẠNH GẤP ~10.5 lần majority,
  KHÔNG MẠNH BẰNG 100 lần như cách tính class_weight thô — vì nó nhận ra 1000
  mẫu majority không thực sự mang lượng thông tin gấp 100 lần so với 10 mẫu
  minority, chỉ khoảng 10 lần thôi (do trùng lặp thông tin giữa các mẫu).

Insight: cả 2 kỹ thuật đều đi theo tinh thần chung "đừng đối xử với mọi sample/mọi class như nhau một cách MÁY MÓC" — ADASYN phân biệt sample DỄ/KHÓ trong cùng 1 class, Class-Balanced Loss phân biệt "số lượng thô" với "lượng thông tin thật". Cả 2 đều là hướng phát triển tự nhiên sau khi đã hiểu rõ SMOTE/class_weight cổ điển ở mục 3-4 và deep-dive toán học ở trên.

🔍 So sánh 5 kỹ thuật fix class imbalance (đọc SAU khi đã hiểu 5 techniques ở mục 3-7)

Câu hỏi thực tế: Class imbalance 1:100 (99% negative, 1% positive). Có 5 fix chính. Chọn cái nào? Đây là bảng compare với case cụ thể.

Bảng so sánh 5 techniques

TechniqueCơ chếData sau xử lýƯuNhượcBest for
1. Oversampling (SMOTE) Tạo synthetic positive samples nearby existing 50/50 balanced Không mất positive info; work với tabular data Synthetic samples có thể unrealistic → model học pattern giả Small dataset, positive class rare tự nhiên
2. Undersampling Bỏ bớt negative samples random 50/50 balanced (nhưng nhỏ hơn) Train nhanh, model không thấy noise Mất info negative — model không học đủ pattern negative Data quá lớn (millions), positive nhiều nhưng vẫn imbalanced
3. Class weight Model penalize sai positive gấp N lần Data giữ nguyên Không đụng data. Đơn giản. Weight quá cao → over-predict positive → precision drop XGBoost/sklearn built-in support. Default cho tabular.
4. Threshold tuning Giảm threshold quyết định positive (0.5 → 0.2) Data giữ nguyên, train giữ nguyên Rẻ nhất, dễ tune post-hoc Chỉ trade precision/recall, không giải quyết gốc Đã có model tốt, chỉ cần adjust operating point
5. Focal loss Loss weight cao cho hard examples (uncertain) Data giữ nguyên Model focus hard cases automatically Cần deep learning, không work cho tree-based Object detection, medical NN

3 case cụ thể — kỹ thuật nào win?

=== Case 1: Fraud detection (bank transactions) ===
Data: 10M transactions, 0.1% fraud (10k positive)
Imbalance: 1:1000

Techniques evaluated:
1. SMOTE oversampling: create 5M synthetic fraud → recall 88%, precision 25%
   ❌ Precision thấp — 75% flagged là false positive, bank không xử lý được
2. Undersampling: chọn 10k fraud + 10k normal → recall 82%, precision 68%
   ❌ Model chỉ thấy 20k samples, không đủ pattern normal
3. Class weight (weight_positive=1000): recall 90%, precision 71%
   ✅ Best balance, work với XGBoost
4. Threshold=0.2 với class weight: recall 95%, precision 65%
   ✅ Trade precision cho recall — bank chọn dựa vào cost analysis

WINNER: Class weight + Threshold tuning (fine-grained control)

=== Case 2: Ung thư tầm soát (medical) ===
Data: 100k patients, 1% có ung thư (1k positive)
Cost analysis: miss 1 ung thư = death, false positive = extra test $200

Techniques evaluated:
1. Threshold=0.15 (thấp): recall 98%, precision 25%
   ✅ Miss chỉ 20 ca, spend $600k extra test — acceptable
2. Class weight + threshold=0.3: recall 95%, precision 45%
   Cost hiệu quả hơn nhưng miss 50 ca — không acceptable trong medical

WINNER: Threshold tuning ultra-low (recall > precision khi cost of miss cao)

=== Case 3: Stock prediction UP class hiếm ===
V18 3-class: UP 25%, DOWN 25%, FLAT 50%
Imbalance nhẹ 1:2

Techniques evaluated:
1. SMOTE trên UP class: no gain, adds noise
2. Class weight balanced: CV +1% improvement
3. Threshold tuning: 0.4 cho UP → precision drop 5%
4. 2-stage architecture (Stage 1 gate FLAT): CV +8% ⭐

WINNER: Architecture fix (2-stage) thay vì class weight hack

RULE: Imbalance nhẹ (1:2 to 1:5) → thay đổi architecture đôi khi tốt hơn.
      Imbalance nặng (1:100+) → cần class weight + threshold tuning.

Metric compare — accuracy misleading, dùng gì?

MetricCông thứcKhi dùngCạm bẫy
Accuracy (TP+TN)/all Class balanced tự nhiên ❌ 99% với imbalanced (chỉ đoán majority)
Precision TP/(TP+FP) False positive costly (spam, ad) Cao khi rất strict → miss real positive
Recall TP/(TP+FN) Miss positive costly (fraud, ung thư) Cao khi loose → nhiều false positive
F1 2·P·R/(P+R) Balance precision + recall Không phân biệt được cost khác nhau
PR-AUC Diện tích dưới precision-recall curve Imbalanced classification ⭐ Best metric cho imbalanced
ROC-AUC Diện tích dưới TPR-FPR curve Balanced classification Misleading khi imbalanced (luôn cao)

Insight quan trọng — thứ tự try

  1. Bước 1: Test class weight (không đụng data, cheap)
  2. Bước 2: Nếu vẫn tệ, tune threshold post-hoc
  3. Bước 3: Nếu vẫn tệ, SMOTE với care (validate synthetic samples realistic)
  4. Bước 4: Xem xét kiến trúc lại (2-stage, filter negative trước)
  5. Bước 5: Nếu deep learning, thử focal loss

Rule: Bắt đầu với technique rẻ nhất (class weight, threshold), chỉ dùng SMOTE khi cần.

8. V18 case — FLAT majority

V18 áp dụng 3 techniques kết hợp
  1. Class weight: FLAT weight 0.5, UP/DOWN weight 1.5 (V18 sample_weight formula)
  2. 2-stage cascade: stage 1 gate binary balanced hơn 3-class, stage 2 train on subset (đã filter FLAT)
  3. Threshold tuning: dir_conf_gate tune trên val set để maximize skill score (không hard-code 0.5)
⚠️ 3 hiểu lầm phổ biến về class imbalance
  1. "Class imbalance = phải luôn resample data" — SAI. Nếu metric bạn tối ưu (VD: log-loss, PR-AUC) đã đúng cho imbalance, model TỰ HỌC được. Resample chỉ cần khi model dùng threshold cứng 0.5 + metric = accuracy. Nhiều Kaggle winner không dùng SMOTE, chỉ dùng class_weight + threshold tuning.
  2. "SMOTE trước khi split train/val" — SAI KINH ĐIỂN (đã ghi ở L2.4). Sinh synthetic từ toàn bộ data → synthetic của val nằm gần training samples → val score inflated (leak). LUÔN split trước, SMOTE chỉ trên train fold.
  3. "Accuracy 99% thì model tốt" — SAI khi imbalance nặng. Với 1:99, dumb model predict all-majority đã có 99%. Metric đúng: PR-AUC, F1 (nếu care cả 2), Recall@fixed-precision (nếu care recall dưới constraint precision). Accuracy nên bị "ban" khỏi imbalanced classification report.

✅ QA Gate

1. Vì sao accuracy misleading trên 99:1 imbalanced?

Dumb model predict majority luôn → 99% accuracy. Recall minority = 0 → business fail. Dùng precision + recall + F1 + PR-AUC.

2. ROC-AUC vs PR-AUC — cái nào cho imbalanced?

PR-AUC. ROC-AUC dùng FPR = FP/N; với N huge, FPR tăng chậm → curve deceptive. PR-AUC tập trung minority class precision — reflect actual value.

3. SMOTE pitfall gì?

Synthetic samples có thể unrealistic (interpolate 2 minority samples ra pattern impossible). Cross-validation phải split BEFORE SMOTE, không AFTER (leak vào val).

4. Focal loss γ=0 vs γ=2. Effect?

γ=0: reduce về cross-entropy standard. γ=2: hard examples được weighted up. Easy examples (confidence > 0.7) contribute rất ít loss → model focus hard cases → better cho long-tailed distributions.

5. Threshold tuning trên train set — sai gì?

Overfit. Threshold phải tune trên val set (hoặc CV) để honest. Test set final chỉ evaluate.
