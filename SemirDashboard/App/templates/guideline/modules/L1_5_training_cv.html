💡 Sample weight + CV bằng ngôn ngữ đời thường

Sample weight = trọng số câu hỏi trong đề thi: Học sinh làm 100 câu, giáo viên đánh dấu 5 câu "trọng tâm" giá 50% điểm. Học sinh khôn ngoan sẽ luyện 5 câu đó kỹ hơn. Sample weight bảo model: "sample này quan trọng hơn — làm sai trả giá đắt".

V18: Sample gần đây (2024-2026) weight cao hơn sample cũ (2021) — vì market regime đổi, dữ liệu gần phản ánh reality hiện tại tốt hơn.

Cross-validation = tự thi thử: Học 4 chương, giấu 1 chương để tự test → biết mình yếu chỗ nào. Xoay vòng 5 lần (mỗi chương giấu 1 lần) = 5-fold CV. Optuna = tự động tìm hyperparameter tốt nhất qua nhiều lần thi thử.

1. Sample weights — không phải mọi sample bằng nhau

V18 dùng 3 loại weight nhân với nhau:

1.1 Class balance weight

# Nếu FLAT chiếm 50%, UP 25%, DOWN 25%:
# Cân đối để mỗi class contribute equal loss:
class_weight = {0: 2.0, 1: 1.0, 2: 2.0}   # DOWN, FLAT, UP
w_class = np.array([class_weight[y] for y in y_train])

1.2 Recency decay (temporal weight)

# Sample xa quá khứ giảm weight — market pattern change over time.
# Half-life 200 ngày:
tau = 200 / np.log(2)   # decay constant
days_ago = (today - date_i).days
w_time = np.exp(-days_ago / tau)
📖 Vì đâu có công thức w = exp(−t/τ) với τ = half_life/ln(2)?

Câu hỏi: Tại sao dùng exponential decay, không phải linear (1 − t/T)?

Bước 1 — Đặc tính mong muốn:

  • Sample hôm nay (t=0): weight = 1 (max).
  • Sample rất cũ (t → ∞): weight → 0 (dần dần bỏ qua, không âm).
  • Smooth, không cutoff cứng (linear cutoff tại t=T thì sample t=T+1 nhảy về 0 → discontinuity).

Bước 2 — Chọn exponential vì: Hàm exp(−t/τ) thoả mãn cả 3 tính chất trên + có "memory-less" property: rate decay tại mọi t đều bằng −w/τ (proportional). Tính chất này khớp intuition "market forgetting past exponentially fast".

Bước 3 — Định nghĩa half-life: Ta muốn "sau H ngày, weight còn 1/2". Đặt:

w(H) = exp(−H/τ) = 1/2
=> −H/τ = ln(1/2) = −ln(2)
=> τ = H / ln(2)

Ví dụ H = 200 ngày → τ = 200/0.693 ≈ 288.5. Verify:

t=0:    w = exp(0) = 1.00
t=200:  w = exp(−200/288.5) = exp(−0.693) = 0.50  ✓ (half-life đúng)
t=400:  w = exp(−400/288.5) = 0.25  (quarter)
t=1000: w = exp(−3.47) = 0.031 (gần bỏ)

Analogy đời thực: Giống decay của cà phê nhớ vị — càng lâu càng nhạt, nhưng không bao giờ 0 hoàn toàn. Half-life 200 ngày = "market pattern mờ đi một nửa sau 200 phiên", khớp research empirical VN market (regime shift ~1 năm).

1.3 Label clarity weight

# Samples với |return| xa threshold rõ ràng → weight cao.
# Samples borderline (|return| ≈ threshold) → weight thấp.
excess = np.abs(returns) - label_threshold
w_clarity = 1 + np.clip(excess / label_threshold, 0, 3)   # 1x → 4x

# Combine (cap 5×):
w_total = w_class * w_time * w_clarity
w_total = np.clip(w_total, 0.1, 5.0)

xgb.fit(X, y, sample_weight=w_total)

2. Cross-Validation — test không gian lận

🚨 K-Fold random KHÔNG dùng được cho time-series

K-Fold random shuffle rồi chia — nghĩa là test set có thể chứa data từ 2020 và train set chứa 2024. Đó là data leak: model biết tương lai khi train quá khứ. Test score sẽ inflate, deploy sẽ chết.

Walk-forward validation (đúng cách)

from sklearn.model_selection import TimeSeriesSplit

# 5 folds, mỗi fold train quá khứ + test tương lai gần
cv = TimeSeriesSplit(n_splits=5, gap=5)  # gap 5 phiên tránh leak

for train_idx, test_idx in cv.split(X):
    X_train, y_train = X[train_idx], y[train_idx]
    X_test, y_test = X[test_idx], y[test_idx]
    # train + eval

# Visualization:
# Fold 1: train [.....]      test [T]
# Fold 2: train [.......]    test [T]
# Fold 3: train [.........]  test [T]
# ...
# Test luôn là tương lai của train.

Vì sao cần gap?

Label ở time t được tính từ close[t] → close[t+h]. Nếu test bắt đầu ngay sau train end, thì:

  • Train cuối cùng sample t → label dùng close[t+h]
  • Test đầu tiên sample t+1 → feature có thể tính từ close[t]
  • Overlap → leak

Gap ≥ horizon (5 phiên cho h=5) tránh overlap.

Optuna implementation V18

import optuna

def objective(trial):
    params = {
        'n_estimators': trial.suggest_int('n', 200, 800),
        'max_depth': trial.suggest_int('d', 3, 8),
        'learning_rate': trial.suggest_float('lr', 0.02, 0.2, log=True),
        'subsample': trial.suggest_float('ss', 0.5, 1.0),
        'colsample_bytree': trial.suggest_float('cs', 0.5, 1.0),
        'reg_alpha': trial.suggest_float('ra', 1e-4, 1.0, log=True),
        'reg_lambda': trial.suggest_float('rl', 1e-4, 5.0, log=True),
        'min_child_weight': trial.suggest_int('mcw', 1, 30),
        'gamma': trial.suggest_float('gm', 0.0, 2.0),
    }
    m = XGBClassifier(**params)
    m.fit(X[tr], y[tr], sample_weight=w[tr], eval_set=[(X[val], y[val])],
          early_stopping_rounds=30, verbose=False)
    preds = m.predict_proba(X[val])
    return log_loss(y[val], preds, sample_weight=w[val])

study = optuna.create_study(
    direction='minimize',
    sampler=optuna.samplers.TPESampler(seed=42),   # TPE Bayesian
    pruner=optuna.pruners.MedianPruner(),
)
study.optimize(objective, n_trials=50, timeout=1800)
best_params = study.best_params

Tricks quan trọng

  • log=True cho params như lr, reg_alpha (search log-scale)
  • Pruner: kill trial sớm nếu underperform (tiết kiệm 30-50% compute)
  • Sampler TPE (Tree-structured Parzen Estimator) mặc định — hoạt động tốt hầu hết trường hợp
  • Tie in với CV: mỗi trial chạy full CV (5 folds) → chọn trial có mean CV loss thấp nhất

5. Nested CV — đánh giá pipeline có tune

Pitfall

Nếu bạn tune hyperparameters bằng CV rồi report cùng CV score làm final estimate → overfit đến CV. Đúng cách: nested CV.

Outer CV (5-fold): estimate final performance
├─ Fold 1:
│  ├─ Inner CV (3-fold): tune hyperparameters
│  ├─ Train với best params trên full outer-train
│  └─ Eval trên outer-test → score_1
├─ Fold 2: ... → score_2
...
└─ Fold 5: ... → score_5

Final: mean(score_1..5)

✅ QA Gate

1. K-Fold random KHÔNG dùng được cho time-series — vì sao?

Random shuffle → test set chứa data từ tương lai vs train quá khứ → data leak. Score inflate, deploy fail.

2. TimeSeriesSplit dùng gap để làm gì?

Tránh label leak khi label horizon > 0. Với h=5, feature at t=T dùng data ≤ T; label dùng close[T+5]. Nếu test bắt đầu t=T+1 (không gap), sample T+1's feature có thể sử dụng info tại T (already in train label). Gap ≥ h fix.

3. Recency decay half-life 200 ngày nghĩa là gì?

Sample cách 200 ngày trước có weight = 0.5 (half). Cách 400 ngày = 0.25. Model prefer recent samples — VN market pattern thay đổi (macro shift, retail flow).

4. Optuna vs Grid search cho 9 hyperparameters mỗi cái 5 giá trị. Trial count?

Grid: 5^9 = ~2M trials (infeasible). Optuna 50-100 trials thường đủ với TPE sampler — vì Bayesian pick smart, không waste ở regions bad.

5. Nested CV vs single CV khi tune hyperparameters — score nào honest?

Nested. Single CV overfits vì hyperparams được chọn bằng chính CV → CV score biased. Nested tách tune (inner) vs estimate (outer) — outer score = production estimate.

❌ Sai lầm thường gặp vs ✅ Thực tế
  • ❌ "Shuffle data trước CV để random hơn" → ✅ SAI cho time-series. Shuffle = leak. Luôn dùng TimeSeriesSplit.
  • ❌ "Recency decay càng dốc càng tốt vì recent luôn quan trọng" → ✅ Decay quá dốc → hầu như chỉ train trên 100 samples cuối → high variance + không học pattern cross-regime. Half-life 200-500 là balance.
  • ❌ "Optuna 200 trials luôn hơn 50 trials" → ✅ Với 50 trials, TPE đã converge — thêm chỉ marginal. Dùng compute quí đó cho retraining nhiều seed.
  • ❌ "Nested CV double compute nên skip" → ✅ Skip nested = report inflated score. Nếu compute hạn chế: dùng 1 hold-out set 20% giữ nguyên (final), tune bằng CV trên 80%.
  • ❌ "Sample weight = class_weight sklearn" → ✅ class_weight chỉ balance class. sample_weight tổng quát hơn: per-sample (recency + volatility + class).

6. 🎓 Interview-style Q&A

Q1: "Vì sao Purged CV thay vì thường TimeSeriesSplit?"

Model answer: "Nếu label horizon > 0 (VD predict return T+5), sample tại T+498 có label dùng close[T+503], overlap với test range bắt đầu T+500 → vertical leak. Purge = drop N samples ở boundary (N = horizon). López de Prado (2018) chứng minh purge tăng honest score 3-8% + fix ảo tưởng edge. V18 áp dụng: gap = 5 phiên."

Q2: "Hyperparameter search với 15 params. Grid, random hay Bayesian?"

Model answer: "Bayesian (Optuna TPE). Grid: 5^15 = infeasible. Random: cover space tốt nhưng waste 40% trials ở region bad. Bayesian: học từ trials trước → focus vùng promising, 50-100 trials thường match random 500+ trials. Bonus: median pruner kill trial sớm → tiết kiệm 30% compute."

Q3: "Sample weight có ảnh hưởng calibration không?"

Model answer: "Có. Weighted training = model overfit vào high-weight samples → output probability lệch theo distribution weighted, không phải natural. Fix: calibrate trên val set với sample_weight cũng weighted CÙNG cách. Hoặc: calibrate trên val set unweighted và chấp nhận trade-off. V18 chọn weighted calibration cho consistency."

Q4: "Định nghĩa nhanh: gap, purge, embargo trong CV."

Model answer:
• Gap: khoảng cách giữa train end và test start, ngăn label overlap.
• Purge: drop samples train mà label overlap với test range (khi horizon > 0).
• Embargo: sau test set, thêm 1 buffer trước fold tiếp theo — tránh label từ test leak vào future train (khi có serial correlation).
Kết hợp: Purged Embargoed CV = gold standard finance ML (López de Prado 2018).

Q5: "Nested CV score 55%, single CV score 62%. Trust cái nào cho production?"

Model answer: "Nested 55%. Single CV được dùng để tune hyperparameter → score đó biased upward (chọn params tốt nhất trên chính CV = overfit CV). Nested tách tune (inner) khỏi estimate (outer) → outer score honest. Gap 7% cho thấy hyperparameter search có overfit đáng kể — có thể reduce bằng ít trials + regularize params bounds."
