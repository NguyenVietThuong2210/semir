💡 Multi-agent bằng ngôn ngữ đời thường

Xưởng may áo dài: 1 người không thể may 1 áo dài đẹp một mình. Chia việc: Thiết kế → Cắt vải → May → Thêu → QC → Đóng gói. Mỗi thợ chuyên môn khác nhau, giao tiếp qua "áo đang làm dở" (state).

AI Orchestrator: SpecAnalyze (phân tích yêu cầu) → TaskDecompose (chia task nhỏ) → Engineer (viết code) → Reviewer (review) → Tester (test) → PRWriter (viết PR). Mỗi agent = 1 role chuyên biệt.

Vì sao không dùng 1 agent to? Vì mỗi role cần system prompt riêng, tool set riêng, thậm chí model tier riêng (Engineer dùng Opus, PRWriter dùng Haiku). Chia nhỏ = specialize + cheaper.

Why shared state không message passing?

  • Testable: state hoàn toàn deterministic từ inputs
  • Checkpointable: save/restore any point
  • Auditable: every agent read/write logged
  • Simpler: no message queue / broker infrastructure

4. Design multi-agent — 4 questions

Answer these để design multi-agent system
  1. What roles bạn cần? (list unique functions)
  2. How agents pass info? (shared state vs direct message)
  3. Who decides next agent? (supervisor Python vs LLM route)
  4. How handle loops + failures? (max iterations, escalation paths)

5. Peer-to-peer pattern (alternative)

Instead of supervisor: agents talk to each other directly.
E.g., AutoGen chat pattern: UserProxy + Assistant + Critic conversation

Pros:
- Emergent collaboration
- More flexible

Cons:
- Non-deterministic
- Harder debug
- More tokens (conversation overhead)

Best cho brainstorming / creative tasks. Không phù hợp SDLC.

6. Blackboard + Consensus (voting) patterns

6.1 Blackboard — shared "bảng thông báo"

# Analogy: bảng thông báo ký túc xá — ai có info mới thì viết lên,
# ai cần thì đọc. Không direct message.

class Blackboard:
    facts: dict[str, Any] = {}
    subscribers: dict[str, list[Callable]] = {}

    def post(self, key, value, source_agent):
        self.facts[key] = {"value": value, "source": source_agent, "ts": now()}
        for cb in self.subscribers.get(key, []):
            cb(value)    # trigger interested agents

    def read(self, key): return self.facts.get(key)

# E-commerce fraud detection: RiskAgent posts "user_score=0.8",
# FraudAgent subscribes, wakes up when score>0.7 → deep investigation.

Blackboard tốt khi (1) agents heterogeneous (Python + external service), (2) opportunistic — ai có info thì đóng góp, không schedule.

6.2 Consensus / Voting — 3 LLMs bỏ phiếu

async def consensus_predict(question, models=[claude, gpt4, gemini]):
    votes = await asyncio.gather(*[m.predict(question) for m in models])
    # Majority vote
    tally = Counter(votes)
    winner, count = tally.most_common(1)[0]
    confidence = count / len(models)   # 3/3=1.0, 2/3=0.67
    if count < len(models) // 2 + 1:   # strict majority required (not a float threshold —
        return {"verdict": "abstain", "reason": "no consensus", "votes": votes}  # 2/3=0.6666... would sit ON a "<0.67" cutoff and wrongly abstain
    return {"verdict": winner, "confidence": confidence}

Dùng khi (1) high-stakes decision (approve loan, flag fraud), (2) trade-off cost 3× nhưng error rate giảm mạnh (Anthropic + OpenAI + Gemini ít khi cùng sai một kiểu).

- Engineer: propose diff
- Tester: run tests, report
- Security: audit security implication
- Engineer: iterate based on both
Turns: 8-20, emergent solution, might loop

Team Lead → assign to sub-team (Engineer + QA)
Engineer proposes → QA validates → Team Lead reviews
Turns: same as Supervisor but with escalation layer

Agents bid: Engineer bids "1h", Bugsnag bot bids "30 min"
Cheapest bidder wins task

8. VN scenario — Shopee-style customer support (multi-agent)

4-agent hierarchy cho Shopee VN support
User: "đơn hàng #A123 chưa giao 5 ngày rồi, tôi muốn hoàn tiền"

Triage agent (Haiku, $0.001):
  intent = REFUND + LATE_DELIVERY  → route OrderAgent + RefundAgent parallel

OrderAgent (Sonnet + tools: query_shipment):
  → lookup #A123 → "stuck at Đà Nẵng hub 3 ngày"

RefundAgent (Sonnet + tools: refund_policy_kb, wallet_credit):
  → policy: >48h late = eligible full refund
  → propose: hoàn 350k vào ShopeePay

Supervisor (Python — không LLM):
  if OrderAgent.evidence == "late" AND RefundAgent.eligible == True:
      auto_approve if amount < 500k else human_gate
  → auto_approve → execute wallet_credit(350000)

Response agent (Haiku):
  → viết reply tiếng Việt lịch sự, xin lỗi khách, thông báo hoàn tiền

Insight: Split roles theo cost tier. Triage/Response dùng Haiku (rẻ), Business logic dùng Sonnet, Supervisor dùng Python. 1 request full lifecycle ~$0.02 thay vì $0.15 nếu dùng Opus xuyên suốt.

9. Anti-patterns

Đừng làm
  1. LLM route control flow: cho LLM quyết "next agent = ?" → non-deterministic, không unit test được. Rule: Python router.
  2. Không giới hạn loop: QA fail → Engineer retry → QA fail → ... infinite. Luôn max_iter + progress detection.
  3. Shared state global mutable: mọi agent write bất cứ field nào → race + hard debug. Rule: mỗi agent chỉ write field của mình.
  4. Full context vào mỗi agent: PM report 5k tokens gửi cho mọi agent → token cost N× lãng phí. Rule: pass slice cần thiết.
  5. Chatty peer-to-peer khi supervisor đủ: brainstorm 5 agents cho task "fix typo" → overengineered. Match pattern complexity với task complexity.

10. Case study — pipeline_intent routing

Same 11 agents, 5 different flows

PM detect intent → shape pipeline:

  • query: PM → Analyser → DONE (2 agents)
  • test: PM → Analyser → QA → DONE (3 agents)
  • review: PM → Analyser → Reviewer → DONE
  • bug_fix: PM → Analyser → Engineer → QA → DONE (retry ≤2×)
  • feature: full 11-agent pipeline với human gate

Adaptive complexity: cheap tasks skip agents. Expensive full SDLC for features. Cost proportional to task ambition.

11. Failure handling — 3 modes

  1. Retry with fix: QA fail-minor → Engineer retry với QA feedback (max 2 loops, MAX_QA_ITERATIONS)
  2. Escalate back: QA fail-major → back Analyser để redesign (max 2 loops)
  3. Fail forward: unrecoverable → Retrospective → FAILED terminal (learn from failure)

2. Shared state vs message passing — vì sao Anthropic + LangGraph chọn shared?

(1) Deterministic testing (state = pure function of inputs). (2) Checkpointable (save/restore any time). (3) No broker infrastructure. (4) Auditable (every read/write logged).

3. Supervisor pattern vs Peer-to-peer — recommend nào cho code assistant?

Supervisor. Code review chuỗi predictable (PM → Eng → Review → QA). Peer-to-peer nhiều tokens + non-deterministic. Supervisor Python cheap, testable, auditable.

4. Failure escalation — 3 tiers explain.

(1) Retry với fix (QA fail-minor → Eng again). (2) Escalate back (fail-major → Analyser redesign). (3) Fail forward (unrecoverable → Retrospective learn from failure, terminate FAILED).

5. Adaptive complexity via pipeline_intent — impact economics?

Query costs ~$0.1 (2 agents). Feature costs ~$5-20 (11 agents). Not paying for SDLC overhead khi user chỉ ask question. $5/$0.1=50× đến $20/$0.1=200× cost reduction tùy độ phức tạp feature, so với việc chạy full pipeline cho mọi request.
