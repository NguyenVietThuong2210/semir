8.2 · Skills — Modular Agent Capabilities

Cách package domain knowledge + workflows thành reusable "skills" agent load on-demand. Claude Skills format, best practices, ví dụ từ PredictStock daily-investor-report skill.

Level 8 · AI Artifacts · ~30 phút

🎯 Learning objectives

  • Định nghĩa Skill vs Agent vs Tool
  • Design Skill folder structure
  • Write SKILL.md manifest
  • Best practices: gating, evidence, QA gates
💡 Skill / Agent / Tool bằng ngôn ngữ đời thường

Bếp phở:

  • Đầu bếp = agent (LLM + loop + goal "phục vụ khách")
  • Dao, thớt, bếp gas = tools (atomic — cắt, chặt, đun)
  • Công thức phở gia truyền = skill (package prompts + steps + KB, on-demand invoke khi khách gọi "phở bò tái")

Skill khác Tool: dao (tool) chỉ cắt được — dùng đâu cũng vậy. Công thức phở (skill) chứa nhiều bước + kiến thức domain + template output. Skill invoke tools, không phải thay thế.

Skill khác Agent: agent thường xuyên chạy (running loop). Skill nạp on-demand khi cần.

4. Best practices

4.1 Trigger conditions

When to invoke skill

Skill.md should specify WHEN. E.g., daily-investor-report: user says "generate today's investor report", "mode=all", etc.

Agent load skill only when trigger matches. Not always in system prompt (would waste context).

4.2 Sections structure

  • Persona (role, tone)
  • Data collection (what inputs, from where)
  • Analysis framework (decision rules)
  • Output format (structured, examples)
  • Self-QA gate (mandatory checks)
  • Hard rules (RULE 1, RULE 2 với enforcement patterns)

4.3 Evidence + Traceability

Every claim in output link to source. daily-investor-report §11 Anti-Hallucination check: mọi số hiển thị phải có trong embedded JSON.

4.4 Versioning

# SKILL.md version bump khi:
- Add new section
- Change rule enforcement
- Modify output schema
- Fix bug

# Log breaking changes at bottom for users to migrate.

6.5 · SKILL.md YAML frontmatter — full spec

📋 Deep-dive — SKILL.md structure, tool inheritance, when to author

YAML frontmatter (các field khả dụng — không phải mọi field đều bắt buộc/đang dùng)

---
name: daily-investor-report              # unique slug (matches folder)
description: |                            # 1-2 lines, LLM đọc để decide invoke
  Generate professional daily Vietnamese
  stock investor report in HTML. Two modes:
  vn30 (~30s) or all (~60s).
allowed-tools:                            # pre-approve tool cho lượt gọi skill (KHÔNG phải whitelist chặn tool khác — xem giải thích dưới)
  - Bash(python:*)
  - Bash(pytest:*)
  - Read
  - Write(reports/**)                     # scoped write
  - Grep
argument-hint: "[mode=vn30|all]"          # UX hint hiển thị lúc invoke
---

Lưu ý: SKILL.md thật của daily-investor-report hiện chỉ có 3 field (name/description/argument-hint) — không có allowed-tools. Ví dụ trên minh họa field khả dụng trong spec, không phải trích nguyên văn file thật.

Tool inheritance rules (cơ chế thật, đã verify với docs chính thức)

  • allowed-tools: pre-approve các tool trong list cho lượt gọi skill đó — bỏ qua permission prompt cho riêng list này. KHÔNG chặn tool ngoài list; mọi tool khác vẫn gọi được bình thường theo permission settings hiện có của agent. Đây KHÔNG phải whitelist/sandbox.
  • disallowed-tools: đây mới là field thật sự CHẶN — tool trong list này không được gọi trong lượt invoke skill, kể cả parent có quyền.
  • Scoped patterns: Write(reports/**) chỉ pre-approve ghi trong reports/ (không tự động chặn ghi chỗ khác — muốn chặn phải dùng disallowed-tools hoặc permission deny riêng).
  • Composition (skill A invoke skill B): hành vi hợp nhất permission chưa được document rõ ràng trong spec chính thức — đừng giả định "intersection" hay "union" cụ thể nào khi thiết kế skill chain.

Skill vs prompt library — analogy VN

Prompt library = tủ giấy note dán mảnh ("nhớ ghi số điện thoại", "đừng quên khóa cửa"). Nhanh, gọn, dùng cho ghi chú lẻ.
Skill = cẩm nang kỹ thuật in đóng bìa (VD: cẩm nang bảo trì máy bay). Có mục lục, có checklist QA, có bản vẽ, có version. Bắt buộc cho việc lặp lại + có consequence khi sai.

Anti-pattern quan trọng

  • Nhầm allowed-tools là sandbox: allowed-tools chỉ pre-approve, không hề chặn tool khác — 1 bug trong skill vẫn có thể gọi rm -rf nếu agent parent có quyền đó. Fix: muốn thật sự chặn phải dùng disallowed-tools hoặc permission deny rules riêng, không thể trông cậy vào allowed-tools để "sandbox" skill.
  • Skill trigger description mơ hồ: "handle stock stuff" → LLM invoke lung tung. Fix: description chỉ rõ khi nào invoke, kèm arg pattern.

Interview Q&A

  1. Q: Skill có state không? A: Không native (mỗi invoke fresh). Skill có "convention state" — quy ước ghi output ra reports/, next invoke đọc lại. Đó là app-level state, không phải skill runtime.
  2. Q: Skill vs sub-agent (L8.1) — khi nào chọn cái nào? A: Skill = deterministic workflow user trigger (report generation). Sub-agent = LLM delegation cho sub-task (research, plan). Skill có KB + scripts, sub-agent chỉ có prompt.
  3. Q: allowed-tools có sandbox skill không? A: Không — allowed-tools chỉ pre-approve tool trong list (skip permission prompt), không chặn tool ngoài list. Muốn chặn thật sự, dùng disallowed-tools hoặc permission deny rules.

7. Skill discovery patterns

7.1 Explicit invocation

User: "/daily-investor-report mode=all"
System: match skill by name → invoke

7.2 Keyword triggering

User: "Generate today's stock report"
System: detect "stock report" → suggest daily-investor-report skill

7.3 Auto-selection

Available skills listed in system prompt as one-liners:
- daily-investor-report: Generate daily VN stock report
- ml-walkforward-backtest: Backtest ML predictions

LLM decide which to invoke based on user request.

8. Anti-patterns

  1. Mega-skill: 1 skill cover 20 tasks. Fix: split by domain.
  2. No self-QA: skill trust LLM output blindly. Fix: mandatory checks (skill §11).
  3. Prompt drift: skill.md 1000+ lines LLM ignore parts. Fix: hard rules with enforcement patterns.
  4. No versioning: bug fix silently → downstream break. Fix: semver + changelog.
  5. Scripts + skill divergence: SKILL.md says X, script does Y. Fix: single source (README references code).

🔬 DSPy Signatures — khác gì với SKILL.md, tại sao gọi "compiler"?

Vấn đề cụ thể: SKILL.md (§3 ở trên) là văn bản TIẾNG ANH TỰ DO — engineer tự tay viết câu chữ prompt, muốn cải thiện phải tự đọc lại + sửa tay. DSPy đặt câu hỏi ngược: nếu coi việc gọi LLM giống 1 HÀM (function) có input/output rõ ràng, liệu có thể để MÁY TỰ TÌM câu chữ prompt tốt nhất thay vì người tự viết tay?

Cơ chế: DSPy có 3 khái niệm tách biệt: Signature = khai báo input/output mong muốn dưới dạng khai báo (declarative), KHÔNG chứa câu chữ prompt cụ thể — VD question -> answer hay context, question -> reasoning, answer. Module = 1 pattern gọi LLM cụ thể implement cho signature đó (VD Predict gọi thẳng 1 lần, ChainOfThought tự thêm bước suy luận trước khi trả lời) — module có thể ghép thành pipeline nhiều bước. Teleprompter (compiler) = component TỰ ĐỘNG tối ưu câu chữ prompt thật sự + chọn ví dụ few-shot cho từng module trong pipeline, dựa trên 1 tập dữ liệu mẫu (training set nhỏ) + 1 hàm đánh giá (metric) — giống compiler biến code cấp cao thành máy-code tối ưu, DSPy biến signature khai báo thành prompt cụ thể tối ưu.

⚠️ Chỗ dễ nhầm nhất: DSPy KHÔNG train lại model weight (không phải fine-tuning) — "compile" ở đây nghĩa là tìm ra CÂU CHỮ PROMPT + VÍ DỤ FEW-SHOT tốt nhất cho model ĐÃ CÓ SẴN (frozen), qua thử nghiệm nhiều biến thể trên tập training rồi giữ lại biến thể cho điểm metric cao nhất — khác hẳn RLHF/fine-tuning (L4.4/L4.5, đổi weight thật).

✅ QA Gate

1. Skill vs Agent vs Tool — 3 dimension mỗi cái khác nhau.

Skill = package (prompt + scripts + KB) domain-specific. Agent = LLM + tools + loop + goal (running). Tool = atomic capability (Read, Bash). Skill invoke agent that use tools.

2. SKILL.md sections tối thiểu?

Persona, Data collection, Analysis/decision framework, Output format, Self-QA gate. Optional: hard rules, examples, versioning changelog.

3. Vì sao skill có §11 Self-QA gate?

LLM output có thể hallucinate, miss format, invent numbers. Skill mandate LLM check output trước declare success. Anti-hallucination check verify every numeric value có source trong data. Fail → rename file _FAILED.html, alert user.

4. daily-investor-report skill trigger keyword nào?

Explicit: /daily-investor-report [args]. Keyword: "daily report", "stock investor report", "VN30 analysis". Auto: agent detect user asking for market analysis.

5. Anti-pattern "mega-skill" — fix?

Split by domain. E.g., 1 skill cover both stock report + earnings analysis → split thành 2 skills invocable independently. Alternative: sub-skills (nested folder) cho related workflows.
