8.6 · AI Frameworks Landscape (2025)

Survey 15+ frameworks: LangChain, LangGraph, LlamaIndex, DSPy, Semantic Kernel, CrewAI, AutoGen, Haystack, Instructor, Guidance, Outlines, Pydantic AI. Pick right tool per job.

💡 Framework survey bằng ngôn ngữ đời thường

Đi chợ Đông Ba mua nguyên liệu bún bò Huế: Không mua hết ở 1 sạp — mỗi sạp chuyên 1 thứ. Sạp rau (LangChain — general purpose), sạp thịt (LlamaIndex — RAG heavy), sạp gia vị (DSPy — optimize prompt), sạp bún tươi (CrewAI — multi-agent orchestration).

Framework survey = biết sạp nào chuyên gì để chọn đúng. Không có sạp "best" cho mọi món — có sạp best cho từng công thức.

Nguyên tắc chọn:

  • Cần graph phức tạp có loop/branch → LangGraph
  • Cần RAG heavy trên nhiều loại document → LlamaIndex
  • Cần tune prompt tự động → DSPy
  • Cần structured output đảm bảo JSON → Instructor/Pydantic AI
  • Cần multi-model routing rẻ nhất → LiteLLM

2. LangChain

Pros

  • Large ecosystem (500+ integrations)
  • Community + docs mature
  • Multi-language (Python, JS/TS)

Cons

  • API changes frequent (breaking upgrades)
  • Over-abstraction (many wrapping layers)
  • Perf overhead vs raw SDK calls

Best cho: prototype fast, standard patterns (RAG chatbot, summarization).

3. LangGraph

Pros

  • State machine model perfect cho agents
  • Deterministic routing (Python control)
  • Native HITL + checkpointing
  • Production-ready (Postgres, Redis)

Cons

  • Learning curve (state, edges, reducers)
  • Overkill cho simple chains

Best cho: complex agent workflows, SDLC pipelines, HITL (ai_orchestrator uses this).

4. LlamaIndex

Pros

  • RAG-first design
  • Rich retrieval strategies (sub-question, tree-summarize, agent-based)
  • Vector DB adapters extensive
  • Good abstractions cho document processing

Cons

  • Weaker cho general orchestration vs LangGraph
  • Agent support secondary priority

Best cho: knowledge base search, document QA, enterprise data indexing.

5. DSPy (Stanford)

Different philosophy

Instead prompt engineering (edit strings), DSPy: declarative programming with LLMs. Define signature (input/output), let DSPy compile optimal prompt via few-shot bootstrap.

import dspy

class GenerateAnswer(dspy.Signature):
    """Answer question based on context."""
    context = dspy.InputField()
    question = dspy.InputField()
    answer = dspy.OutputField(desc="short answer")

# Define pipeline:
class RAG(dspy.Module):
    def __init__(self, num_passages=3):
        self.retrieve = dspy.Retrieve(k=num_passages)
        self.generate = dspy.ChainOfThought(GenerateAnswer)

    def forward(self, question):
        context = self.retrieve(question).passages
        return self.generate(context=context, question=question)

# Compile với few-shot examples auto-selected:
rag = RAG()
compiled_rag = dspy.BootstrapFewShot().compile(rag, trainset=trainset)

Best cho: production systems where prompt need optimization, research iterations.

6. Semantic Kernel (Microsoft)

Pros

  • Enterprise-grade, .NET + Python + Java
  • Plugins ecosystem (Semantic Kernel plugins)
  • Integration Azure OpenAI, Microsoft stack
  • Planning: plan + execute pattern built-in

Cons

  • Smaller community vs LangChain
  • Focus Microsoft ecosystem

Best cho: Enterprise .NET shops, Azure users.

7. CrewAI

Pros

  • Simple role-based multi-agent
  • Easy to define agents với goal + backstory
  • Tasks orchestrate sequential/hierarchical

Cons

  • Limited flexibility (fixed patterns)
  • Non-deterministic routing (some LLM decisions)
  • Persistence secondary

Best cho: prototype multi-agent apps, small teams simple workflows.

8. AutoGen (Microsoft Research)

Pros

  • Conversational multi-agent (chat pattern)
  • Rich UserProxy for HITL
  • Code execution native

Cons

  • LLM decide next speaker → non-deterministic
  • Conversational overhead expensive
  • Debug hard (state = conversation history)

Best cho: brainstorm/creative tasks, research.

9. Haystack (deepset)

Pros

  • Enterprise NLP pipeline
  • Strong retrieval + ranker components
  • Elasticsearch + Postgres + vector DBs

Cons

  • Heavier setup vs LlamaIndex
  • Traditional NLP roots (some legacy API)

Best cho: enterprise search, question answering, hybrid search (BM25 + dense).

Interview Q&A

  1. Q: DSPy vs LangChain philosophically? A: LangChain = imperative (bạn viết chain). DSPy = declarative (bạn khai báo signature, compiler viết prompt). DSPy như PyTorch cho prompts — có optimizer, có metric.
  2. Q: LlamaIndex vs LangChain cho RAG? A: LlamaIndex sinh ra cho RAG, có 20+ index types, response synthesizers built-in. LangChain general-purpose, RAG là 1 use case. Pick LlamaIndex nếu RAG là core.
  3. Q: Framework nào "future-proof"? A: Không cái nào. Skill quan trọng: hiểu abstraction underneath (LLM API + prompt + parse) — thay framework dễ khi hiểu core.

10. Instructor / Outlines / Guidance / Pydantic AI

Category: structured output enforcement.

Instructor

from instructor import from_openai
from pydantic import BaseModel

class UserInfo(BaseModel):
    name: str
    age: int

client = from_openai(OpenAI())
user = client.chat.completions.create(
    model="gpt-4",
    response_model=UserInfo,  # Pydantic model → auto-parse
    messages=[{"role": "user", "content": "John is 25"}]
)
# user is UserInfo instance, guaranteed valid

Outlines

Grammar-guided decoding — LLM output guaranteed valid via constrained token sampling. Regex + JSON schema supported.

Guidance

Microsoft's version. Template with markers cho LLM fill. Structured output + streaming.

Pydantic AI

Newest (2024). Type-safe, Pydantic-native, provider-agnostic.

🔬 Cơ chế constrained decoding — vì sao Outlines đảm bảo 100% valid, Instructor chỉ retry

Vấn đề cụ thể: §10 mới nói "Outlines = grammar-guided decoding, LLM output guaranteed valid" và "Instructor = post-hoc validate + retry" — nhưng CHƯA giải thích TẠI SAO 1 bên "guaranteed" còn bên kia chỉ "retry". Đây là 2 CƠ CHẾ hoàn toàn khác nhau, không chỉ khác implementation.

Cơ chế Instructor (post-hoc, retry-based): model sinh ra text TỰ DO như bình thường (không bị can thiệp trong lúc sinh) → sau khi sinh XONG, code parse output thành JSON → validate bằng Pydantic → nếu FAIL (JSON sai cú pháp, thiếu field, sai type) → gửi LẠI lỗi cho model kèm yêu cầu sửa → lặp lại tối đa N lần. Vì model sinh tự do, không có gì NGĂN nó sinh sai ngay từ đầu — chỉ có cơ chế PHÁT HIỆN + YÊU CẦU SỬA sau khi đã sai.

Cơ chế Outlines (constrained decoding, sai từ gốc là KHÔNG THỂ): model sinh text từng TOKEN MỘT (như bình thường), nhưng TRƯỚC KHI chọn token tiếp theo, hệ thống tính trước "nếu đang ở vị trí NÀY trong JSON schema, những token nào HỢP LỆ tiếp theo?" (VD: sau dấu {"name": ", chỉ token nào tạo ra ký tự string hoặc dấu " đóng mới hợp lệ — token số hay dấu ngoặc vuông bị LOẠI hoàn toàn) — bằng cách gán xác suất -∞ (hoặc set 0) cho MỌI token không hợp lệ trước khi model chọn, rồi mới sample. Cơ chế theo dõi vị trí hợp lệ này thường dùng finite-state machine (máy trạng thái hữu hạn) được biên dịch sẵn từ JSON Schema/grammar.

Đây là lý do đa số production app dùng Claude/GPT (API đóng) chọn Instructor-style, còn team tự host model mở chọn Outlines.

12. Anti-patterns

  1. Framework Frenzy: adopt every new framework. Fix: master 2-3 well, know landscape.
  2. Over-abstraction: 5 wrapper layers, debug painful. Fix: prefer thin abstractions or raw SDK.
  3. Lock-in: framework tie deeply, hard migrate. Fix: use LiteLLM adapter, provider-agnostic patterns.
  4. Framework as silver bullet: use framework for problem không suit. Fix: solve problem first, framework later.
  5. Version chaos: LangChain 0.1 → 0.3 breaking. Fix: pin versions, upgrade planned intervals.

13. Emerging (2025)

  • Pydantic AI: Pydantic-native LLM SDK, gaining traction
  • Agent Development Kit (ADK): Google's agent framework, MCP-native
  • Mastra: TypeScript-first alternative to LangGraph
  • Motia: event-driven multi-agent
  • Letta / MemGPT: persistent memory agents

14. Interview cheat sheet

  1. "LangChain vs LangGraph — khi nào?" → LangChain: linear chains, RAG, prototype. LangGraph: agents, cycles, HITL, state management. Same team, different scope.
  2. "Vì sao DSPy?" → Prompt engineering brittle + manual. DSPy compile prompt automatic + optimize với examples. Best cho research + production maintain.
  3. "Structured output 3 options?" → (1) LLM native (OpenAI structured output, Claude tools). (2) Instructor (Pydantic). (3) Grammar-guided (Outlines).
  4. "Choose framework production?" → Prefer least abstraction. Raw SDK cho simple. LangGraph cho complex agents. Avoid over-abstraction. Pin versions.

✅ QA Gate

1. Categorize 8 frameworks bạn biết theo layer.

Orchestration: LangGraph, LangChain, Haystack. RAG: LlamaIndex. Multi-agent: CrewAI, AutoGen. Declarative: DSPy. Structured output: Instructor, Outlines. SDK unified: LiteLLM, Semantic Kernel. Runtime: vLLM. Observability: LangSmith.

2. LangGraph vs LangChain — 3 lý do choose LangGraph.

(1) State machine cho agents (cycles, conditional edges). (2) HITL native (interrupt_before + resume). (3) Checkpointing (Postgres/Redis).

3. DSPy compile prompt — mechanism?

Define signature (input/output fields). DSPy tests candidate prompts (few-shot examples auto-selected via bootstrap or teleprompter). Best prompt chọn. Optimize gradient-like on prompt space. Result: prompt outperform manual engineering, self-improve với data.

4. Structured output — Instructor vs Outlines mechanism khác?

Instructor: post-hoc validate output (LLM output → Pydantic parse → retry nếu fail). Outlines: grammar-guided decoding — during generation, LLM tokens constrained match grammar. Outlines guaranteed valid; Instructor iterative retry.

5. Framework Frenzy anti-pattern — fix?

Adopt 2-3 core (LangGraph + LlamaIndex + Instructor covers 80% needs). Know landscape (this module) but not commit. New framework only if solve real problem existing not. Migration cost 3-6 months typical.
