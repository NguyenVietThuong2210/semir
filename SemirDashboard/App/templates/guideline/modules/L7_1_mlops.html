💡 MLOps bằng ngôn ngữ đời thường

Trồng lúa: Không phải chỉ gieo hạt → gặt lúa. Cần cả pipeline: chuẩn bị đất (data collection) → gieo (train) → chăm bón (validate) → gặt (deploy) → xay xát (serving) → bán (monitor doanh thu) → mua giống mới (retrain). Bỏ 1 khâu = không có gạo trên bàn.

MLOps = DevOps + ML-specific: data versioning (DVC), model registry (MLflow), CI/CD cho model (không chỉ code), monitoring drift, auto-retrain. Model không phải "code chạy 1 lần rồi thôi" — nó già đi theo thời gian và cần chăm sóc liên tục.

3. Model registry

Vì sao cần (đọc TRƯỚC ví dụ)

Model registry = "sổ hộ tịch" cho model. Mỗi lần train ra model mới, registry ghi lại: model này version bao nhiêu, train từ data nào, code commit nào, đo được metrics gì, đang ở trạng thái nào (dev/staging/prod). Không có registry → không ai biết "model đang chạy prod tên gì, train ngày nào, có rollback được không" — giống công ty không lưu hợp đồng lao động, hỏi ai đang làm vị trí gì cũng không biết.

Khác feature store (lưu dữ liệu đầu vào) và experiment tracking (lưu log các lần thử nghiệm chưa chắc dùng) — model registry chỉ lưu các model đã "tốt nghiệp" từ experiment, sẵn sàng candidate cho production.

Model versioning:
├─ v1: baseline (2024-01)
├─ v2: added foreign flow features
├─ v3: retrained monthly (2024-Q2)
├─ v3.1: hotfix bad quantization
├─ v4: current production
└─ v5-candidate: A/B testing

# Registry tracks:
- Model artifacts (weights)
- Training data version
- Code version (git commit)
- Metrics on evaluation set
- Deployment status (dev, staging, prod, deprecated)

5. Drift detection

3 loại drift

TypeWhatDetect
Data driftFeature distribution shiftKL divergence, PSI, KS test
Concept driftP(y|X) changeAccuracy drop, prediction feedback
Prediction driftModel output distribution shiftCompare output histograms over time

Population Stability Index (PSI)

PSI = Σ (actual% - expected%) × ln(actual% / expected%)

# expected% = phân phối feature lúc TRAIN (baseline, ví dụ RSI hôm train)
# actual%   = phân phối feature HÔM NAY (production, đang phục vụ)
# Chia feature thành bins (ví dụ RSI: 0-10, 10-20, ... 90-100),
# so % lượng data rơi vào mỗi bin giữa 2 thời điểm.

# Interpret:
# PSI < 0.1: no significant change
# 0.1 <= PSI < 0.25: minor shift, monitor
# PSI >= 0.25: major shift, retrain candidate

# Compute per feature, alert on top-10 features

Ví dụ tính tay — feature RSI chia 2 bin đơn giản (oversold <30, còn lại ≥30):

Lúc TRAIN (expected%): bin <30 chiếm 20%, bin ≥30 chiếm 80%
HÔM NAY (actual%):      bin <30 chiếm 35%, bin ≥30 chiếm 65%  (thị trường downtrend nhiều hơn)

PSI = (0.35-0.20)×ln(0.35/0.20) + (0.65-0.80)×ln(0.65/0.80)
    = 0.15×ln(1.75)            + (-0.15)×ln(0.8125)
    = 0.15×0.5596              + (-0.15)×(-0.2076)
    = 0.0839                  + 0.0311
    = 0.115

→ PSI=0.115 nằm trong khoảng [0.1, 0.25) = "minor shift, monitor" — chưa
  đủ ngưỡng retrain nhưng đáng theo dõi thêm vài ngày.
🔍 Common confusion — KL divergence vs KS test vs PSI

Cả 3 đều trả lời "2 phân phối có khác nhau không?" nhưng khác cách đo:

  • KL divergence: đo "tốn bao nhiêu thông tin" nếu dùng phân phối cũ để xấp xỉ phân phối mới. Số càng lớn = khác biệt càng nhiều. Nhạy với bin rỗng (chia 0).
  • KS test (Kolmogorov-Smirnov): so khoảng cách lớn nhất giữa 2 đường cong phân phối tích lũy (CDF). Có p-value → trả lời "khác biệt có ý nghĩa thống kê không".
  • PSI: biến thể của KL divergence, dùng phổ biến trong ngành finance/credit scoring vì có ngưỡng diễn giải rõ ràng (0.1 / 0.25) — dễ set alert tự động hơn p-value.

V18/V20 dùng PSI vì đơn giản, dễ alert theo threshold cố định, không cần hiểu thống kê sâu để action.

6. Retrain triggers

  • Drift-based: PSI > threshold auto-trigger
  • Performance-based: 7d rolling hit rate drops > 10pp (V20 Slice 5 pattern)
  • Data-based: N new labels available
  • Manual: engineer decision

8. Training-serving skew

Common bug

Train dùng pandas rolling(20).mean(), serve dùng NumPy convolution — subtle differences (window inclusive vs exclusive). Prediction offset → prod accuracy drop.

Fix: shared code path. V18 dùng cùng features_v18.py::build_v18_features() cho cả train và inference. Test: assert train_features == serve_features on same input.

9. Retraining pipeline

Trigger → Fetch data → Feature engineering → Train
     ↓                                          ↓
     └── Validate features ─────────────────── Evaluate
                                                ↓
                                             Champion vs challenger
                                                ↓
                                             Approve → Register → Canary → Prod
💡 Champion vs Challenger là gì

Champion = model đang chạy production hiện tại (đương kim vô địch). Challenger = model mới vừa train xong, đang xin "đấu" để thay thế. So sánh 2 model trên cùng 1 evaluation set (offline) hoặc cùng traffic (online, xem canary section 7) — challenger phải thắng rõ ràng trên metric quan trọng (hit rate, ECE) mới được promote. Nếu challenger thua hoặc ngang → giữ nguyên champion, không đổi vì đổi tốn risk mà không lợi.

✅ QA Gate

1. Feature store — vì sao cần?

Prevent training-serving skew. Same transformation guaranteed for both. Also: reuse features across models, low-latency online serving.

2. Data drift vs Concept drift?

Data drift: P(X) change (input distribution). Concept: P(y|X) change (relationship input-target). Data drift detectable without labels (features histogram). Concept requires ground truth (labels catch up).

3. PSI = 0.35 feature "RSI". Action?

Major shift. Investigate: market regime change? Data pipeline bug? User behavior shift? Retrain if root cause not fixable. Meanwhile: watch model accuracy — may need canary rollout of new model.

4. Canary deploy 5%. New model higher error rate. Do gì?

(1) Investigate error type — same as old or new bug? (2) Freeze rollout. (3) Reproduce locally. (4) Fix + re-canary. (5) If severity high: rollback 100% to old immediately.

5. V20 model dir hygiene — 3 rules từ V19.5 lessons?

(1) Never in-place edit. (2) Immutable versioned dirs (v20-candidate/, v20/). (3) Atomic cut-over via mv + engine restart. Rollback = single mv command. Documented trong README_model_dirs.md.
