2. Anthropic Contextual Retrieval (2024)

Core idea: prepend to each chunk 1-2 sentence AI-generated context mô tả chunk nằm ở đâu trong document.

# Before (naive chunk):
"The company reported revenue of $8.5B."

# After (contextualized chunk):
"This chunk is from Acme Corp Q3 2024 10-K filing, section on
Financial Performance. The company reported revenue of $8.5B."

Impact (Anthropic benchmark)

  • Contextual embeddings alone: −35% retrieval failure rate
  • + Contextual BM25: −49% failure rate
  • + Reranking: −67% failure rate

Implementation với prompt caching

DOCUMENT_CONTEXT_PROMPT = """
<document>{{WHOLE_DOCUMENT}}</document>
Here is the chunk we want to situate within the whole document:
<chunk>{{CHUNK_CONTENT}}</chunk>
Give a short succinct context to situate this chunk. Answer only with the context.
"""
# Cache document (large) → chỉ pay full price 1 lần cho toàn corpus

3. Hybrid retrieval — BM25 + Dense + RRF

# BM25 catches exact keywords (ticker "VNM", số "8.5B")
# Dense catches semantic ("revenue" ~ "sales" ~ "top line")

def reciprocal_rank_fusion(bm25_hits, dense_hits, k=60):
    scores = {}
    for rank, doc_id in enumerate(bm25_hits):
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)
    for rank, doc_id in enumerate(dense_hits):
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])

4. Cross-encoder reranking

Bi-encoder (dùng cho retrieval): embed query + doc riêng, cosine sim. Nhanh (millions docs).

Cross-encoder (dùng cho rerank): concat [query || doc] → BERT → 1 score. Chậm nhưng chính xác.

# Pipeline: top-100 (bi-encoder) → rerank → top-10 (cross-encoder)
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")
pairs = [[query, doc.text] for doc in top100]
scores = reranker.predict(pairs)
top10 = sorted(zip(top100, scores), key=lambda x: -x[1])[:10]

Options

  • Cohere Rerank v3 — API, best quality, ~$2/1000 search units (1 unit = 1 query + tới 100 docs, không tính theo token)
  • bge-reranker-v2-m3 — open source, multilingual, đủ tốt
  • Jina Reranker — mid tier

5. GraphRAG (Microsoft Research 2024)

Problem: naive RAG fail cho "global queries" (theme, summarize) vì retrieval là local.

GraphRAG pipeline:

  1. LLM extract entities + relationships từ corpus → knowledge graph
  2. Community detection (Leiden algorithm) → clusters
  3. LLM sinh community summary cho mỗi cluster (bottom-up)
  4. Query time: match query → relevant communities → return summaries

Trade-off: index cost cao (LLM parse full corpus), nhưng answer global queries tốt hơn naive 3-5×.

6. Agentic RAG

6.1 Self-query decomposition

User: "So sánh revenue growth của VNM và MSN trong Q2 2024"
Agent: decompose thành:
  - "VNM Q2 2024 revenue growth"
  - "MSN Q2 2024 revenue growth"
Run 2 retrievals separately, LLM synthesize.

6.2 Query router

if query.type == "factual":     use vector RAG
elif query.type == "aggregate": use SQL over structured
elif query.type == "temporal":  use time-series index
elif query.type == "global":    use GraphRAG summaries

Ví dụ số cụ thể — cùng query "Q2 revenue growth Vinamilk" trên 100 docs

Naive RAG:
  Retrieve top-5 dense embedding matches
  → Miss 2/5 vì embedding "revenue" ≠ "doanh thu" (cross-lingual gap)
  → Recall: 60%, Answer quality: 6/10

Contextual RAG (Anthropic 2024):
  Prepend "[Vinamilk Q2 2024 earnings report, Financial Highlights section]"
  vào mỗi chunk trước khi embed
  → Recall: 78%, Answer quality: 7.5/10

Hybrid + Rerank:
  BM25 catches "VNM ticker" exact + Dense catches "doanh thu tăng"
  Rerank top-100 → top-5
  → Recall: 88%, Answer quality: 8.5/10 ⭐

GraphRAG (cho "chiến lược đầu tư 2024 theme"):
  Naive RAG fail vì knowledge scatter khắp docs
  GraphRAG extract "chiến lược đầu tư" community → summary → 3× better

HyDE (Hypothetical Document Embeddings) — Gao 2022

Analogy VN: "hỏi rồi tự trả lời giả định trước → dùng câu trả lời giả để tìm doc thật". Vì query ngắn (câu hỏi) và doc dài (câu trả lời) sống ở vùng embedding khác nhau — mismatch. Solution: sinh hypothetical answer trước, embed câu trả lời giả, dùng nó match doc thật.

# Pipeline HyDE
query = "Q2 2024 revenue Vinamilk là bao nhiêu?"

# Step 1: LLM sinh câu trả lời GIẢ ĐỊNH (không cần đúng số)
hypothetical = llm(f"Answer this question: {query}")
# → "Vinamilk Q2 2024 báo cáo doanh thu khoảng 15,000 tỷ đồng,
#    tăng 5% so với cùng kỳ, driven by domestic dairy segment..."

# Step 2: Embed hypothetical (không phải query)
h_emb = embed(hypothetical)

# Step 3: Retrieve với h_emb thay query
docs = vector_store.search(h_emb, top_k=10)

# Insight: hypothetical + real doc same "shape" (statement style)
# → retrieval accuracy tăng 15-30% cho question-style query

Trade-off: thêm 1 LLM call trước retrieval (+latency + cost). Dùng khi corpus large + query dạng câu hỏi phức tạp. Skip cho keyword search.

Ragas metrics — công thức chính xác

Analogy VN: "chấm bài RAG như chấm essay — có 4 tiêu chí độc lập". Mỗi metric = 1 rubric.

Faithfulness — chi tiết step-by-step

# Step 1: LLM decompose answer thành atomic claims
answer = "VNM có doanh thu Q2 2024 là 15.5k tỷ, tăng 8% YoY, biên gộp 42%"
claims = llm_decompose(answer)
# → ["VNM revenue Q2 2024 = 15.5k tỷ", "VNM revenue Q2 2024 grew 8% YoY", "VNM gross margin = 42%"]

# Step 2: Cho từng claim, verify từ context
verdicts = []
for claim in claims:
    v = llm(f"Given context:\n{context}\n\nIs claim supported? {claim}\nYES/NO")
    verdicts.append(v == "YES")

# Step 3: Faithfulness = mean(verdicts)
faithfulness = sum(verdicts) / len(claims)
# VD: 2/3 supported → faithfulness = 0.67

Answer relevance + Context precision + Context recall — ví dụ số cụ thể (3 metric còn lại chưa có số)

# --- Answer relevance ---
# LLM sinh ngược n=3 câu hỏi từ answer, so cos_sim với query gốc
answer = "VNM Q2 2024 revenue tăng 8% YoY"
query_goc = "Q2 2024 revenue Vinamilk là bao nhiêu?"
generated_questions = [
    "VNM Q2 2024 revenue tăng bao nhiêu?",   # cos_sim(embed(q), embed(query_goc)) = 0.94
    "Doanh thu quý 2 Vinamilk thế nào?",      # cos_sim = 0.81
    "VNM có lãi Q2 không?",                   # cos_sim = 0.42 (answer không nói lãi — LLM suy diễn lệch đề)
]
answer_relevance = mean([0.94, 0.81, 0.42]) = 0.72
# → 0.72 = khá nhưng không cao, vì 1/3 câu hỏi sinh ngược bị lệch — dấu hiệu answer
#   có phần không trực tiếp trả lời câu hỏi gốc.

# --- Context precision (top-5 retrieved, v_k=1 nếu chunk k relevant) ---
retrieved = [chunk1(relevant), chunk2(relevant), chunk3(irrelevant), chunk4(relevant), chunk5(irrelevant)]
# precision@1 = 1/1 = 1.0   (chunk1 relevant, v_1=1 → tính)
# precision@2 = 2/2 = 1.0   (chunk2 relevant, v_2=1 → tính)
# precision@4 = 3/4 = 0.75  (chunk4 relevant, v_4=1 → tính; chunk3 kéo mẫu số xuống)
context_precision = (1.0*1 + 1.0*1 + 0.75*1) / 3  # 3 = tổng số relevant chunks trong top-5
                   = 2.75 / 3 = 0.917

# --- Context recall (ground-truth answer có 4 câu, đếm mấy câu được retrieved context support) ---
gt_sentences = ["revenue tăng 8%", "biên gộp 42%", "dẫn đầu ngành sữa", "guidance Q3 tích cực"]
supported_by_retrieved = ["revenue tăng 8%", "biên gộp 42%", "dẫn đầu ngành sữa"]  # thiếu guidance Q3
context_recall = 3 / 4 = 0.75
# → retrieval bỏ sót 1 fact quan trọng (guidance Q3) dù precision cao (0.917) — đây
#   chính là lý do PHẢI track cả precision lẫn recall, 1 con số cao không đủ nói lên
#   chất lượng retrieval toàn diện.

Agentic RAG — self-query + self-critique

# Self-query (LlamaIndex): LLM tự rewrite query cho retrieval tốt hơn
raw_query = "cổ phiếu nào rẻ nhất VN30?"
structured = llm_extract_filter(raw_query)
# → {filter: {sector: "*", metric: "PE"}, sort: "asc", limit: 5, group: "VN30"}
# Chuyển thành SQL / metadata filter thay chỉ vector search

# Self-critique (Reflexion pattern)
answer_v1 = llm(prompt + retrieved_docs)
critique = llm(f"Critique answer for factual accuracy + completeness: {answer_v1}")
if critique.mentions_gaps():
    new_query = llm(f"What to retrieve to fill gaps: {critique}")
    more_docs = retrieve(new_query)
    answer_v2 = llm(prompt + retrieved_docs + more_docs)
# Loop until critique clean or max_iter

Cohere Rerank v3 — mechanics

  • Model: multilingual cross-encoder (support 100+ languages, tốt cho tiếng Việt)
  • Input: query + 1000 docs (batch)
  • Output: relevance score 0-1 cho từng doc
  • Cross-encoder score = joint attention (query, doc) → nhạy với semantic + keyword
  • Latency: ~200ms cho 100 docs, ~1s cho 1000 docs
  • Best practice: retrieve top-100 (bi-encoder) → rerank top-100 → keep top-5 cho LLM context

Anti-pattern VN

  • Ragas thay human eval: Ragas = CI signal, không thay human. Faithfulness 0.9 vẫn có thể sai nếu ground-truth-fact không có trong context.
  • HyDE cho keyword query: "VNM giá bao nhiêu" — HyDE overkill, chỉ cần BM25 exact match ticker.

Interview Q&A

  1. Q: HyDE khi nào KHÔNG dùng? A: Query có exact keyword/ticker/entity (BM25 win). Query đơn giản factual (embedding trực tiếp OK). Latency-critical (thêm LLM call = +500ms).
  2. Q: Faithfulness vs Answer Relevance khác gì? A: Faithfulness = answer có bám context? (hallucination check). Answer relevance = answer có trả lời đúng câu hỏi? (topical). 2 orthogonal — có thể faithful nhưng irrelevant, hoặc relevant nhưng hallucinated.
  3. Q: Self-critique loop infinite risk? A: Yes. Cap max_iter=3. Nếu critique vẫn nhiều gap sau 3 loop → escalate HITL, không bơm thêm LLM call.
  4. Q: Context precision vs recall trade-off? A: Precision cao = ít noise cho LLM (top-3 relevant). Recall cao = cover đủ ground truth (top-20 maybe). Rerank giúp cả 2 (retrieve wide, rerank narrow).

✅ QA Gate

1. Contextual Retrieval giảm failure rate bao nhiêu?

Anthropic 2024: −35% embedding alone, −49% với BM25, −67% với rerank. Cost: 1-shot LLM call per chunk (dùng prompt caching để cheap).

2. Bi vs cross-encoder — khi nào dùng cái nào?

Bi-encoder cho retrieval (top-100 từ millions, fast). Cross-encoder cho rerank (top-100 → top-10, slow nhưng accurate). Pipeline chuẩn: bi → cross.

3. Lost in the middle problem?

Liu 2023: LLM attention degrade với info giữa long context. Fix: rerank + top-3 only, đừng dump top-20 raw. Test bằng needle-in-haystack.

4. Khi nào cần GraphRAG?

Global queries (theme, summarize corpus). Naive RAG chỉ trả lời local factual. GraphRAG cost cao index nhưng giải quyết class problems khác.

5. RAGAS 4 metrics core?

Faithfulness (answer↔context), Answer relevance (answer↔question), Context precision (relevant chunks / retrieved), Context recall (retrieved chunks / ground truth). Không thay human eval, chỉ CI signal.
