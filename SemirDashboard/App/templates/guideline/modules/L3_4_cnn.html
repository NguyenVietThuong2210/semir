💡 CNN bằng ngôn ngữ đời thường

Đọc báo bằng kính lúp: Bạn không cần đọc cả trang cùng lúc. Kính lúp 3×3 pixel quét từ trái qua phải, trên xuống dưới, mỗi lần "thấy" 1 pattern nhỏ (cạnh, góc, chữ). Đó là convolution.

Weight sharing: Cùng 1 kính lúp dùng cho cả ảnh — vì cạnh chân mèo giống cạnh tai mèo (locality). Không cần học 1 detector riêng cho mỗi vị trí.

Layer sâu = trừu tượng tăng dần: Layer 1 nhận cạnh + màu → Layer 2 ghép thành mắt/tai/mũi → Layer 3 ghép thành mặt mèo. Giống thị giác con người phân tầng.

1D-CNN cho time-series: Kính lúp trượt theo trục thời gian — bắt pattern như "3 ngày tăng liên tiếp rồi giảm mạnh" (như candle chart pattern).

1. Convolution — intuition + công thức chi tiết

Analogy: lăng kính di chuyển scan ảnh. Kính 3×3 quét từ trái qua phải, trên xuống — mỗi vị trí "chụp" 1 patch, tính dot product với kernel → 1 số ra feature map.

🔢 Convolution — worked example với số

Setup: Input 4×4, kernel 3×3 (edge detector Sobel-x), stride=1, padding=0.

Input I:              Kernel K (Sobel-x):
[[ 1, 2, 3, 4],       [[-1, 0, 1],
 [ 5, 6, 7, 8],        [-2, 0, 2],
 [ 9,10,11,12],        [-1, 0, 1]]
 [13,14,15,16]]

Output size: (4 - 3 + 2·0)/1 + 1 = 2 → output 2×2.

Cell output[0,0] = tổng element-wise product của K với patch I[0:3, 0:3]:

Patch [[1,2,3], [5,6,7], [9,10,11]]
     · [[-1,0,1], [-2,0,2], [-1,0,1]]
= (-1·1) + (0·2) + (1·3)
+ (-2·5) + (0·6) + (2·7)
+ (-1·9) + (0·10)+ (1·11)
= -1 + 0 + 3 - 10 + 0 + 14 - 9 + 0 + 11
= 8

Cell output[0,1] patch I[0:3, 1:4]:

Patch [[2,3,4], [6,7,8], [10,11,12]]
= -2 + 0 + 4 - 12 + 0 + 16 - 10 + 0 + 12 = 8

Cả 2 = 8 vì Sobel-x đo horizontal gradient — ảnh này đều đặn theo x. Output cuối:

Output = [[8, 8],
          [8, 8]]        # Sobel-x nhất quán = constant horizontal edge strength

Công thức tổng quát (2D conv với multi-channel)

y[b, o, i, j] = Σ_c Σ_ki Σ_kj  x[b, c, i·S+ki-P, j·S+kj-P] · K[o, c, ki, kj]  +  bias[o]

# b = batch, o = output channel, c = input channel
# i, j = output position; ki, kj = kernel position (0..K-1)
# S = stride, P = padding

Output shape formula

Out = ⌊(In + 2P - K) / S⌋ + 1

# K = kernel size, P = padding, S = stride
# In=32, K=3, P=1, S=1 → Out = (32+2-3)/1 + 1 = 32   (same padding)
# In=32, K=3, P=1, S=2 → Out = (32+2-3)/2 + 1 = 16   (downsample 2×)
# In=224, K=7, P=3, S=2 → Out = (224+6-7)/2 + 1 = 112 (ResNet stem)

Ý nghĩa biến:

BiếnÝ nghĩaẢnh hưởng output
K (kernel size)Kích thước filter (3, 5, 7)K lớn → RF lớn, nhiều params, output nhỏ
S (stride)Bước nhảy khi trượtS=2 → downsample 2× (thay pooling)
P (padding)Zero-pad viền inputP = (K-1)/2 → same padding, giữ size
C_in, C_outSố channel in/outParams = K·K·C_in·C_out + C_out (bias)
dilation dKhoảng cách giữa element kerneld=2 → RF effective = K + (K-1)·1

Receptive field — nhìn xa được bao nhiêu?

# RF của layer L = RF_{L-1} + (K_L - 1) · Π stride của layer trước
# VD ResNet stem: conv 7×7 s=2 → RF=7, output stride=2
#   → maxpool 3×3 s=2 → RF = 7 + (3-1)·2 = 11, stride=4
#   → conv 3×3 s=1 → RF = 11 + (3-1)·4 = 19, stride=4
# Deeper CNN accumulate RF exponentially với stride hoặc pooling.
# Dilated conv d=2^L → RF exponential trong depth mà không lose resolution.

Hình dung trực tiếp — RF "phình" ra qua từng layer (cùng ví dụ ResNet stem ở trên):

Input:                     [────────────────────────]  RF = 1  (mỗi pixel chỉ thấy chính nó)
Sau conv 7×7 s=2:          [███████──────────────────]  RF = 7
Sau + maxpool 3×3 s=2:     [███████████───────────────]  RF = 11
Sau + conv 3×3 s=1:        [███████████████████───────]  RF = 19

→ mỗi layer cộng thêm phần "phình" quanh vị trí output, không reset về 0
→ xếp đủ layer/stride/dilation → 1 neuron ở layer cuối "nhìn thấy" cả ảnh gốc

Pooling và vì sao stride>1

  • Max pool 2×2 s=2: lấy max mỗi patch 2×2 → output nửa size. Translation invariant nhẹ, mất spatial info.
  • Avg pool: mean thay max. Global avg pool (GAP): mean toàn feature map → thay FC layer cuối (ResNet, EfficientNet).
  • Stride > 1 thay pooling: modern architectures (ResNet-v2, ConvNeXt) dùng strided conv thay maxpool — learnable downsampling, không mất info như max.
  • Tại sao downsample? Giảm compute (H×W ÷ 4 mỗi lần), tăng RF, buộc học representation compact.

3. ResNet residual block — the game changer

def residual_block(x):
    residual = x
    x = conv3x3(x)
    x = BatchNorm(x)
    x = ReLU(x)
    x = conv3x3(x)
    x = BatchNorm(x)
    x = x + residual   # skip connection
    return ReLU(x)

Vì sao work? Gradient có path direct qua skip → không vanish. Layer chỉ cần học residual (small correction), dễ hơn học full function từ đầu.

🔗 ResNet skip connection — math cụ thể
# Forward
y = F(x, {W_i}) + x        # F = 2-3 conv layers
                            # nếu shape mismatch: y = F(x) + W_s·x (1×1 conv shortcut)

# Backward — chain rule qua skip
∂L/∂x = ∂L/∂y · ∂y/∂x
      = ∂L/∂y · (∂F/∂x + I)     # I = identity matrix từ skip
      = ∂L/∂y · ∂F/∂x + ∂L/∂y   # gradient KHÔNG mất qua identity path

# Với deep ResNet 152 layers, gradient tại layer 1:
∂L/∂x_1 = ∂L/∂x_152 · Π (I + ∂F_l/∂x_l)
# Ngay cả khi ∂F_l/∂x_l ≈ 0 (vanish), gradient vẫn = ∂L/∂x_152 qua I
# → Deep network trainable

Ý nghĩa biến: F = residual mapping (small correction); I = identity; W_s = projection shortcut khi H, W, C thay đổi (stride>1 hoặc channel mismatch).

Same idea in Transformer

Transformer block cũng có 2 residual: x + attention(LN(x)) và x + FFN(LN(x)). Copy-paste concept từ ResNet 2015.

4. Squeeze-and-Excitation (SE) — "channel attention" trước cả khi Transformer phổ biến attention

💡 Analogy

Conv layer bình thường tạo ra C feature map (channel) — VD 1 channel bắt "cạnh dọc", 1 channel bắt "màu đỏ", 1 channel bắt "kết cấu lông"... Vấn đề: mọi channel được CỘNG/GHÉP với TRỌNG SỐ NGANG NHAU cho layer sau, dù với 1 ảnh CỤ THỂ, channel "màu đỏ" có thể quan trọng hơn hẳn channel "kết cấu lông" (VD ảnh con cáo — màu đỏ rất informative, kết cấu lông ít phân biệt hơn). Squeeze-and-Excitation (SE, Hu et al. 2018) giống 1 "ban giám khảo" nhìn qua TOÀN BỘ feature map 1 lượt, chấm điểm xem channel nào đang hữu ích cho ẢNH NÀY, rồi NHÂN LẠI mỗi channel với điểm số đó trước khi đưa cho layer sau — channel quan trọng được khuếch đại, channel ít quan trọng bị giảm nhẹ.

Vấn đề cụ thể: convolution xử lý thông tin CỤC BỘ (local) — 1 kernel 3×3 chỉ nhìn thấy 1 vùng nhỏ trong không gian VÀ chỉ 1 channel tại 1 thời điểm khi tính output cho channel đó (dù kết hợp nhiều input channel, nó vẫn không có bước nào "so sánh TOÀN CỤC channel nào đang quan trọng hơn channel nào cho cả bức ảnh"). SE thêm đúng bước này — 1 bước "nhìn toàn cục rồi tái cân bằng channel" — mà không cần đổi kiến trúc conv nền tảng.

# Bước 1 — SQUEEZE: nén mỗi channel (H×W) thành 1 con số DUY NHẤT (thống kê toàn cục)
z_c = GlobalAvgPool(feature_map_c)   # trung bình toàn bộ H×W của channel c → 1 số
# Input (C, H, W) → z shape (C,)      # "nén" hết thông tin không gian, chỉ giữ lại
                                      # "channel c trung bình sáng/mạnh cỡ nào"

# Bước 2 — EXCITATION: học 1 hàm nhỏ (2 lớp FC) map z → điểm attention mỗi channel
s = σ( W2 · ReLU( W1 · z ) )   # W1: (C, C/r), W2: (C/r, C), r = reduction ratio (thường 16)
                                # ReLU ở giữa (bottleneck) → non-linear, giảm params
                                # σ = sigmoid → mỗi s_c ∈ (0,1), như 1 "công tắc mềm" per-channel

# Bước 3 — SCALE: nhân lại feature map gốc với điểm attention (broadcast theo H,W)
output_c = s_c · feature_map_c   # channel s_c cao → giữ nguyên/khuếch đại
                                  # channel s_c thấp → giảm nhẹ, không loại bỏ hoàn toàn

Ví dụ số cụ thể: giả sử C=4 channel, sau Squeeze có z=[0.8, 0.1, 0.6, 0.2] (channel 1 "màu đỏ" trung bình cao, channel 2 "kết cấu lông" trung bình thấp cho ẢNH NÀY). Excitation học ra s=[0.9, 0.2, 0.7, 0.3] (giả định, sau khi qua FC+sigmoid) → Scale: channel 1 giữ 90% cường độ, channel 2 chỉ giữ 20% — layer sau nhận feature map đã được "ưu tiên hoá" theo đúng ảnh đang xử lý, không phải trọng số cố định học 1 lần cho MỌI ảnh.

⚠️ Chỗ dễ nhầm nhất: SE KHÔNG phải spatial attention (không chọn VÙNG nào trong ảnh quan trọng, như attention trong Transformer chọn TOKEN nào quan trọng) — SE chỉ hoạt động trên trục CHANNEL, giữ nguyên toàn bộ chiều không gian (H, W). Đây là lý do SE được gọi "channel attention", khác hẳn "spatial attention" (VD CBAM — Convolutional Block Attention Module — kết hợp CẢ 2 loại) hay self-attention trong Transformer (hoạt động trên trục vị trí/token, xem L3.5 kế tiếp).

Insight: SE là ví dụ sớm (2017-2018, trước khi Transformer phổ biến rộng trong vision ~2020) của ý tưởng "để model tự quyết định thông tin nào quan trọng hơn, thay vì coi mọi thứ ngang hàng" — chính tinh thần đó sau này trở thành nền tảng của attention trong Transformer, chỉ khác trục áp dụng (channel vs token). SE-ResNet-50 (thêm SE block vào ResNet-50) đạt độ chính xác gần bằng ResNet-101 nhưng chi phí compute gần với ResNet-50 — "gần như miễn phí" về compute, đây là lý do SE block trở thành 1 module chuẩn được chèn vào rất nhiều kiến trúc sau đó (SENet thắng ILSVRC 2017 classification track).

📖 Mở rộng: rất nhiều kiến trúc hiện đại "thừa hưởng" ý tưởng SE mà không gọi thẳng tên nó — EfficientNet (mục 1 bảng cheat map ở trên) dùng SE block trong mỗi MBConv block; các Vision Transformer hybrid đôi khi chèn SE-style channel gating giữa các block attention để bổ sung tín hiệu channel-wise mà self-attention thuần không nắm bắt tốt (self-attention mạnh về quan hệ giữa VỊ TRÍ, không tự nhiên mạnh về tái cân bằng CHANNEL).

5. 1D CNN cho time-series

Alternative to LSTM cho sequence:

class Chomp1d(nn.Module):
    # Cắt bỏ phần dư bên PHẢI sau khi pad — đây là điểm bắt buộc để
    # giữ tính CAUSAL (output tại vị trí t chỉ phụ thuộc input <= t)
    def __init__(self, chomp_size):
        super().__init__()
        self.chomp_size = chomp_size
    def forward(self, x):
        return x[:, :, :-self.chomp_size] if self.chomp_size > 0 else x

class TCN(nn.Module):   # Temporal Convolutional Network (Bai et al. 2018)
    def __init__(self, in_ch, hidden_ch=64, kernel=3, layers=6):
        super().__init__()
        blocks = []
        for i in range(layers):
            dilation = 2**i   # 1, 2, 4, 8, 16, 32 — receptive field grows fast
            pad = (kernel - 1) * dilation   # pad TOÀN BỘ vào bên TRÁI, không chia đôi
            blocks.append(nn.Conv1d(
                in_ch if i==0 else hidden_ch,
                hidden_ch,
                kernel_size=kernel,
                padding=pad,        # PyTorch Conv1d chỉ nhận pad đối xứng 2 bên...
                dilation=dilation,
            ))
            blocks.append(Chomp1d(pad))   # ...nên phải chomp bỏ phần dư bên PHẢI
                                            # sau conv để chỉ còn causal padding bên trái
            blocks.append(nn.ReLU())
        self.net = nn.Sequential(*blocks)
        self.out = nn.Linear(hidden_ch, 1)

Hình dung trực tiếp — pad đối xứng (SAI) vs pad-trái-rồi-chomp (ĐÚNG), ví dụ kernel=3, dilation=1 (pad = (kernel-1)·dilation = 2), input 5 phần tử [x0..x4]:

SAI — pad chia đôi 2 bên (1 mỗi bên), "same" padding kiểu thường:
  padded: [0, x0, x1, x2, x3, x4, 0]
  output[2] (ứng vị trí x2) = conv([x1, x2, x3])
                                          ↑
                            x3 là TƯƠNG LAI so với x2 → leak look-ahead

ĐÚNG — pad=2 CẢ 2 bên (bắt buộc vì Conv1d chỉ nhận pad đối xứng), rồi Chomp
cắt 2 phần tử THỪA ở bên PHẢI sau conv → hiệu ứng ròng = chỉ còn ngữ cảnh bên trái:
  padded (trước conv): [0, 0, x0, x1, x2, x3, x4, 0, 0]
  conv ra 7 phần tử (dài hơn input 2) → Chomp bỏ 2 phần tử cuối → còn lại đúng 5:
    output[0] = conv([0, 0, x0])       → chỉ thấy x0
    output[1] = conv([0, x0, x1])      → x0, x1
    output[2] = conv([x0, x1, x2])     → x0, x1, x2   (KHÔNG có x3 → không leak)
    output[3] = conv([x1, x2, x3])
    output[4] = conv([x2, x3, x4])

Vì sao Chomp bắt buộc: padding=(kernel-1)*dilation//2 (chia đôi, đối xứng 2 bên) — cách viết tưởng gọn nhưng SAI cho time-series forecasting: output tại vị trí t khi đó cũng "nhìn thấy" input ở tương lai (t+1, t+2...) nằm trong receptive field, tức leak look-ahead y hệt lỗi feature leak đã học ở L2_4_timeseries_cv.html. Cách đúng: pad toàn bộ (kernel-1)*dilation vào bên TRÁI, rồi Chomp cắt bỏ phần dư bên phải sau conv — đảm bảo output[t] chỉ phụ thuộc input[0..t]. Đây chính là lý do tên gọi "Causal Convolution" trong paper gốc.

Dilated conv: receptive field expand exponentially → capture long-range pattern với few layers. TCN thường match LSTM performance + train nhanh hơn (parallelizable) — nhưng chỉ khi implement đúng causal padding như trên, nếu không sẽ leak tương lai và không dùng được cho forecasting thật.

Cách CNN 1D "nhìn" chứng khoán (tóm tắt lại TCN ở mục 5)

# Input: 60 ngày close price [c_1, c_2, ..., c_60]
# CNN 1D với kernel size 5:

Layer 1: kernel 5 quét qua sequence
  Position 1: nhìn [c_1..c_5] → feature "5-day trend at day 5"
  Position 2: nhìn [c_2..c_6] → feature "5-day trend at day 6"
  ...
Weight sharing: cùng 1 kernel dùng cho mọi position (invariance)

Layer 2: pooling giảm resolution
Layer 3: kernel 5 lớn hơn effective receptive field 25 days
Layer 4: fully connected → prediction

Ưu: nhanh, ít params, tận dụng translation invariance
Nhược: chỉ thấy local patterns (last N days), không capture regime shift dài hạn

Cách RNN "nhìn" chứng khoán

# Input: 60 ngày. Đọc tuần tự.

t=1: h_1 = f(0, c_1)          # nhớ ngày 1
t=2: h_2 = f(h_1, c_2)        # nhớ ngày 1-2
t=3: h_3 = f(h_2, c_3)        # nhớ ngày 1-3
...
t=60: h_60 = f(h_59, c_60)    # nhớ ngày 1-60 (nhưng ngày 1 đã fade)

Prediction: FC(h_60)

Vấn đề: vanishing gradient. Ngày 1 chỉ chiếm 0.995^59 ≈ 74% hidden state
LSTM cải thiện bằng cell state + forget gate → nhớ được 100-200 days
Vẫn không parallelize được, train chậm 20-100× so CNN

Cách Transformer "nhìn" chứng khoán

# Input: 60 ngày [c_1..c_60]

Attention matrix (60×60):
  Cell [i, j] = độ liên quan của ngày i với ngày j
  VD: attention[60, 5] cao nghĩa là hôm nay (day 60) liên quan strong đến day 5

Model có thể học:
  - "Nếu ngày 5 là breakout, thường ngày 60 sẽ pullback" (long-range)
  - "Nếu 3 ngày gần nhau volume tăng, likely trend change" (local pattern)
  - Cả 2 đồng thời qua multi-head attention

Ưu: capture cả local + long-range
Nhược: O(60²) = 3600 attention weights → memory hungry với sequence dài
       Cần nhiều data để tránh overfit

Vì sao XGBoost thắng NN cho V18?

  1. Data quantity: 1250 samples/ticker. NN cần 5-10× hơn để không overfit. XGBoost với tree regularization + early stopping work với data nhỏ.
  2. Tabular features: 88 features đã pre-engineered (RSI, MACD,...). NN mạnh khi tự học representations từ raw data. Với tabular pre-engineered, tree win.
  3. Interpretability: SHAP explain per-prediction rõ ràng. NN attention nhìn ok nhưng khó giải thích cho trader non-tech.
  4. Missing values: XGBoost native handle. NN cần impute cẩn thận.
  5. Speed: XGBoost train 3 phút/ticker × 82 tickers × 3 horizons = 12 giờ. NN 25 phút/ticker × 82 × 3 = 100+ giờ. Không justify khi accuracy tương tự.

2D CNN cho vision — vì sao thắng MLP tuyệt đối?

# MLP xử lý ảnh 224×224×3:
# Input flatten: 224 × 224 × 3 = 150,528 features
# Hidden 1000 neurons: 150,528 × 1000 = 150M params
# → Overfit khủng khiếp

# CNN thay MLP:
# Conv 3×3 với 64 filters: 3 × 3 × 3 × 64 = 1,728 params
# Kernel share weights across all positions → 87,000× ít params
# Locality inductive bias: pixel gần nhau liên quan
# Translation invariance: mèo ở góc trái ~ mèo ở góc phải
# → CNN win ImageNet 2012, thắp lửa deep learning

INSIGHT: Architecture với inductive bias phù hợp task = win.
         Không có "1 architecture universal" — mỗi task cần architecture phù hợp.

🐛 Common bugs / gotchas — CNN
  1. Sai axis khi feed Conv1D: PyTorch nn.Conv1d mong (N, C, L), không phải (N, L, C). Feed sai → shape "correct" nhưng convolve sai chiều.
  2. Padding không tương xứng khi kernel chẵn: K=4, "same" padding không tồn tại chính xác. Dùng K lẻ (3, 5, 7).
  3. Quên BatchNorm running stats khi transfer learning: freeze conv nhưng BN vẫn update EMA → phân bố predict shift. Set bn.eval() hoặc model.apply(freeze_bn).
  4. ResNet shortcut mismatch shape: khi F(x) downsample (stride=2) mà skip vẫn = x → RuntimeError. Fix: 1×1 conv stride=2 trên skip.
  5. Global Average Pool + flatten thứ tự sai: GAP đã reduce spatial → không cần flatten thêm; nếu flatten trước GAP → chiều sai.
  6. Dilated conv effective RF tính sai: RF = 1 + Σ (K-1)·d_l. Quên factor d → mismatch receptive field.
  7. Data augmentation áp dụng cho val set: chỉ train transform; val chỉ resize+normalize. Nếu random crop val → accuracy fluctuate.
  8. Padding='same' trong PyTorch với stride>1: chỉ hỗ trợ từ PyTorch 1.9+, và không cho phép stride≠1. Compute manual padding.

✅ QA Gate + Interview Q&A

1. Conv kernel 3×3, stride 2, padding 1, input 224×224. Output size?

Out = (224 - 3 + 2·1)/2 + 1 = 112. Output 112×112.

2. Vì sao ResNet solve vanishing gradient?

Skip connection cho gradient path direct qua layer. y = x + F(x) → dy/dx = 1 + dF/dx. Gradient không vanish qua identity path. Layer chỉ học F (residual) — dễ hơn.

3. Dilated convolution làm gì?

Insert holes between kernel elements → receptive field expand không tăng params. Dilation d=2, kernel 3 → thấy 5 positions (indices 0, 2, 4). Layered dilated: RF exponential.

4. ViT beat CNN chỉ khi data > bao nhiêu?

~10M images (JFT-300M scale). Below đó, CNN win. Với ImageNet-1k (1.3M), CNN vẫn competitive. Chinchilla scaling apply.

5. Cho V18 (79 handcrafted features, 1250 samples/ticker), CNN có win XGBoost?

Không. Features tabular đã encoded, không có spatial structure. CNN inductive bias không applicable. Empirically XGBoost dominant cho tabular với size này.

6. [Interview] Params của conv 3×3, C_in=64, C_out=128 là bao nhiêu? So với FC input 224×224×64 → 128?

Conv: 3·3·64·128 + 128 = 73,856. FC: 224·224·64·128 + 128 = 411,041,920 (411M). Ratio 5566×. Đây là why CNN scale được cho ảnh — weight sharing + local receptive.

7. [Interview] Bottleneck block ResNet-50 (1×1→3×3→1×1) tiết kiệm params thế nào so với 2 conv 3×3?

Basic block (ResNet-34): 2× (3·3·256·256) = 1.18M params. Bottleneck: 1·1·256·64 + 3·3·64·64 + 1·1·64·256 = 16k + 37k + 16k = 69k params. Tiết kiệm 17×. 1×1 conv giảm channel (256→64) rồi conv 3×3 rẻ, rồi 1×1 restore. Cho phép ResNet-152 khả thi.

8. [Interview] Vì sao dilated conv thay stride-2 conv cho semantic segmentation?

Stride>1 giảm resolution → mất per-pixel info, không segment được. Dilated giữ resolution nhưng tăng RF exponential (d=1,2,4,8 → RF=3,5,9,17...). DeepLab dùng atrous conv giữ output stride 8-16 thay 32 như classification network.

9. [Interview] Depthwise separable convolution (MobileNet) tiết kiệm bao nhiêu compute?

Standard conv K×K, C_in→C_out: cost = K²·C_in·C_out·H·W. Depthwise separable = depthwise (K×K per channel) + pointwise (1×1, C_in→C_out): cost = K²·C_in·H·W + C_in·C_out·H·W. Ratio = 1/C_out + 1/K². Với K=3, C_out=256: 1/256 + 1/9 ≈ 0.115 → 8-9× rẻ hơn. Đây là core của MobileNet, EfficientNet, ConvNeXt.
