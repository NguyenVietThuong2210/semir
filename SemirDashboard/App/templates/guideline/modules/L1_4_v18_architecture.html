1.4 · Kiến trúc 2-tầng V18 (Direction gate + 3-class)

Vì sao V18 chia bài toán thành 2 stage thay vì train thẳng 3-class. Case study kinh điển của senior ML system design.

Level 1 · Foundations · ~30 phút

🎯 Learning objectives

  • Giải thích vì sao 3-class direct fail trên VN market
  • Vẽ được 2-stage pipeline: Direction gate → 3-class refined
  • Đọc + hiểu train_v18_unified.py::train_2stage_multi_seed()
  • Trả lời: bao lâu inference 2-stage vs 3-class? Trade-off?
💡 Vì sao V18 tách 2 tầng?

Bác sĩ chẩn đoán: Bệnh nhân đến, bác sĩ giỏi làm 2 bước:
Bước 1 (direction gate): "Có bệnh không?" (Có/Không)
Bước 2 (3-class): "Nếu có, loại gì?" (cảm cúm / cúm mùa / covid).
Bác sĩ tồi làm 1 bước 3-class → dễ nhầm cảm cúm với covid vì overlap symptom.

V18 architecture: Stage 1 dự đoán "có move đáng kể không?" (UP hoặc DOWN vs FLAT). Stage 2 chỉ khi Stage 1 nói "có move" → dự đoán UP hay DOWN. Kết quả: accuracy cao hơn ~5% so với 3-class trực tiếp.

1. Vấn đề với 3-class trực tiếp

Naive approach: train XGBoost 3-class UP/DOWN/FLAT với 79 features. Kết quả thực tế trên VN market:

Train:       accuracy 68%, F1 macro 0.62
Test (OOF):  accuracy 51%, F1 macro 0.35
             ├─ UP recall:   45%
             ├─ DOWN recall: 42%
             └─ FLAT recall: 78%  ← model dự đoán mọi thứ FLAT (class imbalance)

Root cause: FLAT chiếm 40-50% samples (giá dao động < threshold 0.5% khá phổ biến). Model học "khi không chắc, guess FLAT" — precision UP/DOWN thấp → trader không actionable.

2. 2-stage architecture (V18)

Stage 1 — Direction gate (XGBoost binary, 79 features)
  Label: |return T+h| > threshold ⇒ 1 ("có move đáng kể không?")
  Output: p_directional ∈ [0, 1]
        │
        ▼
  p_directional > gate?   (gate thường 0.51-0.68)
        │
   ┌────┴─────┐
   │ YES      │ NO
   ▼          ▼
Stage 2: 3-class          Return FLAT
XGBoost + LightGBM        conf = 0
ensemble → Output:
UP/DOWN prob + FLAT

Vì sao work tốt hơn?

  1. Stage 1 học discriminative signal: "khi nào có edge?" (binary dễ học hơn 3-class imbalanced)
  2. Stage 2 chỉ thấy samples đáng dự đoán: train trên subset (directional), UP/DOWN balance hơn (skip FLAT majority)
  3. Gate control precision/recall tradeoff: gate cao → fewer trades nhưng higher accuracy
  4. Calibration tách biệt: cal1 cho gate, cal2 cho UP/DOWN — mỗi cái tối ưu riêng
🔍 So sánh 1-stage vs 2-stage V18 — con số + FPT (đọc SAU khi đã hiểu 2-stage architecture ở mục 2)

Giờ ta đã hiểu 2-stage architecture. Đây là compare cụ thể với 1-stage naive để thấy 2-stage lợi ở đâu.

Cách 1 — 1-stage 3-class (naive)

# Model: XGBoost predict trực tiếp UP/DOWN/FLAT
# Input: 88 features, Loss: cross-entropy 3-class
# Training: 1250 samples FPT, labels [0.42, 0.38, 0.20]

# Kết quả CV V18-naive:
FPT t1: cv=53%   ← weak
FPT t3: cv=51%
FPT t5: cv=49%

Vấn đề: 3-class overlap nhiều — "up nhẹ 0.3%" vs "flat 0.0%" gần identical features → confuse.

Cách 2 — 2-stage (V18 chuẩn)

# Stage 1: Direction gate binary MOVE/FLAT
# Stage 2: 3-class UP/DOWN/FLAT (chỉ chạy nếu MOVE)

# Inference:
# 1. Stage 1 → 65% chắc chắn MOVE
# 2. Nếu MOVE prob > 0.5:
#    2a. Stage 2 → 70% UP
#    2b. Final: UP với confidence 0.65 × 0.70 = 45.5%
# 3. Nếu FLAT → skip Stage 2

# Kết quả CV V18 2-stage:
FPT t1: cv=61%   ← +8% vs naive
FPT t3: cv=60%
FPT t5: cv=58%

5 lý do 2-stage TỐT hơn 8%

Lý doGiải thích chi tiết
1. Task đơn giản hơnStage 1 chỉ cần "có breakout không". Stage 2 chỉ cần "up hay down" (đã lọc flat). Mỗi stage ít features hơn để giải quyết.
2. Loại ambiguous samples3-class naive: FLAT samples (return ~0%) confuse UP/DOWN. Stage 1 lọc bỏ chúng khỏi Stage 2.
3. Class balanceOriginal UP/DOWN/FLAT: 42/38/20 imbalanced. Stage 2 sau lọc: UP/DOWN 52/48 balanced!
4. Threshold tunableStage 1 threshold 0.5 → 0.7 để "chỉ hành động khi RẤT chắc chắn". Kiểm soát precision/recall.
5. ExplainabilityStage 1 FLAT → skip Stage 2 → clean "hôm nay không có edge". Naive luôn force output 1 class.

Analogy đời thực — bác sĩ chẩn đoán

Bác sĩ tệ (1-stage): Chẩn đoán ngay "cảm cúm / cúm mùa / covid" — overlap symptoms → sai 40%.

Bác sĩ giỏi (2-stage): Stage 1 "có bệnh không?" → nếu không, về nhà. Stage 2 "loại nào?" với focused test. Accuracy 85%.

Khi 2-stage KHÔNG lợi

  • Class balanced tự nhiên (33/33/33) — 1-stage đủ
  • 3 class hoàn toàn distinct (dog/cat/car) — không confuse
  • Data ít (<500 samples) — Stage 2 chỉ còn 200 → underfitting

Best practice design multi-stage

  1. Nghĩ "sub-task nào dễ hơn task tổng"
  2. Kiểm tra class overlap — cao → gate/filter trước
  3. Class balance sau lọc phải cải thiện
  4. Threshold tunable — trade-off precision/recall
  5. Failure mode clear — Stage 1 fail đừng blind trust Stage 2

3. Code walkthrough

# Simplified from backend/train_v18_unified.py

def train_2stage_multi_seed(df_feat, ticker, feat_names, horizon):
    # ── Prepare labels ──
    ret = df_feat['close'].shift(-horizon) / df_feat['close'] - 1
    label_threshold = 0.005  # 0.5%
    y1 = (ret.abs() > label_threshold).astype(int)   # directional
    y2 = np.where(ret > label_threshold, 2,          # UP
             np.where(ret < -label_threshold, 0,     # DOWN
                     1))                              # FLAT

    # ── Stage 1: Directional binary ──
    X = df_feat[feat_names].values
    scaler = StandardScaler().fit(X)
    Xs = scaler.transform(X)

    clf1 = XGBClassifier(n_estimators=500, max_depth=6, ...)
    clf1.fit(Xs, y1, sample_weight=sample_weights)

    # Calibrate stage 1
    cal1 = CalibratedClassifierCV(clf1, method='platt', cv='prefit')
    cal1.fit(Xs_val, y1_val)

    # Gate threshold from val skill
    p1_val = cal1.predict_proba(Xs_val)[:, 1]
    gate = tune_gate_threshold(p1_val, y1_val)  # e.g., 0.55

    # ── Stage 2: 3-class trên directional subset ──
    directional_mask = cal1.predict_proba(Xs)[:, 1] > gate
    Xs_dir = Xs[directional_mask]
    y2_dir = y2[directional_mask]

    clf2_xgb = XGBClassifier(...).fit(Xs_dir, y2_dir)
    clf2_lgbm = LGBMClassifier(...).fit(Xs_dir, y2_dir)

    # Multi-seed ensemble: 3 seeds → average predictions
    # Cross-validation với gap để tránh leak
    # Isotonic calibration cho probability output
    # (Platt/Isotonic/ECE = kỹ thuật + metric hiệu chỉnh xác suất, đào sâu ở L1.6 — Calibration.
    #  Ở đây chỉ cần biết: bước này sửa lại xác suất model output cho "đáng tin" hơn, VD khi
    #  model nói "70% chắc" thì thực tế đúng ~70% lần, không phải 90% hay 50%.)

    return {
        'scaler': scaler, 'clf1': clf1, 'cal1': cal1,
        'clf2_xgb': clf2_xgb, 'clf2_lgbm': clf2_lgbm,
        'cal2_iso': cal2_iso, 'dir_conf_gate': gate,
        'feature_names': feat_names,
        'cv_accuracy_mean': ...,
        ...
    }

Design principle: cascade classifier

Pattern 2-stage này gọi là cascade classifier — cực phổ biến ở object detection (Viola-Jones face detector 2001), fraud detection, medical screening. Idea: fast reject majority → deep analyze minority.

✅ QA Gate

1. Vì sao direct 3-class fail? Bằng chứng gì?

Class imbalance: FLAT 40-50% samples. Model học "guess FLAT khi không chắc". Precision UP/DOWN thấp (~55%). Evidence: F1 macro drop từ train 0.62 → test 0.35.

2. Gate threshold cao (0.68) vs thấp (0.51). Trade-off?

Cao: fewer trades (recall thấp) nhưng precision cao (fewer false BUY). Thấp: nhiều tín hiệu (recall cao) nhưng nhiều false alarms. Chọn dựa PnL curve + risk tolerance.

3. Sample weights dùng để làm gì trong stage 1?

3 loại: (1) Class balance — inverse-freq weight, (2) Recency decay — half-life 200 ngày, exp(-t/tau), (3) Label clarity — weight cao cho samples |return| xa threshold (rõ ràng).

4. Ensemble stage 2 XGBoost + LightGBM. Vì sao dùng cả 2?

Diversity → ensemble stronger. XGBoost level-wise + LightGBM leaf-wise → khác nhau về decision boundary. Blend weight tune bằng validation (V18 blend_a ~0.8 XGB, 0.2 LGBM).

5. Cascade classifier khác one-vs-rest thế nào?

Cascade: sequential — stage 1 filter, stage 2 mới chạy. OvR: parallel — train n binary classifiers cho n classes, argmax. Cascade tiết kiệm compute (skip stage 2 nếu gate reject), OvR đơn giản hơn nhưng chậm hơn cho inference.

📖 Vì đâu có công thức final_confidence = p_gate × p_class?

Câu hỏi: Vì sao khi combine 2-stage output, ta multiply xác suất chứ không add?

Bước 1 — Rule chain của xác suất: P(A và B) = P(A) × P(B|A). Ở cascade:
• A = "có move đáng kể" (stage 1)
• B = "move đó là UP" (stage 2, conditional on A)

Bước 2 — Áp dụng:

P(UP) = P(move) × P(UP | move)
      = p_gate  × p_class_up

VD: p_gate = 0.65, p_class_up = 0.70 → P(UP) = 0.455. Không phải 0.65 hoặc 0.70 riêng lẻ, mà giao của 2 event.

Intuition: Cascade "amplify skepticism". Nếu stage 1 chỉ 65% chắc có move + stage 2 chỉ 70% chắc UP, tổng chỉ 45.5% — đúng với reality "2 điều bất định giao nhau đều bất định gấp bội".

Sai lầm phổ biến: Report p_class_up = 0.70 làm "confidence" mà bỏ qua p_gate → overconfident. V18 báo cáo composite = tích, đúng theo xác suất.

❌ Sai lầm thường gặp vs ✅ Thực tế
  • ❌ "2-stage phức tạp hơn, chắc chắn tốt hơn" → ✅ Chỉ tốt nếu class overlap + imbalanced. Class balanced tự nhiên → 1-stage đủ.
  • ❌ "Gate cao 0.9 = model chỉ trade signal chắc chắn = an toàn" → ✅ Gate quá cao = quá ít signal + recall thấp + có thể miss trend chính. Trade-off precision/recall phải backtest.
  • ❌ "Calibrate stage 1 và stage 2 riêng biệt gây 2× ECE" → ✅ Ngược lại. Mỗi cal1/cal2 fix miscalibration của stage đó → composite calibrated tốt hơn 1-stage raw.

6. 🎓 Interview-style Q&A

Q1: "Explain cascade classifier trong 30 giây."

Model answer: "Chia bài toán khó thành chuỗi sub-tasks dễ, mỗi stage lọc bớt samples. Stage 1 fast + broad reject (VD 'có face không?'); stage sau deep analysis chỉ trên positive. Ưu: compute tiết kiệm (skip stage 2 nếu stage 1 reject), accuracy cao hơn (mỗi stage focus 1 sub-task đơn giản). Ví dụ kinh điển: Viola-Jones face detector, V18 UP/DOWN prediction, fraud detection."

Q2: "Bạn thấy composite confidence = 0.45 nhưng model bảo p_class_up = 0.85. Điều gì đang xảy ra?"

Model answer: "p_gate thấp: 0.45/0.85 = 0.53. Nghĩa là stage 1 chỉ 53% chắc rằng có move đáng kể. Stage 2 confident UP nhưng conditional. Practical: KHÔNG nên trade lớn — signal weak vì stage 1 uncertain. Sizing phải theo composite (0.45), không theo p_class_up (0.85)."

Q3: "Gate threshold nên tune thế nào?"

Model answer: "Tune trên val set, không phải fix 0.5. Compute expected PnL curve: cho mỗi gate threshold ∈ [0.5, 0.9], simulate signal → PnL sau fees. Chọn gate tại peak PnL (thường 0.55-0.68). V18 dùng skill score peak: gate maximize accuracy − baseline. Cross-validate stability qua 5 folds — nếu peak dịch quá nhiều (variance cao) → gate không robust, tăng regularization stage 1."

Q4: "Data ít (500 samples/ticker). Vẫn dùng 2-stage?"

Model answer: "Cẩn thận. Sau gate filter (65%), stage 2 chỉ còn 325 samples → mỗi class ~110 → tree khó learn. Alternatives: (1) Fallback 1-stage nếu < 800 samples. (2) Share features + transfer learning từ blue-chip pool. (3) Pool ticker theo sector, train chung stage 2. V18 áp dụng: nếu ticker < N threshold → fallback v1 legacy 1-stage."

Q5: "Sao không dùng 3-stage: gate → direction (UP vs DOWN) → magnitude?"

Model answer: "Về lý thuyết ok. Nhưng: (1) Mỗi stage extra tăng error compounding (P = p1×p2×p3, nhỏ dần). (2) Compute + calibration effort 3× nhưng edge biên marginal. (3) Data càng ít khi filter deep → stage 3 khó train. V18 dừng ở 2-stage vì trade-off tốt nhất với dataset size. Nếu có 10M samples/ticker (crypto tick data) → cân nhắc 3-stage."
