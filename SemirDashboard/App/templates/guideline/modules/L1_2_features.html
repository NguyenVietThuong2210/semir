Nấu bún bò Huế: Cùng nồi + thịt, đầu bếp giỏi dùng đủ gia vị (mắm ruốc, sả, ớt, sa tế, huyết heo) → xuất sắc. Đầu bếp chỉ có muối + tiêu → lỏng. Feature = gia vị. Model là nồi, data là thịt.

V18: Chỉ feed close price = đầu bếp thiếu gia vị. Thêm RSI (áp lực mua/bán), MACD (xu hướng), volume z-score (bất thường), foreign flow (dòng tiền ngoại) → model "nếm" thị trường ở nhiều góc.

1. Vì sao features quan trọng?

Nguyên tắc vàng

"Garbage in, garbage out" — model không tự tạo signal. Nếu features không chứa thông tin dự đoán, model không thể học ra dù XGBoost siêu mạnh. Trong công nghiệp ML, feature engineering thường chiếm 70-80% thời gian, model architecture chỉ 20%.

Ví dụ: cho model 3 features {open, high, low, close, volume}. Model chỉ thấy 5 số. Nhưng senior trader "thấy" mỗi ngày:

  • Momentum: giá đang tăng/giảm bao nhiều ngày liên tiếp
  • Volatility regime: biến động mấy tuần gần đây so với trung bình 60 phiên
  • Overbought/oversold: RSI 30/70 threshold
  • Trend structure: giá vs MA20/50/200
  • Support/resistance: giá gần đáy cũ / đỉnh cũ nào

Feature engineering = encode kiến thức chuyên gia thành số cho model.

2. 5 features cốt lõi — implement từ đầu

2.1 Moving Average (MA)

Trung bình cộng của n phiên gần nhất. Đơn giản nhưng cực mạnh — smoothing noise, xác định trend.

def ma(close: pd.Series, window: int) -> pd.Series:
    return close.rolling(window=window, min_periods=window).mean()

# Ví dụ:
ma20 = ma(df['close'], 20)     # MA ngắn hạn
ma50 = ma(df['close'], 50)     # MA trung hạn
ma200 = ma(df['close'], 200)   # MA dài hạn

# Feature derived:
above_ma20 = (df['close'] > ma20).astype(int)   # 1 nếu trên MA20
ma20_pct = (df['close'] - ma20) / ma20 * 100    # khoảng cách %
golden_cross = ((ma20 > ma50) & (ma20.shift(1) <= ma50.shift(1))).astype(int)

2.2 Relative Strength Index (RSI)

Đo động lượng, range 0-100. Giá trị > 70 = quá mua, < 30 = quá bán. Chuẩn 14 phiên.

def rsi(close: pd.Series, window: int = 14) -> pd.Series:
    delta = close.diff()
    gain = delta.where(delta > 0, 0).rolling(window).mean()
    loss = -delta.where(delta < 0, 0).rolling(window).mean()
    rs = gain / loss
    return 100 - (100 / (1 + rs))
📖 Vì đâu có công thức RSI = 100 − 100/(1+RS)?

Câu hỏi: Tại sao RSI có dạng lạ như vậy, không phải chỉ là "trung bình gain / trung bình loss"?

Bước 1 — Ý tưởng thô: J. Welles Wilder (1978) muốn 1 con số đo "sức mua vs sức bán". Idea đầu tiên:

RS = avg_gain / avg_loss    # Relative Strength
  • Nếu chỉ tăng: avg_loss = 0 → RS = ∞. Xấu (không bounded).
  • Nếu chỉ giảm: avg_gain = 0 → RS = 0.
  • Cân bằng: RS = 1.

Bước 2 — Vấn đề: RS không bounded. Trader muốn 1 con số [0, 100] dễ đọc (30 = oversold, 70 = overbought). Cần transform.

Bước 3 — Transform RS → [0, 100]:

RSI = 100 × RS / (1 + RS)     # đưa về [0, 100)
    = 100 × 1 / (1/RS + 1)    # đại số biến đổi
    = 100 − 100 / (1 + RS)    # dạng phổ biến

Verify các case:

  • Chỉ tăng: RS → ∞ → RSI → 100 (quá mua tuyệt đối).
  • Chỉ giảm: RS = 0 → RSI = 0 (quá bán tuyệt đối).
  • Cân bằng: RS = 1 → RSI = 50.

Intuition: RSI = "phần trăm energy đang là mua" trong window 14 phiên. RSI 70 = 70% energy mua vs 30% bán → có thể đảo chiều (mean-revert). Bounded [0,100] là why trader tin dùng.

2.3 MACD (Moving Average Convergence Divergence)

Trend + momentum trong 1 indicator. 3 dòng: MACD, Signal, Histogram.

📖 EMA (Exponential Moving Average) khác MA thường thế nào?

MA (mục 2.1) = trung bình cộng đơn giản — 20 phiên gần nhất trọng số bằng nhau. EMA cho phiên gần đây trọng số cao hơn phiên xa, giảm dần theo cấp số nhân (exponential decay) — giống ý tưởng recency weight ở L1.5.

EMA_t = α · close_t + (1 - α) · EMA_{t-1}     với α = 2/(span+1)

# span=12 → α = 2/13 ≈ 0.154
# Phiên hôm nay đóng góp 15.4%, phiên hôm qua 15.4%×(1-0.154)=13%, ... giảm dần

Ví dụ 3 phiên: close = [10, 11, 12], span=2 (α=2/3=0.667).

EMA_1 = 10                                   (khởi tạo = giá đầu)
EMA_2 = 0.667×11 + 0.333×10 = 10.67
EMA_3 = 0.667×12 + 0.333×10.67 = 11.56       ← lệch gần giá mới nhất (12) hơn MA thường (11)

Vì sao MACD dùng EMA chứ không MA? EMA phản ứng nhanh hơn với thay đổi giá gần đây (không "trễ" như MA cộng đều), phù hợp bắt tín hiệu momentum/trend đổi chiều sớm hơn. Đánh đổi: EMA nhạy noise hơn MA.

def macd(close, fast=12, slow=26, sig=9):
    ema_fast = close.ewm(span=fast).mean()
    ema_slow = close.ewm(span=slow).mean()
    macd_line = ema_fast - ema_slow
    signal_line = macd_line.ewm(span=sig).mean()
    hist = macd_line - signal_line
    return macd_line, signal_line, hist

# Feature: MACD crossover
macd_bullish = ((macd_line > signal_line) & (macd_line.shift(1) <= signal_line.shift(1))).astype(int)

2.4 Bollinger Bands (BB)

MA20 ± 2 standard deviation. Encode volatility + mean-reversion.

def bollinger(close, window=20, std=2):
    mid = close.rolling(window).mean()
    band = close.rolling(window).std() * std
    upper = mid + band
    lower = mid - band
    return mid, upper, lower

# Feature: position trong band (0-1)
bb_position = (close - lower) / (upper - lower)   # 0 = touch lower, 1 = touch upper
📖 Vì đâu có công thức Bollinger Band = MA ± 2σ?

Câu hỏi: Tại sao ± 2 standard deviation, không phải 1σ hay 3σ?

Bước 1 — Nhắc lại thống kê: Nếu data phân phối chuẩn (Gaussian), khoảng [mean − 2σ, mean + 2σ] chứa ~95% quan sát (rule 68-95-99.7).

Bước 2 — Áp dụng vào giá: Nếu giá dao động bình thường quanh MA20, thì ~95% ngày sẽ trong band ± 2σ. Ngày nào chọc thủng band → outlier → tín hiệu mean-reversion (giá sắp về MA) hoặc breakout (trend mạnh).

Bước 3 — Vì sao không phải 3σ? 3σ = 99.7% → chỉ 3 signal / 1000 ngày → quá ít event. 1σ = 68% → 320 signal / 1000 → quá nhiều noise. 2σ là sweet spot: signal đủ hiếm để đáng chú ý, nhưng đủ nhiều để backtest.

Caveat: Giá cổ phiếu KHÔNG thực sự Gaussian (fat tails). Nhưng 2σ vẫn work như heuristic mạnh — Bollinger 1980s đã kiểm chứng qua backtests thực tế.

2.5 Volume ratio

Volume hôm nay so với trung bình → phát hiện anomaly.

📖 Z-score là gì? (dùng liên tục từ đây trở đi)

Định nghĩa: z-score đo "1 giá trị cách trung bình bao nhiêu độ lệch chuẩn (standard deviation)".

z = (x - mean) / std

Ví dụ cụ thể: Volume hôm nay VNM = 5 triệu cổ phiếu. Volume trung bình 20 phiên = 3 triệu, độ lệch chuẩn 20 phiên = 0.8 triệu.

z = (5 - 3) / 0.8 = 2.5

Đọc là "volume hôm nay cao hơn trung bình 2.5 độ lệch chuẩn" — theo phân phối chuẩn, việc này chỉ xảy ra ~0.6% thời gian → bất thường rõ rệt (so sánh Bollinger Band ± 2σ ở mục 2.4, cùng logic).

Vì sao dùng z-score thay vì % raw? Z-score tự động thích nghi theo "độ biến động bình thường" của từng ticker/từng giai đoạn — VNM biến động ít hơn NVL, z-score làm 2 ticker so sánh được trên cùng 1 thang đo (điều mà volume raw hay % raw không làm được).

volume_20d = df['volume'].rolling(20).mean()
vol_ratio = df['volume'] / volume_20d       # 1.5 = volume gấp 1.5× TB20
vol_zscore = (df['volume'] - volume_20d) / df['volume'].rolling(20).std()

3. 🚨 LOOK-AHEAD BIAS — nguy hiểm nhất

Câu hỏi phỏng vấn kinh điển

"Bạn compute RSI của ngày T. Được dùng giá đóng ngày T+1 không?" → KHÔNG. Đó là look-ahead bias. Trong production ngày T, bạn chưa biết giá T+1. Model train với leaking future info sẽ trông có vẻ 90% accurate trên test — nhưng deploy sẽ chết.

Cách check: mọi feature ngày T phải chỉ dùng data ≤ T. Trong pandas:

# ✅ ĐÚNG — chỉ dùng past
rsi_t = rsi(close.iloc[:t+1], 14).iloc[-1]

# ❌ SAI — sử dụng future
rsi_t_bad = rsi(close, 14).iloc[t]   # rolling backward — có thể leak

# Kiểm tra: chạy code với close[t+1:] = NaN, RSI at t phải không đổi

5. Common pitfalls

  • Constant feature: nếu feature giống nhau ở mọi row → 0 importance. V19.5 bị: sector_ohlcv passed nguyên df → cross-sectional constant → 0 importance.
  • High collinearity: MA20 và MA21 correlate 0.99 → 1 trong 2 dư. XGBoost handle được nhưng inflates feature count.
  • Categorical với high cardinality: 1000 sectors → one-hot 1000 columns → sparse, over-fit.
  • Scale không đồng nhất: Tree-based không cần scale, nhưng neural nets cần standardize.

✅ QA Gate

1. Vì sao feature engineering chiếm 80% thời gian ML?

Vì model không tự tạo signal. Feature encode domain knowledge thành số. Model architecture chỉ khai thác signal đã có sẵn.

2. Cho pandas Series close. Viết hàm compute RSI(14) từ đầu (không dùng library).

Xem code section 2.2. Key: delta = close.diff(), gain/loss = separate rolling means, rs = gain/loss, rsi = 100 - 100/(1+rs).

3. Look-ahead bias là gì? Cho ví dụ cụ thể và cách detect.

Dùng info tương lai để build feature quá khứ. VD: compute label bằng close[t+5], nhưng feature dùng shift(-1) sai. Detect: mask future data ra NaN, feature at t phải không đổi.

4. Vì sao XGBoost không cần standardize feature nhưng neural net cần?

Tree split dựa threshold rời rạc, invariant với scale. NN dùng gradient descent — features scale khác nhau → gradient dominant bởi feature scale lớn → training không ổn định.

5. Bạn có feature RSI + MA5 + MA20 + MA50. Bạn thấy MA5 correlate 0.98 với MA20. Có nên drop MA5 không?

Nếu dùng linear model: có (giải quyết multicollinearity). Nếu tree-based: không bắt buộc drop nhưng nên (giảm feature count → tránh overfit, cải thiện SHAP interpretability). V20 Slice 3 drop feature adoption < 30%.

❌ Sai lầm thường gặp vs ✅ Thực tế
  • ❌ "Cứ throw hết indicators vào model, XGBoost tự chọn" → ✅ XGBoost handle multicollinearity nhưng SHAP-based importance sẽ noisy → khó explain. V20 audit prune 43 feature ứng viên xuống 17, drop 26 "dead" → CV bằng nhau nhưng interpret dễ hơn.
  • ❌ "Look-ahead bias chỉ xảy ra với label" → ✅ Cũng xảy ra với feature. VD: rolling.mean() mặc định centered ở pandas cũ = leak. Luôn set closed='left' hoặc dùng .shift(1).
  • ❌ "Standardize features cho tree-based model" → ✅ Vô ích. Tree split theo threshold, invariant với scale. Standardize chỉ cần cho NN/linear/kNN.
  • ❌ "Feature correlation cao = bad" → ✅ Với tree, không quan trọng lắm. Với linear model, thì có (multicollinearity → coefficient bất ổn).

6. 🎓 Interview-style Q&A

Q1: "Bạn implement RSI(14) và deploy. Live prediction lệch hoàn toàn với backtest. Debug?"

Model answer: "3 hypothesis theo priority: (1) Look-ahead bias — check rolling window có touch future data không (test: mask close[t+1:] = NaN, RSI[t] có đổi không). (2) Different formula — Wilder original dùng smoothed moving average (α=1/14), simple rolling mean khác nhau ở tails. (3) Missing values handling — pandas rolling.mean() min_periods default 1 sẽ return giá trị partial → skew đầu series. Fix: min_periods=window."

Q2: "80 features V18, bạn nghi 20 là noise. Cách audit khoa học?"

Model answer: "Multi-signal audit: (1) SHAP mean |value| per feature → drop bottom quartile if < 0.5% total. (2) Permutation importance — shuffle 1 feature, re-eval; nếu accuracy không giảm → noise. (3) Correlation với target trên rolling window — feature nào correlation drift về 0 = concept drift. Combine 3 signal, drop feature fail 2/3. Never drop dựa 1 signal."

Q3: "Vì sao V18 dùng volume_zscore_20 thay vì volume raw?"

Model answer: "Ba lý do: (1) Cross-ticker normalization — VNM volume 1M vs NVL 20M không so sánh được scale; z-score đưa về cùng thang. (2) Regime robust — z-score adapt theo baseline 20 phiên, market-cap-agnostic. (3) Model learn dễ hơn — 'z=+2σ' là universal signal 'bất thường cao', model không cần học per-ticker threshold."

Q4: "Feature engineering tự động (autoML) đang hot. Có nên bỏ manual features?"

Model answer: "No, hybrid. AutoML (Featuretools, TSFresh) good cho generate 1000s candidate features nhưng không có domain sense — sinh nhiều garbage. Best practice: manual domain features (RSI, MFI, sector rotation) làm core → autoML sinh interaction/lag features → SHAP filter. V18 phân tích ~200 candidate, chỉ giữ 79."

Q5: "Định nghĩa nhanh: leak, drift, multicollinearity."

Model answer:
• Leak: feature chứa info tương lai (label peek). Fix: strict causal split + shift.
• Drift: distribution feature/label thay đổi qua thời gian. Fix: monitor + retrain.
• Multicollinearity: 2+ features correlate cao → linear model coefficient bất ổn, tree không sao. Fix: drop redundant, hoặc dùng regularization L1.
