🎓 ML Fundamentals

Q1. Explain machine learning trong 1 câu. EASY
ML là xây dựng thuật toán học "quy luật" từ dữ liệu, thay vì lập trình quy luật thủ công. Tom Mitchell định nghĩa formal: performance tại task T (đo bằng P) cải thiện khi có nhiều experience E.
Evidence
Module L1.1 · ML Intro. Applied V18: T = predict UP/DOWN/FLAT, E = 1250 phiên OHLCV/ticker, P = cross-validated accuracy (60.5%).
Q2. Bias vs Variance — explain và cách detect. MEDIUM
Bias = systematic error (model quá đơn giản, miss pattern). Variance = spread across training sets (model quá phức tạp, nhạy noise). Detect via learning curves: high bias (both train + val low), high variance (train cao, val thấp, gap lớn). Trade-off: reduce one usually increases other. Regularization giảm variance tăng bias, nếu tune tốt beat both.
Evidence
Module L2.1. Ví dụ V19.5: cv +0.61pp trong training nhưng deploy fail — high variance qua feature adoption chưa detect được (V20 Slice 3 SHAP prune fix).
Q3. K-Fold random tại sao không dùng được cho time-series? MEDIUM
K-Fold random shuffle rồi split → test set chứa data từ tương lai (relative to some train samples). Data leak. Model "biết trước" → test score inflate, deploy fail. Fix: TimeSeriesSplit (train quá khứ, val tương lai gần), thêm gap ≥ label horizon để tránh label leak. Purged K-Fold + embargo (De Prado 2018) cho label overlap.
Evidence
Module L2.4. V18 dùng TimeSeriesSplit(n_splits=3, gap=5) trong train_v18_unified.py.
Q4. XGBoost 5 innovations vs GBM classic? MEDIUM
(1) 2nd-order Taylor approximation — dùng cả gradient + Hessian, converge nhanh hơn. (2) L1 + L2 regularization trên leaf weights. (3) Weighted quantile sketch cho fast split proposals. (4) Sparsity-aware — handle missing values natively. (5) Parallel + cache-aware — multi-threading + optimized memory access.
Evidence
Module L1.3. V18/V19.5/V20 all use XGBoost + LightGBM ensemble. Paper: Chen & Guestrin 2016 (KDD).
Q5. Class imbalance — 5 techniques handle? MEDIUM
(1) Class weight (inverse freq). (2) SMOTE oversampling minority (synthetic interpolation). (3) Undersampling majority (throw data). (4) Focal loss (down-weight easy examples). (5) Threshold tuning post-training (optimize F1 hoặc business metric). V18 combine: class weight + 2-stage cascade + gate threshold tuning cho FLAT dominant (50%) problem.
Evidence
Module L2.3. V18 sample weight formula 3 components trong backend/train_v18_unified.py.
Q6. Calibration là gì? Vì sao matter cho trading? MEDIUM
Calibrated model: probability output match actual frequency (P=0.7 → đúng 70% lần). XGBoost by default overconfident. Fix: post-training Platt scaling (sigmoid, small data) hoặc Isotonic regression (flexible, cần >1000 samples). ECE metric đo calibration — target <0.02. Cho trading: uncalibrated confidence → EV compute sai → position size wrong.
Evidence
Module L1.6. V18 dùng Platt cho stage 1 (binary gate), Isotonic cho stage 2 (3-class). ECE audit ở reports/_baselines/v19_5_ece_audit.json.
Q7. Overfitting — 5 fixes ưu tiên. EASY
(1) More data (best if possible). (2) Regularization (L1/L2, dropout, weight decay). (3) Simpler model (giảm depth, layers). (4) Early stopping (dựa val loss). (5) Feature selection (drop noise features). (6) Ensemble (bagging giảm variance). (7) Data augmentation (image, text).
Evidence
Modules L2.1 + L2.2. V20 prune 43→17 features = form of regularization.
Q8. SHAP vs Permutation Importance vs Gain? HARD
Gain (XGBoost native): fast, biased toward high-cardinality features. Permutation: model-agnostic, shuffle 1 feature check accuracy drop — slow but honest. SHAP: game-theoretic, satisfies 3 properties (local accuracy, missingness, consistency) — TreeExplainer fast cho tree models, KernelExplainer O(2^features) infeasible large. SHAP additive: sum(SHAP) + base = prediction exactly.
Evidence
Module L2.5. V20 Slice 3 dùng clf2_xgb.feature_importances_ (gain-based) trên 45 artifacts để prune features với adoption <30%.
Q9. Look-ahead bias — cho ví dụ + cách detect. MEDIUM
Feature at time T dùng info từ T+K (tương lai). Ví dụ: volume.rolling(20).mean() tại row T tính cả row T (window inclusive) — nhẹ leak. Hoặc feature dùng close.shift(-1). Detect: mask future data ra NaN, re-compute features, at time T must be unchanged. Fix: chỉ shift positive, hoặc rolling(20).mean().shift(1) để exclude current.
Evidence
Module L1.2. V19.5 Slice 10 replay caveat: model trained on full history → replay có look-ahead bias, hit rate inflate 5-15pp vs real production.
Q10. Optuna vs Grid search vs Random search — khi nào chọn? MEDIUM
Grid: exponential trials với params. Feasible chỉ khi <5 params, small ranges. Random: constant trials, baseline comparison. Optuna (Bayesian TPE): learn từ trials trước, pick smarter → 50-100 trials thường đủ cho 9+ params. V18 Optuna 50 trials search 9 params (n_estimators, depth, lr, subsample, colsample, alpha, lambda, min_child, gamma) — Grid would need 5^9 = 2M trials.
Evidence
Module L1.5. V18 train_v18_unified.py:415 Optuna objective function.

🧠 Deep Learning

Q11. Vanishing gradient — 3 fixes historical. MEDIUM
Sigmoid/tanh max derivative ~0.25 → deep NN gradient nhân liên tục → về 0. Fixes: (1) ReLU (derivative = 1 khi z>0). (2) Batch/Layer Norm (stabilize distribution activations). (3) Residual connections (gradient path direct qua skip). (4) Better init (Glorot/He). (5) Skip: switch RNN → Transformer với attention direct O(1) connection.
Evidence
Modules L3.1 + L3.5.
Q12. Adam vs SGD momentum — production choice? HARD
Adam: adaptive LR per param via 1st + 2nd moments. Fast convergence, work-out-of-box. Default cho most DL 2015+. But: generalize worse than SGD cho computer vision task (Wilson 2017). SGD + Momentum + long cosine schedule beat Adam cho ImageNet training. AdamW (decoupled weight decay) fix generalization gap — modern Transformer default. Rule: AdamW cho Transformer/LLM, SGD Momentum cho CNN.
Evidence
Module L3.2. LLaMA training uses AdamW + cosine schedule + warmup.
Q13. BatchNorm vs LayerNorm — Transformer chọn cái nào? MEDIUM
LayerNorm. BatchNorm normalize per feature across batch — assumes samples in batch similar. Transformer variable-length sequences + padding → BN statistics contaminated. LayerNorm normalize per sample independent → sequence-length-agnostic. Modern LLMs (LLaMA) use RMSNorm — skip mean subtract, 10-15% faster than LayerNorm, comparable quality.
Evidence
Modules L3.3 + L4.2.
Q14. Attention formula + tại sao chia √d_k? MEDIUM
Attention(Q, K, V) = softmax(Q·K^T / √d_k) · V. Chia √d_k vì d_k lớn (e.g., 64) → dot product magnitude lớn → softmax saturate (derivative ~0) → vanishing gradient. Scale factor giữ variance ~1 → softmax không saturate → gradient healthy. Named "scaled dot-product attention" (Vaswani 2017).
Evidence
Module L4.2. Code implementation PyTorch.
Q15. Multi-Head Attention vs Single-Head — lý do dùng multi? MEDIUM
Multi head học multiple aspects khác nhau (syntactic, semantic, coreference). VD: head 1 học subject-verb agreement, head 2 học pronoun resolution. Concat outputs + project. Empirically better than single head cùng total dim. Cost: same param count nhưng expressiveness cao hơn.
Evidence
Module L4.2. Standard 8-16 heads for base models, 64+ for large.
Q16. Vì sao Transformer parallelize được nhưng RNN không? MEDIUM
RNN: h_t phụ thuộc h_{t-1} → phải compute sequential (mỗi timestep chờ trước xong). Transformer self-attention: mỗi position compute independent — Q, K, V compute parallel cho all positions, sau đó attention matrix parallel. → GPU-friendly, scale với data + compute. Reason chính Transformer thay RNN dominant post-2017.
Evidence
Module L3.5 chronological summary.
Q17. LSTM 3 gates function — describe. EASY
Forget gate (f): control lượng past memory (c_{t-1}) giữ. Input gate (i): control new info admit vào cell. Output gate (o): control lượng cell state (c_t) expose làm hidden state (h_t). Cell state = persistent memory linear flow qua time (gradient không vanish). Hidden state = output for this timestep.
Evidence
Module L3.5. Hochreiter & Schmidhuber 1997.
Q18. Dropout — impl + inference behavior? EASY
Training: mask = (rand > p), output = x * mask / (1-p). "/(1-p)" scale up để E[output] không đổi (inverted dropout). Inference: KHÔNG drop, use full network. Prevents co-adaptation neurons, ensemble effect qua random subnetworks. Typical p: 0.1 for conv/embedding, 0.5 for FC.
Evidence
Modules L2.2 + L3.3.
Q19. CNN win vs Transformer cho image — condition? HARD
CNN inductive bias (locality + translation invariance) advantage khi data limited (< 10M images). ViT beat CNN chỉ khi data ~10M+ (JFT-300M scale). ImageNet-1k (1.3M) CNN vẫn competitive. Cost: CNN faster inference (specialized ops). Modern: ConvNeXt (2022) - CNN redesigned với Transformer insights - match ViT quality. Best-of-both.
Evidence
Module L3.4. Dosovitskiy 2020 ViT paper.
Q20. NN cho V18 (79 features, 1250 samples tabular) — win XGBoost? MEDIUM
Không. Features tabular đã handcrafted, không có spatial/sequence structure. NN inductive bias không applicable. XGBoost dominant cho tabular: handle categorical, missing values native, mixed scales without normalization, interpretability higher. Empirically Kaggle top tabular đều tree-based. NN win khi: data size >100k+, deep semantic structure (text/image/speech).
Evidence
Module L3.1 section 7 comparison table. V18 chose XGBoost đúng đắn.

📚 Large Language Models

Q21. BPE tokenization algorithm — 4 bước. EASY
(1) Init vocab với characters + special tokens. (2) Compute frequency of adjacent character pairs in corpus. (3) Merge most frequent pair → new token in vocab. (4) Repeat until vocab size hits target (e.g., 50k). Tokenize: greedy longest match trong vocab. VN cost cao 2-3× English vì diacritics + tone marks split thành multiple tokens.
Evidence
Module L4.1. Sennrich 2016 BPE for NMT paper.
Q22. Encoder-only vs Decoder-only vs Encoder-Decoder — use case? MEDIUM
Encoder-only (BERT, RoBERTa): bidirectional attention, MLM pretrain. Best cho classification, NER, extraction. Decoder-only (GPT, LLaMA, Claude): causal attention, next-token pretrain. Best cho generation, chat, code — 99% modern LLMs. Encoder-Decoder (T5, BART, mBART, mT5): encoder bidirectional + decoder causal + cross-attention. Best cho translation, summarization.
Evidence
Module L4.2. Decoder-only dominant vì scale better với data + compute.
Q23. Chinchilla scaling law — D/N optimal + implication. HARD
Hoffmann 2022: for optimal compute, D (data tokens) ≈ 20 × N (params). GPT-3 175B × 300B tokens = D/N = 1.7 → under-trained. Chinchilla 70B × 1.4T tokens = D/N = 20 → beat GPT-3. Modern (2024+): D/N > 25 common — over-train smaller model for cheaper inference (LLaMA-2 70B × 2T = 28.6). Trade-off: 1-time train cost vs ongoing inference cost.
Evidence
Module L4.3.
Q24. RLHF 3 stages + purpose. MEDIUM
(1) SFT (Supervised Fine-Tuning): fine-tune on ~10k human demonstrations (prompt→ideal response). Teach follow instructions. (2) Reward Model (RM): train classifier predict human preference từ ~100k pairwise comparisons. Loss: -log σ(r(chosen) - r(rejected)). (3) PPO: RL policy against RM reward, với KL penalty vs SFT to prevent drift. Total: SFT + RM data + PPO training.
Evidence
Module L4.4. Ouyang 2022 InstructGPT paper.
Q25. DPO vs RLHF — simplification? HARD
Rafailov 2023 shows: optimal PPO solution có closed form. Skip explicit RM + PPO stages. DPO loss trực tiếp: -log σ(β · [log(π(chosen|x)/π_ref(chosen|x)) - log(π(rejected|x)/π_ref(rejected|x))]). 2 stages (SFT, DPO) vs RLHF's 3. Only 2 models in memory (policy + ref) vs RLHF's 4. 1 hyperparam (β) vs many PPO hyperparams. Match RLHF quality empirically. Adopted by Zephyr, Tulu, LLaMA-3 chat, Mistral.
Evidence
Module L4.4. Rafailov et al 2023.
Q26. LoRA — init B=0 lý do? Rank choice? MEDIUM
ΔW = B·A. Init B=0 → ΔW = 0 → model start identical to base pretrained. Học từ zero drift → stable training, không catastrophic forgetting. Rank r: 4-8 (0.1% params, small domain shift), 16-32 (0.5%, most tasks — default), 64-128 (2-5%, large domain shift medical/legal). Apply typically to attention Q, V projections. Aggressive: also K, O, FFN.
Evidence
Module L4.5. Hu 2021 LoRA paper.
Q27. KV cache size calculation — LLaMA-70B 4k context batch 8? HARD
Formula: 2 (K + V) × n_layers × n_heads × d_head × seq_len × dtype_bytes × batch. LLaMA-70B: 80 layers × 64 heads × 128 d_head × 2 (K+V) × 4096 tokens × 2 bytes (fp16) × 8 batch = 42 GB. Cần A100 80GB just cho KV cache. Insight: memory hungry. Solutions: PagedAttention (vLLM), grouped-query attention (fewer KV heads), quantized KV cache.
Evidence
Module L4.6.
Q28. Top-P vs Top-K sampling — trade-off? EASY
Top-K: sample từ K probable tokens fixed. Simple, không adaptive. Top-P (nucleus, Holtzman 2019): sample từ smallest set whose cumsum ≥ P. Adaptive size: confident distribution (peak sharp) → small set. Flat distribution → larger set. Empirically top-P (0.9) better cho creative gen. Combine common: top-K + top-P + temperature.
Evidence
Module L4.6. Code example section 1.4.
Q29. Prompt caching Anthropic — cost savings? EASY
Mark stable prefix (system prompt, few-shot) as cacheable. First call: pay full price to write cache. Subsequent calls (within 5-min TTL): cached prefix charged 10% price. Savings: 90% on cached tokens. Real: app với 5000-token system prompt called 100x/hour. Uncached $0.075/call. Cached $0.008/call. 89% cost reduction just for system prompt portion.
Evidence
Module L5.5. Anthropic prompt caching docs.
Q30. Fine-tune vs Prompt engineer vs RAG — chọn cái nào? MEDIUM
Task-specific behavior/style: fine-tune (LoRA cheapest). Fresh factual knowledge: RAG (instant update). Simple prompt customization: prompt engineer (free). Cost: prompt eng cheapest but least powerful; RAG medium (retrieval overhead); fine-tune highest setup nhưng cheaper inference. Update knowledge: prompt eng easy, RAG instant, fine-tune needs retrain. Real: often combine (fine-tune style + RAG fresh data).

Q32. LangGraph vs Autogen — architecture khác gì? HARD
LangGraph: state machine với Python routing (deterministic control plane). Node = agent, edge = transition, state = TypedDict shared. Testable, checkpointable, auditable. AutoGen: peer-to-peer conversational multi-agent. LLM decide next speaker → non-deterministic. Chat history = state. LangGraph better cho production SDLC pipelines (ai_orchestrator uses). AutoGen better cho brainstorming, research.

Q33. Vì sao "dumb control plane" quan trọng cho multi-agent? HARD
Routing bằng Python if/else = deterministic. Same input → same route. Testable với unit test (mock state, check next node). Auditable (log every routing decision với reason). Reproducible bugs. Ngược lại: LLM route → non-deterministic. Same input, different route. Cannot reproduce production bug. Cannot unit test. Anthropic Building Effective Agents recommend deterministic control plane.

(3) Embedding domain mismatch (English model, VN docs) → multilingual embed or fine-tune. (4) Stale data — doc updated but vector DB not synced → incremental indexing. Q40. Paperclip maximizer lesson? HARD
Bostrom 2003 thought experiment: AGI với simple goal "maximize paperclips" consumes Trái Đất, solar system, galaxy. Humanity extinct (atoms convert to paperclips). Lesson: optimal AI following simple goal literally = catastrophe. Even benign goal → tail outcomes disastrous. Cannot rely on "just tell AI what to do". Need complex value alignment. Related: instrumental convergence, corrigibility problem, deceptive alignment.

Q41. Training-serving skew — prevention? MEDIUM
Feature compute differ train vs serve → prediction offset → prod accuracy drop. Common: pandas rolling(20).mean() train vs NumPy convolution serve — subtle differences. Prevention: (1) Shared code path (V18 uses features_v18.py::build_v18_features() for both). (2) Assert test: same input → same features across paths. (3) Feature store (Feast, Tecton) single source. (4) Contract tests trong CI.

Q42. Canary vs Blue-Green vs Shadow deployment. MEDIUM
Blue-Green: instant cut-over LB pointer. Rollback instant. Cost 2× temporary. Best cho monolith stateless. Canary: gradual rollout 1% → 5% → 25% → 100%. Monitor at each stage. Best cho ML models (real-world verify). Shadow: duplicate request offline compare — user chỉ see old model. Zero risk. Best cho architecture change major. V20 uses shadow → canary → blue-green sequence.

💡 Delivery tips
  1. Numbers over adjectives: "60.5% accuracy" not "good accuracy". "30-min rollback" not "quick rollback".
  2. Own it "I": I designed, I traced, I proposed. Give team credit separately.
  3. Show meta-lesson: end story với what you learned + how changed approach.
  4. Be specific: names, dates, exact metrics. Not vague "recently".
