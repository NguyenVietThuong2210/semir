1. What is Machine Learning? 🤖

Machine Learning (ML) is teaching a computer to find patterns in data instead of programming it with explicit rules.

Imagine you want a computer to recognize cats in photos. The old way was writing rules: "if it has whiskers AND pointy ears AND fur, it's a cat." This breaks easily — what about a hairless cat? The ML way is showing the computer 10,000 cat photos and 10,000 non-cat photos and letting it figure out the patterns itself.

The Three Types of ML

1
Supervised
You give the computer answers to learn from. "This photo is a cat, this isn't." — Used for our v18!
2
Unsupervised
Computer finds patterns without labels. "Group these customers however you like."
3
Reinforcement
Computer learns by trial-and-error with rewards. "Win the game and get +1."

Two Sub-Types of Supervised Learning

TypePredictExampleV18 uses?
ClassificationA categoryCat / Dog / Bird✅ YES (UP / DOWN / FLAT)
RegressionA numberHouse price = $250,000❌ No
💡 Key Insight
V18 is a 3-class classification problem. We don't predict "VNM will go up by 2.3% tomorrow" (that would be regression — too hard). We predict "VNM will go UP / stay FLAT / go DOWN" — much easier.

2. The Stock Prediction Problem 📈

Why is stock prediction hard?

  • Tiny signal, huge noise — Most daily moves are random (~90% noise, ~10% signal)
  • Regime changes — Patterns from 2022 don't work in 2026 (interest rates, war, COVID...)
  • You can't see the future — Have to use ONLY past data to predict future
  • Transaction costs eat profits — Vietnamese fees: 0.20-0.55% per round trip
⚠️ Reality Check
There are two ways to measure "accuracy":
  • Directional accuracy (binary UP-vs-DOWN when the model commits): random = 50%, edge starts at ~52%, pros run at 53-55%
  • 3-class accuracy (UP/FLAT/DOWN end-to-end): random = 33%, but majority-class baseline is ~40-45% (because FLAT is common). V18 stores this as cv_accuracy_mean — typical value ~0.60 for VN30
What matters is skill_score: how much above baseline. 0 = no skill, 0.05+ = tradeable.

How V18 Defines the Problem

For every trading day, for every stock, predict ONE of three things:

UP
Rise more than threshold next day
Buy signal — price will likely rise
FLAT
Move within ±threshold
No clear direction — don't trade
DOWN
Fall more than threshold next day
Sell signal — price will likely fall
📐 The Threshold Question
What counts as "UP"? The threshold is per-ticker, ATR-based — set so that roughly 20% of historical daily moves land inside the FLAT zone. Real values from live artifacts:
  • TIS (low volatility): 0.20%
  • VNM (medium): 0.27%
  • PDR (higher volatility): 0.45%
Bounded at floor 0.2% and cap 1.5%, scaled by √horizon for T+3 and T+5.

Three Horizons

We don't just predict tomorrow. We predict 3 future days:

HorizonPredictWeight in final decision
T+1Tomorrow's direction50% (loudest voice)
T+33 days from now30%
T+51 week from now20% (weakest voice)

The 3 horizons "vote" together (weighted) to give the final prediction.

3. Features: How Computers See Stocks 👁️

Computers can't "look at a chart". They need NUMBERS. Each stock on each day becomes a row of ~78 numbers called features.

A doctor doesn't diagnose you by "looking at you". She measures: temperature, blood pressure, heart rate, white blood cell count, etc. Each measurement = 1 feature. Together they describe your health. Same for stocks — RSI, MACD, volume ratio, etc.

Example Feature Explained: RSI

RSI (Relative Strength Index) measures momentum on a 0-100 scale:

  • RSI < 30 = oversold (might bounce up soon)
  • RSI 30-70 = neutral zone
  • RSI > 70 = overbought (might fall soon)

Calculation (simplified):

RS = (average gain over 14 days) / (average loss over 14 days)
RSI = 100 - (100 / (1 + RS))

Why "Cross-Asset" Features?

Vietnamese stocks don't move in isolation. When SP500 crashes overnight, VN-Index typically opens lower. When oil prices spike, GAS and PLX rally. V18 includes:

🚨 Look-Ahead Bias — The Cardinal Sin
You CAN'T use tomorrow's data to predict tomorrow. Every feature must use ONLY information available before the prediction. V18 uses shift(1) on all cross-asset features to ensure we never accidentally peek at the future.

4. The Models: From Trees to XGBoost 🌳

Start Simple: A Decision Tree

A decision tree is just a series of "if-then" questions:

Problem: One Tree is Weak

A single tree memorizes training data but doesn't generalize. Solution: combine MANY trees.

Random Forest = Many Trees Voting

Train 100 trees, each on a slightly different sample of data. Final prediction = majority vote.

Gradient Boosting = Trees that Fix Each Other's Mistakes

Train trees sequentially. Each new tree focuses on examples the previous trees got wrong. This is more powerful than Random Forest for tabular data.

XGBoost = Highly Optimized Gradient Boosting

⚡
Fast
Parallel training, optimized C++ core
🎯
Accurate
Wins most Kaggle competitions on tabular data
🛡️
Regularized
Built-in L1/L2 to prevent overfitting
🪶
Handles missing
No need to impute NaN values

LightGBM = Faster, Slightly Different XGBoost

V18 uses XGBoost + LightGBM together. Each makes different mistakes. Averaging their predictions reduces variance.

✅ Why Trees Beat Neural Networks Here
For TABULAR data with < 10,000 samples per ticker, tree-based models (XGBoost, LightGBM) almost ALWAYS beat neural networks (deep learning). Neural nets need huge datasets. Trees handle missing values, mixed scales, and small datasets gracefully.

5. V18 Architecture: The 2-Stage System 🏗️

The Problem with Direct 3-Class Prediction

If we directly predict UP/DOWN/FLAT, the model gets confused at boundaries:

  • Is +0.29% "FLAT" or "UP"?
  • Is -0.31% "FLAT" or "DOWN"?

The classes blend into each other. Solution: split into 2 questions.

V18's 2-Stage Architecture

Why This is Better

  • Stage 1 is easier — Distinguishing "anything happens" from "nothing happens" is more reliable than 3-way classification
  • Stage 2 sees only clear cases — When Stage 1 says "DIR", Stage 2 doesn't need to worry about FLAT noise
  • Better calibration — Each stage handles its specific imbalance

The "Gate" Concept

After Stage 1, we have a probability like "P(DIR) = 0.62". Do we trust it? The gate is the minimum probability required to predict UP/DOWN. Below the gate → FLAT.

V18 has TWO gate values per ticker:

  1. Artifact gate (dir_conf_gate) — found during training, max F1 subject to precision ≥ 0.72
  2. Production gate (V18_PRODUCTION_GATES) — backtest-tuned override used at inference
TickerArtifact gateProduction gate (live)Why
VNM0.450.66Production tuned conservative — fewer false UP signals
PDR~0.500.43Speculative — accept more signals, filter later by composite
VHM~0.500.64Tends to over-predict FLAT — needs high bar
MSN~0.500.68Macro-driven, high uncertainty

Production gates come from walk-forward backtest convergence (the values in V18_PRODUCTION_GATES dict). Plus runtime boosts: +0.08 for low liquidity, +0.10 in bear regime, +0.05 for recent event.

Multi-Seed Ensemble (Stage 1)

Instead of training 1 Stage 1 model, V18 trains 3 with different random seeds (42, 17, 99). At prediction time, average their probabilities.

Asking 3 doctors instead of 1 reduces the chance of a single doctor's biased opinion ruining your diagnosis. Each tree forest has slightly different "biases" — averaging cancels them out.

6. Training Smart: Sample Weights & Cross-Validation ⚖️

Not All Training Examples Are Equal

V18 applies 3 types of weights to each training row:

1. Class Balance Weights

Problem: 80% of days are FLAT, 10% UP, 10% DOWN. A naive model just predicts FLAT for everything (80% accuracy, 0% usefulness).

Solution: weigh UP and DOWN examples higher so model pays attention to them.

cw = 0.5 / freq_of_class
# If FLAT is 80% of data: cw = 0.625
# If UP is 10% of data:   cw = 5.0

2. Recency Decay (Half-Life ~200 days)

Recent data matters more (market regimes shift). Each row's weight decays exponentially with age:

weight = exp(-ln(2) / half_life * days_ago)
# Row from 200 days ago: weight = 0.5
# Row from 400 days ago: weight = 0.25
# Row from today:        weight = 1.0

3. Label Clarity Weighting

A +0.29% day (FLAT) and +0.31% day (UP) are basically identical — same information, different labels. Don't train hard on boundary cases.

Cross-Validation: Testing Without Cheating

You can't test the model on the same data you trained on (it just memorizes). For time-series, we use TimeSeriesSplit:

Why a Gap?

Labels are based on FUTURE returns. Row at day 100 has label looking at day 101's price. If our train set ends at day 99 and val starts at day 100, they share label information. The 5-day GAP prevents this label leakage.

Optuna: Auto-Tuning Hyperparameters

XGBoost has 10+ knobs (tree depth, learning rate, subsample, etc.). Trying every combo = millions of trainings. Optuna intelligently searches:

  1. Try random combination
  2. Measure CV accuracy
  3. Use Bayesian magic to pick "smart next try"
  4. Repeat 50 times
  5. Return best

V18 runs 50 Optuna trials per Stage 1 model.

7. Calibration: Making Probabilities Honest 🎯

XGBoost says "I'm 80% confident this stock goes UP". Is that actually true?

⚠️ The Calibration Problem
A model can be ACCURATE but UNCALIBRATED. Example: model predicts "80% UP" 100 times. If it's well-calibrated, ~80 of those should actually go UP. If only 60 do, the model is overconfident.

Calibration Methods

Platt Scaling (Logistic Regression on probabilities)

Fits a sigmoid curve to map raw probabilities to true frequencies. Good when calibration curve is monotonic.

V18 uses Platt for Stage 1 (cal1 = Logistic Regression on out-of-fold predictions).

Isotonic Regression (More Flexible)

Fits a non-parametric monotonic step function. More flexible than Platt — can handle non-sigmoid calibration curves.

V18 uses Isotonic for Stage 2 (cal2_iso, NEW in Phase 2).

Why Calibration Matters for Trading

If we set "buy threshold = 0.65", we want trades at this threshold to actually win 65% of the time. Bad calibration → either we trade too often (losses) or too rarely (missed opportunities).

Raw model saysTruth (without cal)After calibration
P(UP) = 0.90Actually 70% win rateP(UP) = 0.70 ✓

8. Composite Confidence: Combining 4 Signals 🔮

The ML model gives us "P(UP)". But we also have OTHER information that the ML model can't fully see:

🧠
Model Probability
XGBoost's P(UP) — calibrated
📊
Volume Alignment
Is volume confirming the direction?
🌏
Foreign Flow
Are foreign institutions buying or selling?
📰
News Sentiment
Recent news positive or negative?

The Formula

compositeConfidence = (
    0.55 * model_prob +
    0.20 * vol_alignment +
    0.10 * foreign_alignment +
    0.15 * news_alignment
)

If all 4 signals agree → high confidence → trade.

If they conflict → low confidence → skip.

Example: VNM Today

Model says DOWN with 60% conf0.600.55 × 0.60 = 0.330
Volume confirms DOWN (surge 2.5×)0.750.20 × 0.75 = 0.150
Foreigners SELLING heavily1.000.10 × 1.00 = 0.100
News neutral0.500.15 × 0.50 = 0.075
compositeConfidence0.655

Buy/sell threshold is typically 0.60-0.65. This signal would pass.

9. Per-Ticker Routing & Production Gates 🔀

Not all stocks behave the same. V18 has per-ticker optimizations:

V13 vs V16 Routing

From historical backtests, we discovered:

  • For 21 tickers (ACB, CTG, MWG, etc.) → V13 feature set works best
  • For 9 tickers (BVH, GAS, HPG, STB, etc.) → V16 feature set (with peer + breadth) works better

V18 routes each ticker to its better feature set automatically.

Per-Ticker Production Gates

Each ticker has TWO gates:

  1. dir_conf_gate (Stage 1) — minimum P(DIR) to proceed to Stage 2
  2. min_skill (NEW in Phase 1) — if model's overall skill is too low, return FLAT regardless

10. From Prediction to Trade 💰

Exit Conditions (checked in order — defaults from ai_trader_config)

  1. Stop loss: P&L ≤ -stop_loss_pct (default −5%) → SELL immediately
  2. Take profit: P&L ≥ take_profit_pct (default +10%) → SELL to lock in
  3. Signal reversal: Model now says DOWN with conf ≥ 0.65 → SELL
  4. Distribution: Volume shows institutional selling → SELL
  5. Time-based: Held ≥ 15 days AND P&L < −2% → cut losses

Stop loss and take profit are user-configurable. Other defaults: buy_threshold = 0.60, max_positions = 5, initial_budget = 100M VND.

11. The V1→V18 Journey: 18 Iterations of Learning 🚀

V18 wasn't built in a day. Here's the journey:

v1 skill -0.33 ❌

Single XGBoost, 51 features. Predicted FLAT 90% of the time. Useless.

v2 skill -0.13

+ Optuna, isotonic calibration, recency decay. Big improvement but still negative.

v5 skill -0.07

BIG REWRITE: 2-stage architecture introduced. Bug: only 204 training rows used.

v6-v8 skill -0.07

Fixed 2-stage + recency. Tried 29 features (worse), restored 53 (better).

v9 skill -0.06

Per-ticker feature removal based on IC analysis. Each stock gets its own subset.

v12 skill -0.048

Added 9 money-flow features (MFI, CMF, accum_streak).

v13 skill -0.029 ✓ BREAKTHROUGH

Added 7 vol-regime features (realized_vol, ATR norm, BB width). + AdaptiveContext rules. First version where 18/30 tickers PASS.

v14 skill -0.07 ❌ DISASTER

Tried "separate features per stage". Stage 2 lost critical UP/DOWN signals. -0.04 regression. Stopped at ticker 8/30.

v15 skill -0.03

Reverted v14's mistake. Added adaptive gate, min_conf restore.

v16 skill -0.06

Added VN30 breadth + peer pair features. Worse on average but BETTER on 9 specific tickers.

Hybrid-MAX skill -0.017 🏆

Insight: pick V13 for 21 tickers, V16 for 9. FIRST iteration ever NET PROFITABLE after transaction costs (+0.006%/trade).

v17 skill -0.068 ❌

Over-engineered "online hybrid" with auto-routing. Added complexity, removed clarity.

v18 FIXED skill -0.028, 19/30 PASS

Final: per-ticker routing (offline-decided) + restored v13 components. Matches Hybrid-MAX PASS count.

Key Lessons (Critical for Any ML Practitioner)

📊
Labels matter most
Fixing label thresholds (v1→v2) was the biggest single jump (+0.20 skill).
🌳
Don't prune features
v7 and v14 both regressed by removing features. Trees handle redundancy well.
🧪
A/B test architecture
v14's disaster could've been caught in 1 ticker. Always pilot first.
📉
Variance is real
Per-ticker skill swings ±0.05 between runs. Don't trust single runs.
🎯
Per-ticker > universal
One-size-fits-all rarely works. v18's routing was the breakthrough.
📐
Calibration matters
Without calibration, "65% confidence" doesn't mean 65% win rate.

12. Glossary 📖

Feature
A measurable input number. E.g., "RSI = 42" is one feature value.
Label
The target the model predicts. For V18: UP, DOWN, or FLAT.
Training Data
Historical examples with known labels — what the model learns from.
Test/Validation Data
Examples held out to evaluate the model on data it hasn't seen.
Overfitting
When a model memorizes training data perfectly but fails on new data.
Cross-Validation (CV)
Testing technique: split data into folds, train on some, test on others, average results.
TimeSeriesSplit
CV variant that respects time order — always train on earlier data, test on later.
XGBoost / LightGBM
Gradient boosting tree libraries. The workhorses of tabular ML.
Optuna
Automated hyperparameter tuning library. Tries many combinations smartly.
Calibration
Adjusting probabilities so "80% confidence" actually means 80% truth rate.
Skill Score
How much better than baseline. (accuracy - baseline) / (1 - baseline). 0 = no skill.
Look-Ahead Bias
Accidentally using future data — the cardinal sin of time-series ML.
RSI
Relative Strength Index. 0-100 scale measuring momentum.
MACD
Moving Average Convergence Divergence — trend-following indicator.
ATR
Average True Range — measures volatility (how much a stock typically moves).
OHLCV
Open / High / Low / Close / Volume — the 5 basic data points per bar.
T+2 Settlement
Vietnamese rule: cash from selling shares is available 2 trading days later.
Ensemble
Combining multiple models. V18 uses ensembles at multiple levels.
